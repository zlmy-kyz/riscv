## 给 myCPU 搭起黄金轨迹差分验证环境（用户请求："我要怎么做才能实现验证"）

产出 `difftest/`（全部脚本化，iverilog + Python，一键 `run.ps1`）+ `doc/黄金轨迹差分验证方法.md`。

### 结构
- `golden/rvtool.py`：RV32I 汇编器 + 指令级 ISS + 导出 `rom.hex` / `trace.txt`（写回事件）/
  `itrace.txt`（指令流）/ `rf_golden.txt` / `mem_golden.txt`。**期望值全部由程序生成，人不算一位。**
- `golden/selftest.py`：用**外部证据**校验黄金模型 —— 工程 ROM 实际固化的 7 条指令
  （逐条比对汇编器输出）+ 黄金模型在原程序上的行为。不做这步就是自己给自己判卷。
- `tb/tb_difftest.v`：三路比对 —— ①写回轨迹 `{pc,wnum,wdata}` ②指令流 `{pc,inst}` ③终值（RF+DRAM）。
  不一致 → 打印「第几次写回/第几条指令 + DUT 值 + 黄金值」+ `$finish`。
- `model/*.v`：时序忠实的存储器行为模型（1 拍同步读、ROM 内部地址寄存器不复位、
  **输出在 rst 撤销后仍强制 0 一拍**）。用它而不是厂商 IP，因为 iverilog 拿不到
  `GTP_DRM36K_E1` 的 .v 源（Pango 只给 `D:\modelsim\...\pango_sim_libraries` 编译好的 .qdb）。
- `prog/*.S`：prog0_alu（不访存）/ prog1_mem（含访存）。
- `rtl/mycpu_sync_loadfix.v`：load 停一拍的参考实现（**未合入工程**）。

### 关键约定（最容易写错的三处）
1. **采样点**：`debug_wb_*` / `if_id_*` 是组合直出，必须 `always @(posedge clk)` 取**沿前值**
   才是"该沿提交的指令"。沿后采样会整体错一拍。
2. **x0 不算写回**：`jal x0,halt` 的 `rf_we` 真拉高，但两边都要按 `rd != 0` 门控。
3. **停机标记 = `jal x0, self`（自环）**，黄金模型与 RTL 共同认它。

### 写 load 补丁踩的两个坑（都被差分验证当场抓出）
1. **多插一个气泡 → 把该跑的指令冲掉**（报"指令流不一致：DUT pc=0x14 / 黄金 pc=0x10"）。
   根因：**本设计根本不存在 RAW 冒险**。只有 IF/ID 一个流水边界，生产者在自己 ID 那拍末尾的沿
   写 RF，消费者下一拍 ID 组合读 —— 非阻塞赋值在该沿已完成，背靠背也读得到新值。
   load 多停一拍后消费者正好落在写回沿之后那拍，**既不用前递也不用气泡**。
2. **只冻 IF/ID 不冻 pc → 取指流错位**（同样丢 0x10）。IF/ID 在沿上锁的是 `(pc, mem[pc])` 这一对，
   只冻 IF/ID，下一拍交付变成 `(pc+4, mem[pc+4])`，中间那条被跳过。
   → 可合入的最小改动：`inst_sram_addr` 与 `pc` **同时**用 `mem_hold` 冻结，加一个
   `else if(mem_hold)` 冻结分支，`rf_we & ~mem_start`。代价每条 load 多 1 拍。

### 工具教训（第四次踩）
- **bash 工具本机彻底不可用**（用户名含单引号，shim 崩），一律 PowerShell。
- PowerShell 抓不到原生命令 stdout：`| Out-String | Set-Content -Encoding UTF8` 落盘再读；
  直接跑（不经过管道）时给脚本开头加 `[Console]::OutputEncoding = [Text.Encoding]::UTF8`。
- **原生程序 stderr 经管道会被包成 ErrorRecord**，脚本里 `$ErrorActionPreference` 必须是
  `Continue`，否则一行普通编译告警就被当异常抛出（本次踩了）。
- 本机工具会拦截 `Remove-Item`（safe-delete trash-failed），残余文件删不掉，需手工清理。
- IP 的 `*_init_param.v` / `*_Reset_Value.v` 是被 `include` 的，**不要**列进 iverilog 命令行，
  否则报 localparam 重复定义。
- 自检暴露了我自己写的 ISS 一个真 bug：**12 位立即数不能对拼好的值调 s32()**
  （0xFFD 在 32 位整数里最高位是 0，不会补符号，-3 变成 4093）。要按字段宽度扩：
  `sext(v, bits) = ((v & mask) ^ m) - m`。这类"悄悄错"只有自检能挡住。

## 讨论:分支跳转该在 ID 级还是 MEM 级判定（用户提问）

用户问"分支跳转不是在 id 阶段进行判断的吗"。**澄清:可以,而且 ID 级更常见;不是架构必然。**

| | ID 级判定（教科书主流） | MEM 级判定（本工程现状） |
|---|---|---|
| 比较操作数 | 需**额外**把 `ex_mem_wdata`/`mem_wb_wdata` 转发到 ID | EX 级算 `br_taken` 时已天然吃到转发 |
| 代价 | **1 气泡** + load-use 需停 1 拍 | **3 气泡**(+`fetch_stall` 1 拍),load-use 不用停 |
| 关键路径 | ID 变长:RF 读 + 2 级 mux + 比较器 | ID 短,EX 本来就是关键路径 |
| 目标地址 | ID 级算 | ID 级算（两者相同） |

→ 选 MEM 级的原因:**只有一处需要维护转发逻辑**(分支比较器和 ALU 共用 `ex_rs1/ex_rs2`),
不容易漏;代价是多付气泡。若改成 ID 级,分支的 load-use 必须**真停一拍**
(数据还在 MEM 级组合值上,连转发都拿不到)。

## 产出:RV32I 指令速查/反汇编工具（用户请求）

`.workbuddy/rv32i/rv32i_tool.py` — 单文件,无依赖(Python 3)。
内含:六个编码函数(R/I/S/B/U/J) + 完整译码器 + 伪指令展开器 + 输出器。

| 模式 | 命令 | 说明 |
|---|---|---|
| 完整表格 | `python rv32i_tool.py` | 40 条内置程序,含地址/机器码/汇编/反汇编/格式/伪指令/语义 |
| 反汇编任意编码 | `python rv32i_tool.py 0x00f00093 0x00c0016f ...` | 逐条译码 |
| 表格落盘 | `python rv32i_tool.py --save` | 写 `rv32i_table.txt`(同时写 `doc/RV32I指令速查表.md`) |
| Markdown | `python rv32i_tool.py --md` | 写 `rv32i_table.md` |
| 绕开控制台编码 | `python rv32i_tool.py --out dis.txt 00f00093 ...` | 结果写文件 |
| 往返自检 | `python rv32i_tool.py --selftest` | 汇编→编码→反汇编 一致性校验 |

**自检结果:40/40 通过,0 失败**;边界值也对(-2048 符号扩展、`jal -8`、`beq -4`、
`jal 0x7FFFF<<1` 正偏移上界)。编码器与译码器严格互逆。

**语义描述是"这条指令做了什么"的逐步展开**,例如:
- `lui x10, 0x12345` → `rd = imm << 12 (装入 20 位立即数到高 20 位,低 12 位清零)`
- `jal x1, 0x10` → `rd = pc + 4; pc += imm (跳转,并把返回地址 pc+4 存 rd)`
- `jalr x4, 0x20(x1)` → `rd = pc + 4; pc = (rs1+imm) & ~1 (间接跳转,目标地址最低位清零)`

伪指令识别:`nop` / `li` / `mv` / `inc` / `dec` / `ret` / `j`(判序从严到宽,
先认 `inc`/`dec` 再退化到 `li`/`mv`,否则 `addi x6,x6,1` 会被误判成 `mv`)。

**踩的坑**:
1. 一次 `Edit` 把 `R_ALU = {...}` 的收尾 `}` 和 `I_ALU = {` 之间的换行吃掉了
   → `}    I_ALU = {` → `SyntaxError`。**改完必须跑一次 `--selftest` 验证语法。**
2. `jalr` 反汇编我一度写成 `jalr rd, imm, rs1`(操作数序错),正确是 `jalr rd, imm(rs1)`。
3. 对齐:中文列宽不等于 `len()`(`pad()` 按 CJK 算 2 列)。
4. **PowerShell 管道会把 Python 的 UTF-8 stdout 按本地代码页重编码**,中文必乱。
   绕法:脚本内 `sys.stdout.reconfigure(encoding="utf-8")` + 用 `--save`/`--md`/`--out`
   让 Python 自己写文件(它写的文件是正确 UTF-8)。

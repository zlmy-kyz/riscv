## 访存时序定论(依据用户教材批注 + 复核,2026-09-11 补)
用户桌面的 `流水线设计.txt`(6242B,教材"流水线缓存 + 同步读 RAM"章节)末尾批注:
> 数据 RAM 的读/写请求在指令位于 EXE 阶段时发出,读数据在指令位于 MEM 阶段时返回。

**复核结论:批注正确。** 关键前提是 **RAM 自己的地址输入寄存器充当 EXE/MEM 边界寄存器**(地址由 EXE 组合逻辑直连 RAM 地址端口,中间不再插一级 EX/MEM 寄存器)。
- 地址在 EXE 阶段呈现 → RAM 在 EXE/MEM 上升沿采样 → 数据从该沿起即有效,贯穿整个 MEM 阶段。
- store 也在 EXE/MEM 沿提交。
- **MEM→EX 旁路可直接喂给紧跟其后指令的 EXE 级,load-use 可以不插气泡**(能否收敛取决于 tCO+旁路 mux+ALU 的时序余量;收不住就退回 1 拍停顿)。
- 若在 RAM 前额外插一级 EX/MEM 寄存器,数据会晚一拍落到 WB —— 这才是"浪费拍数"的接法。
- (更正:我之前说"数据在 MEM/WB 沿才有效"是后一种接法的结论,按教材方案应更正为"数据在 MEM 阶段内有效"。)

## RTL 级确认:读通路只有一级寄存器(2026-09-11 再补)
逐层读 `inst_rom.v` → `ipm2l_rom_v1_8_inst_rom.v` → `ipm2l_spram_v1_8_inst_rom.v` → `GTP_DRM36K_E1`:
- `ADDR_WIDTH=10` 使 `ADDR_LOOP_NUM=1`、`CS_ADDR_WIDTH=0` → 无地址级联;`.DOA_REG(c_OUTPUT_REG)=0` → DRM **无输出寄存器**。
- 读通路 `addr → 组合 drm_addr → DRM 内部地址寄存器 → 阵列 → DOA → QA_bus → qa_data_bus → rd_data_bus → rd_full_data → rd_data`,**全链路仅 1 个寄存器**(DRM 内部地址寄存器 = EXE/MEM 边界寄存器)。
- 因此:① EXE/MEM 沿锁存 `A(I)` → 数据**紧接该沿就有效**,贯穿整个 MEM;② MEM/WB 沿锁存的是下一条指令的 `A(I+1)`,同沿后 `rd_data` 变为 `mem[A(I+1)]`。
- 精确说法:在 ② 沿**采进寄存器**能拿到 `mem[A(I)]`(沿前值稳定),是标准的交给 WB 的做法;**但"等到 ② 之后才组合取用"拿到的已是下一条的数据**。
- 只有 `OUTPUT_REG=1`(或手动再插一级地址寄存器)才会变成"② 之后才有效 → 落到 WB"。

### 两种接法的取舍(设计决策)
- ① 组合直连(教材方案,选用):省 1 拍;代价是 **EXE 级时序路径 = ID/EX tCO + ALU + 走线 + RAM 地址寄存器 setup**,比"只算 ALU"长。能否收敛取决于时钟周期。
- ② 多插一级 EX/MEM 地址寄存器:EXE 路径短,但读数据晚一拍落到 WB,load-use 停 1 拍、分支冲刷多 1 拍。
- 结论:先按 ① 做;若 EXE 路径收不紧,再退回 ②。
- 配合细节:load 时 `wr_en=0`,`addr = alu_result[11:2]`(丢低 2 位);`wr_en` 必须与 EXE 级 valid 相与,防冲刷指令误写。

### 方案二的一个关键易错点(2026-09-11 复核用户笔记)
- 方案二里 **MEM/WB 寄存器不能锁存内存值**:MEM→WB 沿上 RAM 输出仍是上一拍的值(新值在沿后才出现)。所以内存值必须**绕过 MEM/WB**,从 RAM 输出组合直送 WB 的写回 mux(`mem_to_reg` 选择)。MEM/WB 寄存器只锁存"其他数据"(ALU 结果、pc+4、rd、控制)。
- 等价说法:**方案二里 RAM 内部地址寄存器扮演的其实是 MEM/WB 边界寄存器** —— 这就是"多花一拍"的准确来源。
- 方案二关键路径实为 **3 段**:①EXE `ID/EX tCO→ALU→EX/MEM 建立`;②MEM `EX/MEM tCO→走线→RAM 地址寄存器建立`;③WB `RAM 内部寄存器 tCO→阵列→DOA→写回 mux→RF 建立`。
- 注意:方案二的写回 mux 输入直接来自 RAM 输出,RF 输入端路径 = RAM tCO + 阵列 + mux + RF setup,所以方案二的时序未必真比方案一好。

## IF 取指的方案一/方案二 与 ROM 复位的隐性前提(2026-09-11 补)
教材原文(用户引用):方案一 = 读请求在**取指级**发起(以 **PC** 为读地址),RAM 输出在**译码级**完成;方案二 = 在**更新 PC 的阶段**发起(以 **nextPC** 为读地址),RAM 输出在**取指级**完成。两者都是 5 级,不增加流水级数。

### 本质区别(一句话)
**ROM 自带的那个内部地址寄存器,你把它当哪个流水边界用。**
- 方案二(addr = nextPC):ROM 内部寄存器与 PC 寄存器锁存**同一个输入**(nextPC)→ **同一个逻辑寄存器**(教材说的"重合")→ 它**就是 IF 边界**,不浪费;指令在 IF 级就绪,可以正常寄存进 IF/ID。
- 方案一(addr = pc_r):ROM 内部寄存器锁存的是 pc_r 的输出 → 它是 pc_r 的**下一级**寄存器 → 与 if_id_pc 内容相同(冗余复制);若再把指令也寄存进 IF/ID,链路上就是 `pc_r → ROM内部寄存器 → if_id` 三个寄存器 → **前端多一级**(整机 6 级)。用户提出的"指令不寄存、只把 pc 存进 if_id"能把它压回 5 级,代价是 **ROM 读访问进入 ID 级时序路径**(ROM tCO + 阵列 + 译码 + RF 读 + ID/EX 建立)。

### 关键结论:方案二有隐性前提 —— ROM 内部寄存器的初值必须是复位向量
- 方案二要求不变式 `ROM 内部寄存器 == pc_r` 从第 1 拍起成立。而它的 D 端是 `nextPC = pc_r + 4`,复位后 pc_r = 0 → nextPC = 4,**不会自动变 0**。
- 后果(复位后):
  - 若 RSTA 把地址寄存器清成 0 → 第 1 拍 ROM 输出 inst[0],0 气泡 ✓
  - 若为未定义值 X → 第 1 拍输出垃圾(冲掉),而**同一沿后 ROM 寄存器与 pc_r 一起跳到 4** → 第 2 拍输出 inst[4] → **inst[0] 被永久跳过**(不是多一个气泡,是丢指令)✗
- 方案一**没有这个前提**:ROM 内部寄存器的 D 端是 pc_r 的输出,而 pc_r 的复位值是确定的 0 → **1 拍后自动对齐**,代价只是复位后 1 个气泡,inst[0] 照样取到。这正是现有 `ifu.v` 里 `run_d1` 气泡的用意("用 1 拍换对 ROM 复位行为不确定性的免疫")。

### 不可从源码判定的部分
`RSTA` 直接连到黑盒原语 `GTP_DRM36K_E1`(见 `ipm2l_spram_v1_8_inst_rom.v` L674/L688,`RST_TYPE = c_RESET_TYPE = "SYNC"`),仓库里**没有该原语的仿真模型**,所以 ROM 内部地址寄存器是否被同步复位清零**无法从 RTL 判定**。配置文件 `inst_rom.idf` 里 `RST_VAL = 0` 但 `RST_VAL_EN = false`(复位值功能**未启用**),是个警示信号。需查 DRM 原语手册/仿真模型确认。

### 方案二的稳妥做法(不依赖 IP 复位行为)
复位后**让 pc 停一拍**(nextPC 强制为复位向量),使 ROM 内部寄存器与 pc_r 在同一沿一起收敛到复位向量,再把这一拍当气泡冲掉 → 需要 1 个气泡,与方案一同价,但换来"指令被正常寄存"的干净时序。
(注:下面"已实施"的版本比这个更优 —— **0 气泡**,不用停拍。)

## 独立的「方案二取指级」参考实现 + 自检 tb(2026-09-11,用户要求"不要参照我的代码"从零写)
- 目录:`.workbuddy/sim_nextpc/`,含 `if_stage.v`(设计)、`if_stage_tb.v`(自检 tb)、`sim.log`(运行日志)。**不依赖本工程 any 文件,可独立编译**。

- 三个设计决定(可作为该方案的"标准写法"):
  1. `rom_addr_o = next_pc` **组合直连**(中间不夹任何寄存器);
  2. `next_pc = rst ? RESET_VECTOR : stall ? pc_q : br_taken ? br_target : pc_q+4` —— **复位门控用常量 RESET_VECTOR**,而不是 `pc_q`。这样 ROM 内部寄存器**一个复位沿就收敛**(用 `pc_q` 需要两个沿),且对 IP 的 RST_VAL 功能完全免疫;
  3. IF/ID 每个沿整对锁存 `{pc_q, rom_rdata_i}`,不需要任何 `pc_d1` 对齐。
- **仿真结果(悲观 ROM 模型:内部地址寄存器不给复位,初值 X)**:A) 复位释放后第一拍即取到 PC=0 有效指令(**0 气泡**,66ns);B) stall 期间 pc 与 IF/ID 均冻结;C) flush+跳转 0x40 恰好 **1 个气泡** 后恢复 → **PASS,17 条有效指令配对全对**。
- 踩坑记录:tb 里 `@(posedge clk)` 后**立刻**读信号拿到的是沿前旧值,必须先 `#1` 再采样,否则 stall 冻结检查会误报。
- 仿真输出中文乱码问题:`vvp` 输出是 UTF-8,PowerShell 采集前需 `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8`,否则中文全部变乱码。

### 详细时序推导(2026-09-11,用户追问"详细时序")
- **稳态不变式(最精确的表述)**:设 P 为当前取指地址,每一拍恒有
  - `pc_q == ROM 内部寄存器`(都是 P,字节地址)—— **完全锁步**
  - `rom_rdata == ROM[pc_q]`
  - `rom_addr`(输入)== `next_pc` == `pc_q + 4` —— **永远领先一步**,这正是"读请求提前一拍发起"
  - 沿上锁存 `{pc_q, rom_rdata}` 必然得到同一条指令
- **复位期间不变式就已成立**:复位时 `next_pc = RESET_VECTOR = 0`,`pc_q = 0`、ROM 内部寄存器 = 0,所以从 C1 起 `rom_rdata` 就 = `ROM[0]`,只是 `if_id_valid = 0` 没锁。释放在 C2 末尾 → `next_pc` 立刻变 4(存在一个很短的 "addr=4" 窗口),↑3 上 ROM 寄存器与 `pc_q` **同一沿**变成 4,同时 IF/ID 锁进 `(0, ROM[0])` → **0 气泡**。
- **`stall`**:`next_pc = pc_q` → `pc_q`/`rom_addr`/ROM 内部寄存器/`rom_rdata`/`if_id` **全链一起冻结**,配对丝毫不动。⚠ 绝不能只冻 IF/ID 而不冻地址。
- **`flush` + `br_taken`(目标 T)**:`next_pc = T` → 该沿 `pc_q` 与 ROM 内部寄存器**同时**变 T,但 `if_id_valid <= 0` → **恰好 1 个气泡**;下一拍 `rom_rdata` 已是 `ROM[T]`,再下一沿锁进 `(T, ROM[T])`。
- ⚠ **新增的硬时序约束(此前未记录)**:`pc_q` 与 ROM 内部寄存器**都由同一个组合函数 `next_pc` 驱动**,要在同一沿采到同一个值,就要求 **`next_pc` 在时钟沿之前充分稳定**(满足 ROM 地址寄存器 setup)。含义是**分支判定必须在当拍内组合完成**;若分支结果踩在沿上再变化,两者会采到不同值 → 配对破裂。关键路径 = `ID/EX tCO → 分支比较 → mux → ROM 地址 setup`。

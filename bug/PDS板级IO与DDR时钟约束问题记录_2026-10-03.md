## 3. 旧顶层/旧视图导致内部信号仍出现在 Pin Planner

### 现象

RTL 中新增板级封装后，PDS 引脚界面仍能看到 `soc_resetn`、单端 `ddr_ref_clk`、`irq_external/software/timer` 等信号；绑定 `ddr_ref_clk_p/n` 时出现“Object can not be found in current view”。

### 原因与解决方法

引脚编辑器基于编译结果建立端口列表。修改 RTL 后，旧窗口和旧编译数据库不会自动变为新的板级接口。

本次板级结构为：

```text
board_top
  ├─ GTP_INBUFDS：ddr_ref_clk_p/n → 内部 ddr_ref_clk
  └─ soc_ddr3_top
       └─ soc_top
            └─ CPU / 总线 / MMIO
```

`core_clk`、`ddr_init_done`、`soc_resetn`、debug 信号接在 board_top 内部；三路 IRQ 接 0。编译顶层选择 `board_top`，重新 Compile，关闭旧 UCE 并基于新结果重开。不得用删除 SoC 内部 debug 逻辑的方法消除外部端口。

判定依据是新的编译日志明确出现 `Module "board_top" is set as top module`，而不是只看设计树或已打开窗口的标题。

## 4. 复制 mem_a[0] 模板导致 IO 属性报错

模板曾将 VCCIO=1.2、HSUL12、DRIVE、SLEW 等属性一起复制到所有端口。地址输出、输入、双向数据和差分时钟的属性要求不同，不能共用一套电气模板。

- INPUT 不设置输出 DRIVE/SLEW，删除这些字段即可处理 0049。
- 差分 CK/DQS 不接受当时套用的单端 HSUL12，产生 0007；应核对实际支持的差分标准及 Bank 供电。
- 末尾重复追加属性会产生 4026，需检查最终覆盖值。
- 同一 Bank 混用 1.2 V/3.3 V 会产生 0003。为了通过检查而随意统一到某个电压，不能证明实板安全或 DDR 电气正确。

此前已有的修复和备份见 [PDS 板级约束报错修复](D:/riscv/RISCV/doc/PDS板级约束报错修复_2026-10-03.md)。这些历史步骤与后续 GUI 保存的现场有所不同，以当前文件和对应日志为准。

## 5. 本次主要修复：SDC-2025 / STA-3009

### 现象

综合完成后，七个时钟源被提示需要 create_clock 或 generated clock；参考时钟还出现没有 clock endpoints 的提示。

原综合报告将参考时钟和六个内部时钟都按 **1000 ns** 分析，因此“综合完成”不能说明设计已按真实工作频率完成时序检查。

### 原因

实际导入的 FDC 没有完整的主时钟和派生时钟定义。PDS 未建立 125 MHz 参考输入、DDR PLL 和分频输出之间的正确时序关系。

### 已执行的解决方法

根据当前生成的 `ipcore/ddr3/pnr/ddr_test.fdc` 的时钟段，适配到实际 `u_soc.u_ddr3.u_ddrphy_top` 层次，加入实际使用的临时 FDC。主时钟定义为：

```tcl
create_clock -name {ddr_ref_clk} [get_ports {ddr_ref_clk_p}] -period {8.000} -waveform {0.000 4.000}
```

派生 SoC 时钟示例：

```tcl
create_generated_clock -name {ddrphy_sysclk} -source [get_ports {ddr_ref_clk_p}] [get_pins {u_soc.u_ddr3.u_ddrphy_top.ddrphy_gpll/clkout0}] -master_clock [get_clocks {ddr_ref_clk}] -multiply_by {12} -divide_by {16}
```

完整处理包含 **17 条时序命令**：1 个主时钟、6 个派生时钟，以及当前 IP 生成例程配套的 multicycle、uncertainty、clock groups。IOCLKDIV 的边沿约束保留 `-edges {5 13 21}`，对应当前 /8、PHASE_SHIFT=2 的配置；不能忽略相位而机械替换成只含频率的约束。

| 时钟 | 报告周期 ns | 频率/含义 |
| --- | ---: | --- |
| ddr_ref_clk | 8.0000 | 125 MHz 参考输入 |
| rst_clk | 8.0000 | 125 MHz 复位控制时钟 |
| ddrphy_sysclk | 10.6667 | 93.75 MHz，驱动 SoC |
| phy_dq_clk_0 | 1.3333 | 750 MHz PHY 时钟 |
| phy_dq_sysclk_0 | 10.6670 | 约 93.75 MHz，保留相位关系 |
| phy_dq_clk_1 | 1.3333 | 750 MHz PHY 时钟 |
| phy_dq_sysclk_1 | 10.6670 | 约 93.75 MHz，保留相位关系 |

时钟修复过程中保留了当时生效的 **351 条 IO 属性**，没有通过本次时钟约束修改 DDR IP 频率、CPU RTL 或 IO 电压。

## 8. 最新截图：Timing-4086/4087 与 Public-4008

### Timing-4086/4087

```text
W: Timing-4086: Port 'mem_dq[0]' is not constrained,
   it is treated as combinational input.
W: Timing-4087: Port 'mem_dq[0]' is not constrained,
   it is treated as combinational output.
```

这些属于时序提示，不能直接理解为“DQ0 没绑球位”。当前 DQ0 的 Location 已是 P6，但没有完整的外部接口时序约束；DQ 是双向端口，因此可同时有输入、输出方向的提示。

| 约束类别 | 作用 |
| --- | --- |
| PAP_IO_LOC | 连接哪一个 FPGA 球位 |
| VCCIO / IOSTANDARD | IO 电气条件 |
| create_clock / create_generated_clock | 时钟频率及派生/相位关系 |
| 输入/输出延迟等接口时序约束 | 外部设备和 PCB 信号到达/采样时序 |

后续需按 DDR IP 的实际接口模型、器件时序和 PCB 延迟检查外部 IO 约束；不能给所有 DDR 信号随意填同一个延迟，也不能为了消除提示而将未核对的路径全部设为 false path。本次尚未完成这些检查。

### Public-4008

截图示例为 DDR PHY 内部 `ck_dly_set_bin_tra[7:0]` 实例 dangling，将被 cleaned。工具检测到悬空或无效连接的逻辑并准备清理；参数化 IP 中的未使用逻辑可能出现这种现象。

必须按具体实例判断是否符合预期，并核对 DDR 必需的数据、时钟和训练路径仍完整。单凭这一条警告不能判定 DDR 逻辑损坏，也不能断言所有此类警告都无害。本次没有逐条审计截图中的全部 Public-4008。

界面的 `No Identifier Infos/Warnings` 是消息分组及数量，不是新的故障编号。应检查具体消息、流程结果和时序报告，不能仅用警告总数判断是否通过。

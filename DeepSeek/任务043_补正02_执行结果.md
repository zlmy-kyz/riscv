### 4.2 SoC 顺序与排空（补正02 第 2 项）

`xs_soc_20261018_d`：真实 `soc_top`（真 CPU、双互连、片内 ROM/RAM、MMIO、UART、I/D cache、Camera/PP 窗）＋功能 x32 用户口模型，镜像预载（明确不是 Full Boot）。两个 epoch，各自干净复位，共 384 沿、84 条退休、1 次中断。16 条判据全 PASS：

| 判据 | 观测证据 |

| A1 队列未空时非 DDR 一律不被接受 | 违例 0 |

| A3 先被挡住再被接受（非空证） | 被挡 19 沿（37…55），其中 **11 沿**落在"head 已完成、tail 尚未 W"的窗口内 |

| A9 队列账 | 7 笔 DDR store ⇒ AW 7、W 7 |

| B2/B2b 原因正确 | 取中断时 cause=0xb；沿 302 起 `mcause=0x8000_000b` |
| B3 队列忙时从不取中断 | 违例 0 |
| B4 handler 真的跑了 | 0x4000_0100/104/108 三条退休 |
| M1 最终 DDR 字 | 见下表 |

最终 DDR 字节/字（CPU 视角）：

```
0x4000_1000 = 0x11   0x4000_1020 = 0x22   0x4000_1040 = 0x1（epoch1 完成标记）
0x4000_1060 = 0xC0DE0001  0x4000_1080 = 0xC0DE0002   ← 同一地址两次读，值不同 ⇒ 未命中缓存、未被填入
0x4000_10A0 = 0xB0B00001  0x4000_10C0 = 0xB0B00002
```

Camera/PP 的"不填/不命中"同时由两件事证明：同一地址各发出 2 次 AR（命中就不会再发），且两次返回的数据不同（模型首读后改内容）。

### 4.3 剩余桥边沿 E1–E7（补正02 第 3 项）

`xs_edge_20261018_d`：124 沿，7 笔 store（AW/W 各 7）、11 次 load（AR/R 各 11）、6 次取指，`wb_cancel=0`、`front_cancel=0`、I 数据逐字节核 6/6。

| 门 | 值 | 含义 |
|---|---|---|
| `tail_only_blocked` | 1 | 仅 tail 同行 load 在 head 完成沿被保守挡住，随后接受并 forward `0xB2B20002` |
| `i_rsp_after_store_w` | 6 | 035 毒化后 I 响应全部晚于该 line 的 W |
| `same_edge_ar_r` | 2 | AR/R 真正同沿，地址与 ID 正确 |
| `parked_ar_saved` | 1 | 提升后的 AR 用的是保存地址（live 地址已改） |
| `i_owner` / `d_owner` | 4 / 7 | RID 0=I、1=D 各自填各自缓存 |
| `partial_mask_loads` | 5 | E6 窗口内 load 响应数 |
| `dual_pending_load_accepts` | 1 | **两笔 store 同时在队**时接受了 load |
| `rsp_turnover_same_edge` | 1 | **旧响应消费与新请求接受在同一沿** |

E6（新增）：同一字上两笔互补 strobe（`4'b0011` / `4'b1100`），转发返回值 `0x1122_CCDD`（head 供字节 0..1、tail 供字节 2..3），排空后 DDR 同值；再补一笔真实 SH 形状（`4'b0011`），返回值 `(keep & 0xFFFF0000) | 0x00007788`，排空后 DDR 同值。
E7（新增）：旧响应消费的同一沿接受了年轻请求（`same_edge=1`），且年轻请求的响应数据正确——所以该接受是真实的，不是重放。

### 4.5 参考与分类 + 离线负例（补正02 第 5 项）

参考加固（`check_wb2.py` / `check_soc.py` 均为封存副本参与判定）：

* I 侧不只数响应：每次 I 响应逐字节核数据（hit 取 I 缓存、miss/毒化取 DDR），并要求被核次数 == 响应数；遇毒化还要求响应晚于该 line 的 W。
* **RID 归属**：每次 AR 认领一次"需要访问 DDR 的读"（按发射顺序的 FIFO），响应 RID 必须等于认领者（0=I、1=D）；同 RID 非 0/1 直接报错。截图式负例证明这条以前缺失、现在生效（§5）。
* 优先级漏洞用**明确分支**修掉（不再依赖 `and`/`or` 的短路优先级）：
  ```python
  if cfg.posted_active:
      checks['posted_queue'] = m.store_acc == m.w + m.wb_cancel
  else:
      checks['nonposted_queue'] = m.store_acc == m.w
  ```
* N/P 记录数、重复检测、reset 期间取消账（逐侧逐 epoch：`accept == rsp + cancel`）、结尾"无未结账请求/无未结 AR"断言。
* 阻塞分析只在**测试侧**分类并允许重叠：store 容量、store 周转等待、load 队列未空 miss、hit 资格、同行完成沿碰撞、RUW 禁用、共享主槽、init 低。

离线负例拒绝验证（`negative_check.py`，只改 `<run>/negatives/<name>/` 的**副本**，再跑该 run 自己封存的 checker）：

| `xs_fair_d1/d2_20261018_d` | fair | 7/7 拒绝 |
| `xs_edge_20261018_d` | edge | 8/8 拒绝 |
| `xs_x16 / xs_noposted / xs_ruw0_20261018_d` | x16/noposted/ruw0 | 各 7/7 拒绝 |
| `xs_soc_20261018_d` | soc | 5/5 拒绝 |

注入项：删一次 AW 握手、改 W 数据、改 load 响应数据、改 I 响应数据、翻 RID owner、复制一条 N 记录、删一个必需 marker、凭空造一次接受、（SoC）在忙沿伪造非 DDR 接受、把 trap 挪到队列仍忙处、把 FENCE 退休沿标成忙、改一次 Camera AR 握手地址、改一个最终 DDR 字。合计 **48 个注入，48 个被拒（checker 退出码非 0 且 status≠PASS）**；只有拒绝才算通过。

## 6. 保留的厂家诊断与已知限制

1. 厂家诊断**原样保留**（不消除、不改 IP），`xs_soc_20261018_d/log_xsim.txt` 中出现 2 次：
   ```
   IPSpecCheck: 04030130 ipm2l_flex_sdpram parameter setting error !!!: c_WR_ADDR_WIDTH must between 9-20 when DRM Resource is 36K
   ```
   它与既有的"两个后端、旧/新桥都有该显示诊断"一致。
2. SoC 片段的 DDR 模型是**功能模型**，不是 DDR3 时序模型：`aw_block=2 / w_lat=6 / ar_block=1 / r_lat=3`，且 Camera/PP 光圈（局部 `0x0100_0000` / `0x0200_0000`）在模型内部被别名到保留区 `beat 0x800 / 0x840`；这是模型属性而非 DUT 属性，已在 `ddr_model_wb2.sv` 注释中声明。`preload_hex` 只铺 512 字（2 KiB）程序区，因此这是**最小片段，不是完整 ISA/IRQ/相机/CNN 套件**。
3. SoC 片段的 IRQ 是"取到即撤"的电平激励（handler 不负责清中断源）：本片段只验证**进入时机晚于排空**，不验证驱动清中断序列；若不撤会连续重入（曾实测到 4 次 trap）。
4. 为避免猜测而写进 TB 的事实：xsim 的批处理启动器会把单个 argv token 里的 `=` 拆开，`--testplusarg "NAME=value"` 传不进去，故 SoC TB 用固定 cwd 相对路径取镜像/写日志；这属于测试侧实现细节，已随封存源一起留档。
5. 本轮的 `_b`/`_c` 两代目录是同激励的中间产物（`_c` 早于 RID-owner/AR-认领加固），**只有 `_d` 一代是交付证据**；三代 fair 的沿数/周期数一致（54 沿、41 拍），可作为同激励可复现性的旁证。`xs_probe_*` 全部是调试草稿，不是证据。

## 新分歧：edge 154 `AR without an owner`（根因已定，参考侧）

场景 15"复位撤销未消费的寄存命中"的原始事实：

```
TOK 144 37 ACC 0        ← token 37（I 读 0x40000000，计划取消）被接受
TOK 145 37 CAN 144      ← 复位取消，原接受边沿 144
E  153 ... i_v=1 i_r=1 i_addr=40000000   ← 新 token 38 被接受
BUS 154 AR  /  BUS 156 R                 ← token 38 合法 miss 发 AR 并返回
TOK 158 39 ACC 0
```

- 复位使桥的 `inst_line_valid` 清零，因此**同一地址的新请求必然 miss 并发出 AR** —— 与方案"复位清所有权/valid、复位后新请求不继承旧快照"一致，DUT 行为正确。
- 参考却报 "AR without an owner"：它在 edge 153 接受了 token 38，但**其自建 I 缓存模型没有在复位时清 valid**，于是预测"命中、不需要 AR"，未登记读 owner；真正的 AR 到来时无主。
- 即参考的复位处理只撤了未完成 CPU token，**未同步清缓存 valid（及可能的 DDR 在途状态）**，与方案第 19/34 行"复位清所有权/valid … 独立参考从先前接受/响应队列重算"不符。

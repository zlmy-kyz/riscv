# DDR3 复位与指令/数据争用验证

日期：2026-09-29。

## 目的与改动

验证两路 DDR 请求在未初始化、复位、同时到达时的行为，并检查真实片内 ROM/RAM IP、DDR3 IP 和 DDR3 物理模型组成的 SoC 在外部复位后能否重新训练、重新装载和运行 `ld_st`。

- 新增 `source/tb_ddr_bridge_reset_contention.v`：使读地址命令停在 `ARVALID`，插入复位，确认旧命令/响应消失；DDR 再次就绪后同时提出数据和指令读请求，检查数据优先、两个响应均正确。
- 新增 `source/tb_soc_ddr3_pds_ip_reset.v`：包裹现有真实 IP 测试顶层，在装载器开始写 DDR 后施加一次外部复位；观察 DDR 再次训练、CPU 再次启动和 `ld_st` 结束标志，并统计自然出现的指令/数据 DDR 请求重叠。
- 新增 `source/tb_soc_ddr3_pds_ip_contention.v`：在同一真实 IP/物理模型顶层的已译码 DDR 请求入口注入两路同时有效的读请求，检查实际 DDR 响应顺序与数值。
- 新增 `sim/pds_ddr_reset_compile.tcl`、`sim/pds_ddr_reset_run.tcl`：使用独立的 ModelSim 库和日志，不改 PDS 按钮的原有脚本与配置。
- 新增 `sim/pds_ddr_contention_run.tcl`：复用独立库重新编译并运行物理模型争用用例。

## 复现与已测结果

桥级定向测试：

```powershell
$outFile = Join-Path $env:TEMP 'tb_ddr_bridge_reset_contention.vvp'
& 'D:\iverilog\bin\iverilog.exe' -g2012 -s tb_ddr_bridge_reset_contention -o $outFile 'myriscv/dual_sram_to_pango_ddr_bridge.v' 'source/tb_ddr_bridge_reset_contention.v'
& 'D:\iverilog\bin\vvp.exe' $outFile
```

本轮实际输出：

```text
CHECK: both requests blocked before DDR init
CHECK: in-flight read canceled by reset
CHECK: data request completed before held instruction
RESULT: PASS bridge reset cancellation and data-priority contention
```

完整真实 IP 联仿命令（在 `ipcore/ddr3/sim/modelsim` 目录执行）：

```powershell
& 'D:\modelsim\win64pe\vsim.exe' -c -do 'do D:/riscv/RISCV/sim/pds_ddr_reset_compile.tcl; do D:/riscv/RISCV/sim/pds_ddr_reset_run.tcl; quit -f'
```

该测试要求真实 `inst_rom` 的 `INIT_FILE` 为 `boot_rom.dat`，真实 `data_ram` 的 `INIT_FILE` 为 `ld_st.dat`；使用 `+TEST=ld_st +TOHOST=80002000 +EXPECTED_WRITES=1056`。第三次运行（修正后的测试平台）在 `sim/pds_ddr_reset_ld_st.log` 留下：

```text
CHECK: loader wrote 10 DDR words; assert external reset at 80390000.0 ps
CHECK: DDR retrained and CPU released after reset at 159232000.0 ps
CHECK: ld_st CPU copied 1056 words then fetched from DDR
CHECK: loader recopied 1056 words and refetched DDR after reset
CHECK: DDR overlap cycles=0 idle data-priority cycles=0
RESULT: PASS ld_st DDR RV32I tohost=1 cycles=67203
Errors: 0, Warnings: 353
```

无 `RESULT: FAIL`，ModelSim 运行耗时 18 分 57 秒，结束于 2026-09-29 10:45:09。上述 PASS 发生于复位和再次释放之后。DDR3 物理模型仍输出了与原基线同类的初始化/时序文字 warning；ModelSim 错误计数为 0。

物理模型争用用例的复现命令（同样在 `ipcore/ddr3/sim/modelsim` 目录执行）：

```powershell
& 'D:\modelsim\win64pe\vsim.exe' -c -do 'do D:/riscv/RISCV/sim/pds_ddr_contention_run.tcl; quit -f'
```

`sim/pds_ddr_contention.log` 的本轮结果：

```text
CHECK: seeded DDR word through data bridge port
CHECK: simultaneous DDR reads accepted data first
CHECK: physical DDR data read returned aabbccdd
RESULT: PASS physical DDR data-priority contention and both reads
Errors: 0, Warnings: 353
```

无 `RESULT: FAIL`；2026-09-29 10:53:16 结束，耗时 1 分 45 秒。测试先经数据端写入 `0xaabbccdd`，再保持指令读请求，令数据读先被接受并读回该值，随后指令读也读回该值。它使用真实 DDR3 IP 和 x16 物理模型，并编译真实片内 ROM/RAM IP，但两路争用请求由 TB 注入到 SoC 已译码的 DDR 入口，未经过 CPU 指令执行和地址译码器。

测试平台调试经过：第一次运行在测试平台自身的复位检查处停止。DDR 核心时钟在外部复位期间停止，原检查却要求只在该时钟边沿更新的 TB 标志立即清零。第二次运行在注入复位后超时：Verilog 对 `reg` 执行 `force/release` 后，若没有后续过程赋值，`release` 不会把寄存器恢复到旧值，导致外部复位一直保持低电平；日志保存在 `sim/pds_ddr_reset_ld_st_stuck_reset.log`。最终测试平台改为层级过程赋值明确拉低、拉高 `resetn`。这两次失败属于测试平台问题，不作为 RTL 故障结论。

## 未覆盖范围

桥级定向测试使用简化的 DDR 用户口应答，没有 DDR3 物理时序；复位完整联仿只运行 `ld_st`，不等于 42 项回归或实板验证。`ld_st` 自然执行时指令/数据 DDR 请求同时有效的周期数为 **0**；主动争用由专用 TB 注入 SoC 的 DDR 入口，已验证真实 DDR3 IP/物理模型下的仲裁及两路读回，但尚未证明 CPU 程序自然产生两路 DDR 同时请求。当前策略是数据端优先，没有验证数据请求永久连续时指令端的公平性。

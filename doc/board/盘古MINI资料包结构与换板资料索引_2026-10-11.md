# 盘古 MINI 资料包结构与 RISCV 换板资料索引

核对日期：2026-10-11。资料包根目录：`D:/riscv/RISCV/100K200KMINI`。目标板按用户指定为 MINI-(200H)，目标内存地址规划**先按 1 GiB**；这仍是设计假设，DDR 颗粒丝印/BOM 与 IP 配置须在实现前核实。本文是资料索引及换板输入清单，不代表 PDS 编译或实板验收。

资料包约 7,455 个文件，`2_Demo` 内含大量 PDS 生成的 `compile/`、`pnr/`、日志和仿真文件。下面只列换板时需要定位的层级。

## 三、从资料提取出的关键接口事实

- `2_9_ddr3_test` 的 IDF 是 `PG2L200H/-6/FBB676`、DDR3、125 MHz 参考、`MEM_DQ_WIDTH=32`、4 DQS、4 DM；生成的 `ddr3_test.v` 用户数据口为 `8×32=256 bit`、写 strobe 为 32 bit、控制器地址为 28 bit。它**不能直接接入**目前固定 128 bit 用户数据口的 `soc_ddr3_top`/桥。
- **更正（2026-10-11）：**示例 IDF 中 `DDR3_BASE_MEM_PART=MT41K128M16XX` 是默认参考型号，实际选中的是 `DDR_MEM_PART=MT41K256M16XX`，`MEM_ROW_WIDTH=15`、`MEM_COLUMN_WIDTH=10`、`MEM_BANK_WIDTH=3`。MT41K256M16 为每颗 256M×16＝4 Gbit；若板上确实是两颗该容量的 x16 芯片，并联 x32 合计为 1 GiB。示例配置因而与 1 GiB 目标容量一致，但还须核对实物颗粒和用户口地址语义，并用首尾地址读写验证；它仍不能直接接入当前固定 128 bit 的 SoC 桥。
- `2_9_ddr3_test.idf` 的 Pin/Bank 设置为：PLL 参考 Bank `R5`，Control/Address Bank `R5`，启用 `CS_n`，启用 Custom Control/Address Group；`DQ[0:7]` 到 `DQ[24:31]` 均在 `R4`，四个字节组依次为 `G1/G0/G2/G3`。`USER_PINS_CON_EN=false`，即未启用外部 FDC 输入。新 IP 的界面值可据此填写，但生成后的具体球位仍须与手册/板厂资料逐项比对，不能仅靠 Bank/Group 保证接线正确。
- 手册第 16 页与两套示例 IDF 的 Control/Address 球位一致：`RESET=H1`、`CKE=R1`、`CK/CK_N=U6/U5`、`CS=N4`、`RAS/CAS/WE=P6/T7/T8`、`ODT=H2`、`BA0/1/2=P4/R2/T5`；`A0..A14=J1/L3/L2/P3/T2/M1/U1/K1/U2/K2/T3/P1/T4/M2/N1`。在 IP 的 Custom Control/Address 页，先选 `R5` Bank 和相应 Group，再填球位；`A15` 在当前 15 位行地址配置中不使用。**数据线不可照抄示例 IDF 的位号**：例如手册列 `ddr3_dq[0]=G5`，示例 `PAD_DQ0=F4`；最终 DQ/DQS/DM 与 PCB 接线须按手册和实际板修订版逐项核对。
- KEY/LED 示例 FDC 将复位键 `rstn` 约束到 C22，UART 示例 FDC 将 `uart_tx`/`uart_rx` 约束到 C24/B24。LED 示例 FDC 为 `led[0]=A20`、`led[1]=C18`、`led[2]=C19`；硬件手册和底板映射中的编号应与这些示例逐项核对，**本工程三个状态灯可按选定的物理 LED 自行命名**，不要依赖示例的 `led[i]` 序号。
- `key_led_test.fdc`、`uart_test.fdc` 中的 `clk=D18` 是例程的 27 MHz 系统时钟；本工程 DDR 使用的参考是手册所示 125 MHz 差分输入 N3/N2。不能把 D18 约束移给 `ddr_ref_clk_p/n`。
- DDR 示例 `pnr/ddr_test.fdc` 含 8 ns 参考时钟和 PHY 生成时钟约束，绑定示例顶层名/层级；重新生成目标 DDR IP 后应核对并适配其实际层级和端口，不能把它当作完整的 `board_top` 约束直接复制。

## 四、映射到本工程的换板输入清单

| 本工程入口 | 所需资料和待核项目 |
| --- | --- |
| `RISCV.pds` | 确认 PG2L200H、-6、**实际封装**、设计顶层 `board_top`；核对 RTL、ROM/RAM/DDR IP 和 FDC 路径存在且对应同一目标器件。 |
| `constraint_check/temp_constraint_file.fdc` | 用手册 DDR 球位、125 MHz 参考 N3/N2，以及示例 KEY/LED/UART FDC 重建全套 IO/Bank/时钟约束；逐项对 `board_top` 端口，核对 DDR 专用管脚与 1.5 V、普通 IO 电压。 |
| `ipcore/inst_rom`、`ipcore/data_ram` | 在新器件下重建两块独立 16 KiB IP，保持端口/读延迟和已验收 ROM/RAM 初始化镜像身份；不能把双总线同址存储合并。 |
| `ipcore/ddr3`、`myriscv/soc_ddr3_top.v`、`myriscv/board_top.v` | 用目标颗粒生成 x32 DDR3 IP；核对 DQ/DQS/DM、用户数据/地址/strobe 宽度、core clock、复位/训练状态和 APB 接法，再调整顶层。 |
| `myriscv/dual_sram_to_pango_ddr_bridge.v`、`myriscv/{soc_top,inst_bus_interconnect,data_bus_interconnect}.v` | 将 CPU 窗口按 1 GiB 规划为 `0x4000_0000–0x7fff_ffff`；依据**新 IP 实际接口**重新推导地址映射、拍内 32 bit 槽位和写字节使能。只扩大译码 mask 会造成高 512 MiB 别名。 |
| UART/LED/软件镜像 | 若新 DDR IP 的 `core_clk` 改变，更新 `UART_CLK_HZ`、LED/超时计数；核对 Loader/程序链接地址、复制长度与 ROM/RAM 分离镜像。后续上板用通过相应验收的同一对 DAT。 |

**当前工作树快照（2026-10-11 核对时）：**`RISCV.pds` 已选 `PG2L200H/-6/FBB676`，但 Git 状态显示旧 `constraint_check/temp_constraint_file.fdc` 和 `ipcore/` 下多项 ROM/RAM/DDR 文件被删除；PDS 仍引用该 FDC。它们可能正由用户在 PDS 中重建，不应恢复、覆盖或把此状态写成换板完成。旧迁移分析另见[盘古200K MINI 迁移核对](盘古200K_MINI迁移核对_2026-10-11.md)，其中对旧工程的描述是当时快照。

## 五、复核方法、结果及未覆盖范围

- 目录/文件清点：`rg --files 100K200KMINI`，并分别检查六个一级目录；读取 GBK 版根目录说明。
- 参数/端口核对：对 `2_9_ddr3_test`、`DDR_200H` 的 `.pds`、`.idf`、生成 `.v`、`.fdc` 定向检索 `device/package/MEM_DQ_WIDTH/CTRL_ADDR_WIDTH/CLKIN_FREQ/DDR_MEM_PART/MEM_ROW_WIDTH`；只对 `mini-base管脚映射.xlsx` 作只读检索。
- 工程状态：`git status --short -- RISCV.pds ipcore constraint_check 100K200KMINI`，并核对 `RISCV.pds` 的器件选择和 FDC 引用。
- 结果：完成资料位置、200H 示例接口和按两颗 256M×16 推导的 1 GiB 示例配置核对；随后纠正将默认 `DDR3_BASE_MEM_PART` 误认作实际颗粒的错误。没有执行 PDS、生成 IP/位流、仿真或实板测试。
- 未覆盖：实际芯片/DDR 颗粒丝印与板厂 BOM、核心板原理图、完整 x32 DDR 引脚及 Bank 审核、为 1 GiB 新生成的 IP 接口和最高地址验证、时序收敛与实板通信。

## 目的

用板上三个 LED 分别观察 DDR 用户时钟、DDR 就绪/CPU 复位释放、CPU 执行 DDR 自检的结果。失败上报不依赖读取 DDR 诊断区；CPU 未启动或执行停滞时，由硬件超时给出失败指示。

## 顶层输出和板卡连接

`myriscv/soc_ddr3_top.v` 增加三个高电平点亮的输出。引脚依据板商[《RK3568_MES2L50H/MES2L100H 硬件使用手册 v1.1》](https://szlogicmatrix.com/wp-content/uploads/2025/12/RK3568_MES2L50H_100H_%E7%A1%AC%E4%BB%B6%E4%BD%BF%E7%94%A8%E6%89%8B%E5%86%8C_v1.1.pdf)第 2.1.11 节，PDF 第 18–19 页：

| 顶层输出 | 板上 LED / FPGA 球位 | 显示规则 | 能说明什么 |
| --- | --- | --- | --- |
| `led_clk_alive` | 底板 LED3 / J16 | 1 Hz 闪烁 | `core_clk` 和心跳计数器正在运行；训练期间也可闪烁 |
| `led_ddr_ready` | 底板 LED4 / M17 | 就绪时常亮 | `ddr_init_done && pll_lock` 已经过两拍同步，`soc_resetn` 已释放 |
| `led_selftest` | 核心板 K17_LED4 / K17 | 未开始熄灭；运行中 1 Hz 慢闪；PASS 常亮；FAIL/超时 4 Hz 快闪 | CPU 自检程序上报的结果，或硬件检测到启动/执行超时 |

心跳和就绪不证明 DDR 数据正确。自检 PASS 对应当前程序覆盖的区域和花样，不能证明全容量、所有指令或长期稳定性。FAIL 和超时共用快闪，单凭灯不能区分二者。

正常自检可能在毫秒内结束，因此运行慢闪未必能被肉眼看见；最终 PASS 常亮会保留到复位。超时后如果时钟仍运行，FAIL 灯持续快闪；若 `core_clk` 停止，所有闪烁计数也会停止。

`constraints/rk3568_leds.fdc` 保留为历史球位片段；本次新增并导入 `constraints/rk3568_board.fdc`，已合并三个 LED、KEY0、差分参考时钟及全部 DDR 球位，不再重复导入 LED 片段。KEY0/LED FPGA 控制侧为 1.8 V；LED 供电 3.3 V 不决定 FPGA IO 标准。当前完整板级 FDC 仅给出确定的 Location 和 125 MHz 主时钟；Bank 电源、电气标准、驱动等仍须结合实物原理图核对。

## RTL 行为和参数

- `soc_ddr3_top` 内新增 `u_leds : soc_ddr3_leds`，辅助模块放在同一个 `.v` 文件末尾，现有 PDS/ModelSim RTL 源列表可直接编译。
- `CORE_CLK_HZ` 默认 `100_000_000`，用于 LED 分频；`SELFTEST_TIMEOUT_CYCLES` 默认 `CORE_CLK_HZ * 5`，即 5 秒。这里是 DDR IP 输出的 **core_clk 频率**，不是直接使用输入晶振频率。修改 IP 后须核对实际用户时钟并设置该参数。
- 时钟灯使用进入 SoC 的 `resetn` 复位（板级来自消抖后的 key_resetn），不受 DDR 训练期间的 `soc_resetn=0` 阻止。若 IP 没有输出 `core_clk`，心跳也不会运行。
- 自检看门狗从 `soc_resetn` 释放后的第一拍计时，包含片内装载器复制程序的时间；IDLE/RUN 均计时，PASS/FAIL 停止计时。DDR 训练时间不计入该超时。
- 超时锁存后，迟来的 PASS 不能把快闪变成常亮。外部复位或 SoC 重新进入复位会清除结果和超时；没有提供软件清除接口。
- `soc_top` 增加 `selftest_status[1:0]` 输出，来自 `u_simple_mmio`。所有新增信号均在 `core_clk` 域内，没有新增 CPU/DDR 跨时钟数据路径。

## MMIO 上报协议

`simple_mmio` 新增偏移 `0x10 TEST_STATUS`，默认绝对地址 `0x10000010`；原有 `SCRATCH/ID/CYCLE/STATUS` 行为保持兼容。

| 读值 / 写命令 | 含义 | 接受条件 |
| --- | --- | --- |
| 0 | IDLE，仅复位后读到 | 写 0 返回错误，不能清除状态 |
| 1 | RUN | IDLE→RUN；重复 RUN 无变化 |
| 2 | PASS | RUN→PASS；IDLE 时写入返回错误 |
| 3 | FAIL | RUN→FAIL；IDLE 时写入返回错误 |

读返回零扩展的两位状态。写入仅最低字节 `req_wstrb[0]` 生效，命令取 `req_wdata[7:0]`；其他字节写入不改变状态。最低字节命令不是 1/2/3 时返回总线错误。PASS/FAIL 为终态，后续合法命令不改变已锁存结果。

硬件超时状态位于 `u_leds`，没有回写 MMIO。例如 CPU 未启动时，MMIO 仍读到 IDLE，而 LED 已快闪；CPU 在超时后才上报 PASS 时，MMIO 可读到 PASS，LED 仍保持超时快闪。需要区分具体原因时应结合调试信号和诊断区。

RV32I 上报示例（伪汇编）：

```asm
li t0, 0x10000010
li t1, 1
sw t1, 0(t0)     # RUN
# ... 执行检查 ...
li t1, 2        # 失败分支写 3
sw t1, 0(t0)     # PASS / FAIL 锁存至复位
```

## 自检镜像与仿真入口

`MyCpu_test/build_ddr_selftest.py` 在程序入口写 RUN，完成比较与成功诊断记录后写 PASS，失败分支先写 FAIL 再写 DDR 诊断区。后者确保已发现错误时，即使诊断区写入停滞，FAIL 灯仍有依据。程序由历史 237 字增至 **245 字**，成功比较仍为 112 次。

快速自检 TB 检查真实 CPU 的 MMIO 上报序列，并连接 LED 模块检查 PASS 常亮；完整物理模型 TB 的 `+CHECK_SELFTEST_LED` 开关同样检查 RUN→PASS/FAIL 与 `tohost` 的一致性。通用 RV32I 测试未启用该开关。`sim/pds_ddr_selftest_run.tcl` 从 `manifest.tsv` 读取装载字数，避免固定写死 237。

现有自检地址仍为仿真布局：DDR 程序 `0x80000000`、诊断区 `0x80001000`，对应自检 TB 的 `DDR_BASE=0x80000000` 覆写。RTL 默认 DDR 窗口仍为 `0x40000000`；部署时须匹配顶层参数与镜像地址。主 PDS `data_ram` 仍初始化 `ld_st.dat`，该 RV32I 镜像没有新的上报指令，直接运行它会在超时后快闪。自检使用 `MyCpu_test/ddr_selftest/ipcore/data_ram` 隔离 IP；部署前需选择自检镜像并重新生成实际片内 RAM IP。

# RK3568_MES2L100H → 盘古 200K MINI 工程迁移核对（2026-10-11）

## 目的与现状

本步只读审查当前工程，为迁移至用户所述 `MINI-(200H)` / PG2L200H、676 球封装列出修改点；未改 RTL、PDS、IP、约束或镜像，未运行 PDS/仿真/实板。工作树已有大量未提交改动，不能把旧板成功位流或仿真结果当成新板验收。

当前设计入口 `RISCV.pds` 的设计顶层为 `board_top`，器件选择是 `Logos2 / PG2L100H / -6 / FBG484`，约束入口是 `constraint_check/temp_constraint_file.fdc`。`ipcore/inst_rom/inst_rom.idf`、`ipcore/data_ram/data_ram.idf`、`ipcore/ddr3/ddr3.idf` 的 header 均绑定旧器件与封装。旧 DDR IP 为 x16，参考 125 MHz，`board_top.v` 和 `soc_ddr3_top.v` 按 `core_clk=93.75 MHz`、差分参考、KEY0 20 ms 消抖编写。`board_top.v` 的 DDR 实体端口为 16 根 DQ、两对 DQS。CPU DDR 桥的用户数据口固定 128 位。

## 先决资料

必须按实物 PCB 修订版取得板厂原理图、管脚表、DDR3 例程及对应 PDS 工程。公开[小眼睛/逻辑矩阵竞赛说明](https://szlogicmatrix.com/forum-post/1291.html)把 200K MINI 列为独立板卡，并说明原理图与 IP 资料需向板厂获取。公开[同板 RISC-V 教程](https://szlogicmatrix.com/forum-post/1281.html)称 `MES2L676-200HP-MINI`、器件 `PG2L200H-6FBB676`；用户提供的标识为 `PG2L(200H)-6IFBG676`。另外，[竞赛资料](https://szlogicmatrix.com/forum-post/1324.html)对 676 系列 200H 写 `PG2L200H-6IFBG676`。这些表述不一致，必须以实物芯片丝印、板厂该修订版 BOM、PDS 器件列表共同确认，不能预先把 FBB676/FBG676 当成同一封装。

需核对：DDR 颗粒型号/数量/位宽/容量及走线、DDR 专用差分参考时钟的实际频率和输入球位、DDR Bank 电压与 VREF、按键/LED 极性和球位、UART 是否接 USB 转串口及其电平、配置/JTAG 接口。教程的 27 MHz `clk` 和例子 FDC 是另一个 SparrowRV 工程的系统时钟/信号定义，不能直接套入本工程的 DDR 参考时钟及 `board_top` 端口。

## 修改顺序

1. 在 PDS 中基于现有源码另建新板工程或保留旧工程副本，选择经核实的 PG2L200H、-6、正确 676 封装；设计顶层继续用 `board_top`。不使用旧 `impl.tcl`：它是含多轮旧命令的生成历史，不是当前项目配置入口。
2. 在新器件下重新生成 `inst_rom`、`data_ram` 和 DDR3 IP。ROM/RAM 保持 CPU 接口、16 KiB 深度、读延迟与原 ROM/RAM 镜像各自对应。DDR IP 必须匹配新板颗粒、x16/x32 实际布线、引脚分组、时钟、速率和电气设置；不能只手改旧 IDF 的 `<device>`/`<package>`。若新 DDR 用户口的地址、数据宽度或时序变动，连同 `soc_ddr3_top.v` 和 `dual_sram_to_pango_ddr_bridge.v` 的接口/地址换算一起修改。
3. 依据新板原理图重建 FDC：DDR 全部信号、参考时钟、按键、LED、UART 的 `PAP_IO_LOC`、`PAP_IO_VCCIO`、`PAP_IO_STANDARD`；时钟约束以新生成 DDR IP 的例程和实际输入频率为准。不能沿用旧 FDC 的球位或 DDR PHY 层级时钟路径。
4. 若参考时钟不是差分，修改 `board_top.v` 的参考时钟端口及 `GTP_INBUFDS`。按实际参考频率调整 KEY 消抖周期；按新 DDR IP 的 `core_clk` 调整 LED/自检计时与 UART 分频。当前 `soc_ddr3_top.v` 虽有 `CORE_CLK_HZ`，例化 `soc_top` 时未传 `UART_CLK_HZ`，因此若 `core_clk` 改变，还须显式传递真实频率。若 DDR 物理位宽变动，调整板级 DDR 端口和 `soc_ddr3_top.v` 连接；若仅用户口宽度仍为 128 位，桥的 32 位槽位逻辑可先保持并验证。
5. 核对新 IP 的 ROM/RAM `INIT_FILE`、启动布局和新板 DDR 窗口容量。保留已验收的 ROM/RAM DAT 身份，除非端口/IP 格式要求变换，任何变换都要重新验收。旧 `board_top.sbit` 不能在新器件上复用。
6. 用户在新工程执行 PDS 编译、综合、映射、布局布线、时序分析和生成位流；先看引脚/Bank/DDR IP 约束错误，再看所有时序端点。上板先检查参考时钟、DDR `pll_lock`/`ddr_init_done`、复位释放与 LED，再用 UART Loader/DDR 读写定向软件，最后跑 CoreMark。仿真 PASS、DDR 训练、时序 PASS、实板 PASS 分开记录。

## 1 GiB 工作假设与 CPU 地址规划

用户 2026-10-11 明确选择**先按两颗各 4 Gbit，即每颗 512 MiB、合计 1 GiB**进行 MINI 迁移设计。这是设计假设，实物 DDR 丝印/BOM 尚未核实；不再因手册第 8/10 页的较小容量文字把目标窗口限定为 512 MiB。

目标 CPU 字节地址窗口为 `0x4000_0000–0x7fff_ffff`（1 GiB），DDR 局部字节偏移为 `0x0000_0000–0x3fff_ffff`。若采用现有掩码译码形式，两路互连及 `soc_top` 的 DDR mask 需从 `32'he000_0000` 改为 `32'hc000_0000`，同时保持 ROM/RAM/MMIO/UART 的独立译码优先级。

**仅改 mask 不成立。**现有桥默认 `CTRL_ADDR_WIDTH=28`，按旧 x16 IP 的“用户地址单位 16 bit 字、128 bit 数据拍”计算：`selected_ctrl_addr = {selected_addr[28:4], 3'b000}`。目标局部字节地址需要 30 bit；在旧换算规则下控制器地址需要 29 bit。若其余不改，局部字节地址 `0x2000_0000` 的 bit29 被丢弃，CPU `0x6000_0000` 将别名到 `0x4000_0000`。相关路径包括 `dual_sram_to_pango_ddr_bridge.v`、`soc_top.v` 和 `soc_ddr3_top.v` 的地址宽度及最终 DDR IP 用户口。

新 x32 DDR IP 的**实际用户地址单位和数据拍宽度必须以生成端口/文档为准**。若仍以 16-bit 字寻址且拍宽保持 128 bit，应扩展为 29-bit 地址并核对各级端口/拼接；若寻址单位或拍宽改变，重新推导地址转换、拍内槽位、写 strobe、I/D 缓存行与返回选择。DDR3 容量为 1 GiB 不等于用户口地址天然为 29 bit，不能在未生成新 IP 时写死该结论。

新 IP 接入后，最小定向验证要让 CPU `0x4000_0000` 与 `0x6000_0000` 写入不同数据并分别读回，再检查最高有效字地址 `0x7fff_fffc` 和窗外 `0x8000_0000` 的响应；同时确认指令与数据两路都能到高半区。暂未改主 RTL/PDS，因为新 IP 端口契约未确定，单独扩大译码会产生真实别名风险。

## 15:10 布局入口 IO 标准修复（当前入口为临时 FDC）

用户主工程 Place & Route 在读 `device_map/board_top.pcf` 时报告四条 0007：第 23–25 行三颗 LED 使用 HSTL18D_I，第 53 行单端 mem_rst_n 使用 HSTL15D_I。这不是这些标准在所有端口都不受支持，而是单端端口被配置成差分标准。KEY0 当时 VCCIO=1.8、IOSTANDARD=LVCMOS15，也与已核对的 1.8 V 板级信号不一致。

检查 Git 状态及差异后，备份源约束到 `constraints/constraint_backup/temp_constraint_file_before_iostandard_fix_20261003.fdc`，修改实际导入的 `constraint_check/temp_constraint_file.fdc`：

- 三灯和 resetn：LVCMOS18，保留 1.8 V。
- DDR 单端端口（DQ、DM、地址、Bank、控制、mem_rst_n）：按当前 IP 生成例程改为 SSTL15_I。
- DDR CK/DQS 差分端口及参考时钟：按当前 IP 例程改为 SSTL15D_I。
- DDR 输出/双向 DRIVE 采用当前 IP 例程的 8.9 档位。

共修改 55 条 STANDARD 和 49 条 DDR DRIVE 属性；逐行对比备份确认 55 个 Location、所有 VCCIO、17 条时序命令及其它属性不变。保留用户当前选择的 DDR/参考 1.5 V，但它仍未被实板原理图/测量证实。本步不修改未导入的 `constraints/board_top.fdc`，不直接编辑主工程自动生成的 PCF，不改 RTL、IP 或 PDS 配置。

Compile、Synthesize、Device Map 完成；新 PCF 中四条错误输出及 KEY 均是修正后的属性。PNR 日志在 2026-10-03 15:10:17 结束，所有 55 条 `def_port` 都被成功接受，0007 消失，M15 share pin 仅保留 C 类提示。**完整 PNR 仍失败**，新阻塞为 Place-0054：`u_soc/u_ddr3/u_ddrphy_top/ddrphy_slice_top/i_ca_group[0].u_ddc_ca/ddc_inst` 关联 IO 必须在同一 DQS group。

该新错误发生在约束检查结束后的 pre global placement。当前 IP 的 PAD_DQ0=C2、PAD_DQS0=E1 等仍为旧示例球位，而源 FDC 为板卡 P6/P5；生成的 slice RTL 也硬编码 A0/A5 等 CA 分组。只改外部 Location 不会重生成 IP 内部的 PHY 分组，需在 IP Pin 配置中按板卡球位重配 PAD/CA/DQ/DQS 并重新生成，再检查 PHY 专用物理约束。不能移动已确认板卡球位来满足旧 IP，也不能用时序例外跳过此物理错误。该步骤未盲改厂商生成 RTL；新 IP 生成将需要完整 DDR 联仿及实现回归。

主工程 GUI 须重新加载当前源 FDC，重新执行 Compile/Synthesize/Device Map 以生成新 PCF，再运行 Place & Route；仅重跑 PNR 会读到旧 PCF。CLI 在失败时返回 0，本次结论以日志 E/Program Error Out 为准，不能根据退出码宣布成功。此次未跑 CPU 仿真，约束改动也不代表实板电气或时序已通过。

## 报错原因与修改

| 报错 | 原因/处理 |
| --- | --- |
| ConstraintEditor-0046，找不到 ddr_ref_clk_p/n | 旧视图对应 soc_ddr3_top；当前编译已是 board_top，新检查已能找到两个端口。 |
| ConstraintEditor-0049，INPUT 不支持 DRIVE/SLEW | 输入没有输出驱动能力，删除 ddr_ref_clk_p、ddr_ref_clk_n、resetn 的输出驱动/摆率属性。 |
| ConstraintEditor-0007，差分 CK/DQS 的 HSUL12 非法 | 单端模板不能直接用于差分信号；未确认板卡电气参数前撤下套用的标准，不用 HSUL12D 掩盖电压未知的问题。 |
| ConstraintEditor-4026，重复属性覆盖 | 文件末尾有 GUI 追加的同一端口属性，合并为每个端口/属性唯一一条。 |
| ConstraintEditor-2002，M15 是 share pin | 当前是 C 类提示，表明 M15 是复用管脚，不是上述 E 类约束检查失败原因。实现时仍须核对配置管脚复用设置。 |

`board_top.fdc` 保留全部 **55 个球位及方向**，保留原有 `PAP_IO_UNUSED TRUE`，没有改变球位映射。KEY0/M15、LED J16/M17/K17 的 FPGA 控制侧已确认是 1.8 V，配置 `PAP_IO_VCCIO 1.8`、`PAP_IO_STANDARD LVCMOS18`；不指定未经确认的驱动强度/摆率。

DDR 和 R4/T4 参考时钟撤下模板的 `VCCIO 1.2`、`HSUL12/HSUL12D`、`DRIVE 0.1`、`SLEW FAST`，并在文件头留下 TODO。GUI 追加的 `ddr_ref_clk_n PAP_IO_DDR_TERM_MODE OFF` 也需在确认参考时钟标准/终端后再启用，已保留为文件头备注。

## 电气依据与剩余缺项

现有 IP **示例** `ipcore/ddr3/pnr/ddr_test.fdc` 对 DDR 使用 **1.5 V**：单端 `SSTL15_I`，CK/DQS 差分 `SSTL15D_I`。这证明原来的 1.2 V 模板与生成示例不同，但示例球位不是本开发板球位，且主 PDS 没有导入该示例；不能视为本板已生效的完整电气约束。

再次读取[板卡厂商硬件使用手册 v1.1](https://szlogicmatrix.com/wp-content/uploads/2025/12/RK3568_MES2L50H_100H_%E7%A1%AC%E4%BB%B6%E4%BD%BF%E7%94%A8%E6%89%8B%E5%86%8C_v1.1.pdf)的完整相关页面：PDF 第 9–10 页（正文第 6–7 页）给出 125 MHz 振荡器 U24，3.3 V 供电，C272/C273 交流耦合，电阻网络连接 `FPGA_VCC_DDR`，R181 外部 100 Ω 跨差分端终端；PDF 第 12 页确认 DDR 接 Bank R4/R5。这里没有给出 `FPGA_VCC_DDR` 的电压数值，也没有给出振荡器具体型号/输出标准。3.3 V 振荡器供电不能用于推断 FPGA Bank 电压。

需取得与实物版本一致的原理图或板厂参考 FDC，确认：

1. DDR Bank R4/R5 的实际 VCCIO、VREF、颗粒供电与 IP 电气配置。
2. R4/T4 的输入标准、共模/摆幅，以及外部终端与 GTP_INBUFDS 默认内部终端是否应同时启用。

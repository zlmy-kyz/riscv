# 异常与中断：第 5 步异常记录和副作用抑制

本步在 [`mycpu_sync.v`](/D:/riscv/RISCV/myriscv/mycpu_sync.v) 中建立同步异常的流水通路。**第 5 步交付时尚无真实指令产生 `id_exc_valid`，也尚未接入 EX 的具体异常检测**；测试台通过注入信号验证通路。第 6 步接入 ECALL/EBREAK 及 trap CSR 更新，第 7 步接入非法指令/CSR，第 8 步接入数据地址非对齐。

## 异常项如何流动

| 阶段 | 行为 |
|---|---|
| ID | `id_exc_valid/cause/tval` 为预留检测入口。本步默认全零；若检出异常，仍让该指令以 `valid=1` 发射，并把异常记录、PC、指令字锁入 ID/EX。故障分支不能在 ID 先重定向。 |
| EX | `ex_exc_*` 先原样传递已有异常，未来可叠加 EX 检测。故障 store 的 RAM 写许可在 EX 当拍关断。 |
| MEM | EX/MEM 的异常记录与 PC、指令字同拍推进；若这里有老故障，正在 EX 的年轻 store 写许可关断。 |
| WB | `mem_wb_valid && mem_wb_exc_valid` 产生一次 `sync_trap_event`；故障项不写 GPR/CSR，也不是 `normal_retire`。控制重定向到当前 `mtvec`，清除年轻流水项。 |

气泡表示 `valid=0`，异常项表示 `valid=1 && exc_valid=1`。不能用 `exc_valid` 代替流水项的有效位，否则异常项可能在推进中丢失。已有 ID 异常传到 EX/MEM/WB 时保持原因码和 `tval`，不会被后续默认译码覆盖。复位、气泡和 kill 会清除对应异常记录。当前流水线只对前端保持并向 ID/EX 插气泡，EX/MEM/WB 不做数据停顿；因此故障项在前端等待期间仍向 WB 推进。将来若增加总线等待，需要让异常记录与 PC/指令字一起保持。

## 关键内部信号

| 信号 | 位宽 | 作用 |
|---|---:|---|
| `id_exc_valid/cause/tval` | 1/5/32 | ID 异常入口，本步默认零；后续连接具体检测器。 |
| `id_ex_exc_*`、`ex_mem_exc_*`、`mem_wb_exc_*` | 每级 1/5/32 | 异常记录与原有 PC、指令字、valid 同步传递。 |
| `ex_exc_valid/cause/tval` | 1/5/32 | EX 级异常合成位置，目前透传 ID 记录。 |
| `fault_inflight` | 1 | ID/EX、EX/MEM 或 MEM/WB 含异常项；阻止年轻项继续发射并保持前端。 |
| `older_fault_for_ex` | 1 | EX/MEM 或 MEM/WB 有老故障；当前 EX store 属于年轻指令，不能提交。 |
| `ex_store_commit` | 1 | 有效 store、非故障、无老故障、未取消且非复位时才为 1；同时门控 RAM `wr_en` 和字节使能。地址及读取时序未改变。 |
| `sync_trap_event` | 1 | WB 有效故障项的单拍事件；驱动控制重定向和年轻级取消。 |
| `normal_retire` | 1 | WB 有效、非故障、非非法 CSR 项的正常退休条件；本步主要用来区分故障项，后续可接性能计数/差分接口。 |

故障项在 EX、MEM、WB 均被排除出前递源；WB GPR 写口和 CSR `csr_commit` 也受故障标志门控。故障在 ID 或 EX 被发现后，前端停止发射；老指令可继续完成。即使故障较晚才在 MEM 被发现，`older_fault_for_ex` 也会在同一周期阻止年轻 store 写 RAM。当前数据 RAM 在 EX 沿写入，所以仅在 WB 屏蔽写回不足以保证精确异常。

`sync_trap_event` 已使用第 3 步预留的重定向控制，将 PC 转向 `csr_file.trap_target`（复位默认 `0x100`），并清除年轻项。**第 5 步尚未拉高 `csr_file.trap_enter`，所以当时的 `mepc/mcause/mtval/mstatus` 不会更新；该重定向只用于验证流水控制。**第 6 步已接入 ECALL/EBREAK 及 CSR trap 更新，handler 可以根据异常记录处理并返回。

## 验证

新测试台 [`tb_exception_path.v`](/D:/riscv/RISCV/difftest/tb/tb_exception_path.v) 包括三个场景：

1. 在 ID 给一条 `addi` 注入异常，检查原因、`tval`、PC、指令字随项到 WB；老 store 完成，故障指令的 GPR 写及年轻 store 被抑制，WB 只触发一次 trap，重定向后目标首条指令执行。
2. 给 store 本身注入异常，检查 EX 当拍 RAM 写许可为零，年轻 store 也不写入。
3. 模拟老指令到 MEM 才检出异常，同时年轻 store 在 EX；检查年轻 RAM 写立即关断，故障记录到 WB，故障 GPR 写不提交。

结果：`RESULT: PASS exception payload, precise stores, WB event and redirect`。`prog0_alu`、`prog1_mem`、`prog2_hazard_precision` 的指令/写回差分及 GPR/RAM 终值均通过；第 4 步 CSR 测试、流水控制测试和冒险测试也通过。真实 FPGA 综合、具体异常检测以及 trap CSR 更新未在本步验证。

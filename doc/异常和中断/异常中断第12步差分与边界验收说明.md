## 参考模型检查内容

模型维护 32 个 GPR、4 KB 小端 RAM、`mstatus/mie/mtvec/mscratch/mepc/mcause/mtval`、当前架构 PC。它实现当前内核使用的 RV32I 运算、访存、分支与跳转，以及六条 CSR 指令、ECALL、EBREAK、MRET、FENCE 和本阶段作为 NOP 的 WFI。非法指令、数据地址非对齐、被采用的跳转目标非对齐均由模型独立决定 cause 与 `mtval`。中断原因从**测试台提供的原始三路输入**、模型自身的 `mie/mstatus` 计算，按 MEI > MSI > MTI 仲裁。

每条正常退休都检查 `{PC, 指令, GPR 写回目标和值}` 与模型下一条应执行的指令一致。每次同步 trap 检查模型自己算出的 cause/`mtval`；每次中断接受检查模型的使能、pending、优先级和独立续执行 PC。trap 与 MRET 后逐项比较 `arch_next_pc`、7 个可变 CSR、32 个 GPR 和 1024 个 RAM 字。这样若 RTL 用超前的预取 PC 写入中断 `mepc`，快照和下一条退休 PC 都会报错。日志只决定**何时**重放退休或中断事件；参考模型负责判定事件是否合法及其架构结果。逐拍发射和排空条件另由 HDL 断言检查。

## 边界覆盖与断言

| 边界 | 定向检查 |
|---|---|
| 老异常与年轻异常同拍 | 第 9 步故障 load 与年轻非对齐 branch 同拍；先处理 load，返回后处理 branch。 |
| 错误路径异常 / store | 第 9 步 JALR、branch 后的零编码不得发射；第 11 步 JAL 后的错误路径 store 不得发内存请求，RAM 对应字保持零。 |
| 故障项副作用 | 故障 WB 项不得正常退休或写 GPR；故障 load/store 不得产生有效访存请求。 |
| store 恰好一次 | 测试台为每条 ID 发射分配独立 token，EX 写入时检查 token 此前未写；中断接受边界上请求数与退休数相等。 |
| 中断撤销 | 定时器请求在排空中撤销后不进入 trap，前端恢复。 |
| load-use 与中断同拍 | 目标 `lw x6` 在 EX、依赖的 `addi x7` 在 ID 停顿时注入 MSI；消费者不得提前发射或退休，中断 `mepc=0x30`，返回后只执行一次。 |
| 接受边界 | `irq_take` 要求 ID/EX、EX/MEM、MEM/WB 全空；同时无 ID 发射、load/store 请求、正常退休或同步 trap。 |

当前 RAM IP 没有独立读请求/响应握手，排空断言基于固定一拍 BRAM 时序；未来总线阶段需增加 outstanding 检查。输入是同步电平，板级异步同步器及软件可清除源属于后续 SoC 工作。

## 回归结果

| 测试 | 结果 |
|---|---|
| 普通程序 `prog0_alu`、`prog1_mem`、`prog2_hazard_precision` | 三组指令流、写回、GPR/RAM 终值差分 PASS |
| CSR 文件及第 4～11 步十组专项 RTL 测试 | 全部 PASS |
| 非法指令/CSR 日志重放 | `R=142 T=8 M=8 I=0 S=16`，PASS |
| 数据非对齐日志重放 | `R=197 T=11 M=11 I=0 S=22`，PASS |
| 跳转目标非对齐日志重放 | `R=115 T=6 M=6 I=0 S=12`，PASS |
| 中断日志重放 | `R=106 T=1 M=10 I=9 S=20`，PASS |

# 异常与中断实现步骤清单

依据：[RV32I异常与中断实现方案](../cpu/RV32I异常与中断实现方案.md)。

适用方案：单核、仅 M 模式、无 C 扩展；保留 EX 级 BRAM 访存；CSR/MRET 串行执行；同步异常在 WB 处理；中断停止发射并排空后响应。

清单中的勾选表示该步骤的交付物完成且验收通过。第 1 步仅固定接口和普通指令基线，不表示异常或中断已经接入 CPU。

实施顺序：**固定接口 → CSR 模块 → 流水控制 → CSR 指令 → 异常通路 → ECALL/MRET 闭环 → 各类异常 → 中断 → 实际中断源 → 联合验证。**

## 1. 保存基线，确定本阶段接口

- [x] 保存当前 RTL 和测试结果，跑通 `prog0_alu`、`prog1_mem`、`prog2_hazard_precision` 及停顿检查。
- [x] 固定 CSR 地址、可写位、复位值和异常编号，统一放入定义文件或同一组 localparam。
- [x] 确定 trap 入口地址和处理程序存放位置；首版采用 mtvec Direct 模式。
- [x] 定义 `id_fire`、正常退休、trap、MRET 和内存请求实际发生的事件，区分它们与单纯的 valid。

本步记录见[异常中断第1步接口与基线](异常中断第1步接口与基线.md)。

验收：已有测试通过；接口命名与异常编号没有多份冲突定义。

## 2. 编写独立的 csr_file 模块

- [x] 实现 mstatus、mie、mtvec、mscratch、mepc、mcause、mtval、mip。
- [x] 加入方案中固定值的 misa、mstatush 和标识 CSR，形成明确的已实现地址表。
- [x] 实现读端口、软件写端口、写掩码及合法值约束；MPP 固定为 M，mepc 低两位固定为零。
- [x] 实现 `csr_exists`、只读地址写访问等合法性判断；区分只读 CSR 地址与 CSR 内只读字段。
- [x] 预留一次性 `trap_enter`、`mret_commit` 和三根中断状态输入，由一个时序块统一更新 CSR 状态。

本步模块接口、状态规则及单元测试见[异常中断第2步CSR模块说明](异常中断第2步CSR模块说明.md)。

验收：独立测试复位、正常读写、保留位、非法地址，以及 trap/MRET 对 MIE、MPIE、MPP 的更新。

## 3. 改造流水控制，建立串行执行能力

- [x] 区分前端保持、ID/EX 插气泡、各级取消和 PC 重定向，不复用一根含义模糊的 flush。
- [x] 增加“停止 ID 发射，但允许老 EX/MEM/WB 继续推进”的控制。
- [x] 增加串行等待与运行状态：老指令排空后只发射一次特殊指令，完成前不放行年轻指令。
- [x] 统一 PC 和 ROM 地址口的重定向选择，重定向优先于 load-use 保持。
- [x] 增加 refill/取指有效性控制，丢弃旧取指返回值。
- [x] 复位清除新状态和有效位，禁止复位沿的寄存器、CSR 和 RAM 写入。

本步实现与测试范围见[异常中断第3步流水控制说明](异常中断第3步流水控制说明.md)。

验收：普通程序仍通过；人为保持多拍不会重复发射指令；重定向后 PC/inst 配对且第一条指令不丢。

## 4. 接入六条 CSR 指令

- [x] 实现 CSRRW、CSRRS、CSRRC、CSRRWI、CSRRSI、CSRRCI 的读许可、写意图和读改写操作。
- [x] 流水项携带 CSR 地址、操作、源值、rd、PC 和指令字；首版在 WB 读取并提交 CSR。
- [x] WB 增加 CSR 旧值到 GPR 的写回选择，并同步修改 debug 写回数据。
- [x] 修改 GPR 写许可为已实现指令白名单，移除 `~wmem & ~inst_b` 的宽泛判断。
- [x] `uses_rs1` 加入三条寄存器型 CSR 指令；三条立即数型 CSR 不读取 GPR，所有 CSR 都不读取 rs2。
- [x] CSR 提交后预留中断重评估控制周期，再释放年轻指令。

本步实现、信号及测试见[异常中断第4步CSR指令接入说明](异常中断第4步CSR指令接入说明.md)。

验收：六条指令结果正确；连续 CSR 写读、CSR 结果紧接 ALU/branch/store 正确；x0 特例和“非零寄存器编号但内容为零”正确。非法访问此时必须产生检查结果，随后接入异常通路。

## 5. 建立异常记录和副作用抑制通路

- [x] 在流水寄存器中增加 `exc_valid`、`exc_cause`、`exc_tval`；PC/inst 与记录保持配对。
- [x] 明确气泡为 `valid=0`，故障项为 `valid=1 && exc_valid=1`；故障项继续流向 WB。
- [x] 现有前端 stall 保持 IF/ID，后端故障记录继续推进；kill 清除被取消记录，已有故障不被默认译码覆盖。
- [x] 检测到异常后，老指令继续完成，年轻指令停止发射或被取消。
- [x] **在 EX 当拍禁止故障 store 写 RAM，并阻止年轻 store 越过老异常。**
- [x] 故障指令不正常写 GPR/CSR，不提供前递结果；保留当前普通 BRAM 的读时序。
- [x] WB 增加同步 trap 事件，故障项不产生正常退休事件。

本步实现、信号及注入测试见[异常中断第5步异常记录与副作用抑制说明](异常中断第5步异常记录与副作用抑制说明.md)。

验收：向 ID/EX 注入故障记录，能够到达 WB；老指令完成，故障项及年轻项无正常副作用，流水线不死锁。

## 6. 打通 ECALL、EBREAK、trap 和 MRET 闭环

- [x] 精确译码 ECALL、EBREAK、MRET；ECALL/EBREAK 在 ID 形成故障项。
- [x] WB trap 更新 mepc、mcause、mtval、mstatus，并跳转到 mtvec 的基地址。
- [x] MRET 串行执行，在提交点读取最新 mepc/mstatus，恢复状态并重取指。
- [x] 编写最小纯汇编 handler：保存使用的寄存器、记录原因、按测试目的修改 mepc、恢复后 MRET。
- [x] 初始软件设置有效 sp 和 mtvec，确保入口及栈都在实际存储器范围内。

本步实现、汇编处理程序及闭环测试见[异常中断第6步ECALL与MRET闭环说明](异常中断第6步ECALL与MRET闭环说明.md)。

验收：ECALL 的 cause=11，EBREAK 的 cause=3，mepc 为自身 PC；软件加 4 后准确返回；`csrw mepc; mret` 使用新值；ECALL 后的年轻 store 哨兵不变。

## 7. 接入非法指令和非法 CSR 异常

- [x] 将未实现的指令编码、无效 funct 字段和不支持的指令长度映射为 cause 2。
- [x] 将不存在 CSR、只读 CSR 的写访问等检查结果接入 cause 2。
- [x] mtval 保存故障指令编码；禁止故障指令的 GPR 和 CSR 写入。
- [x] 显式处理 FENCE；本阶段可串行排空实现。WFI 明确译码为合法的串行 NOP。
- [x] 不支持 FENCE.I 时，不宣称支持 Zifencei；不把 FENCE 的保留 rd/rs1 字段当作 GPR 操作。

本步实现、指令样例及测试见[异常中断第7步非法指令与CSR说明](异常中断第7步非法指令与CSR说明.md)。

验收：有效指令字 0 会 trap，气泡不会；非法 CSR 不清零 rd；合法 CSR、FENCE 和选定的 WFI 行为正常。

## 8. 接入数据地址非对齐异常

- [x] EX 检查 LH/LHU/SH 的 addr[0]，LW/SW 的 addr[1:0]；字节访问不报非对齐。
- [x] load 使用 cause 4，store 使用 cause 6；mtval 保存原始有效地址，mepc 保存访存指令 PC。
- [x] 故障 store 在同一拍关闭 wr_en 和字节写使能，不允许部分字节写入。
- [x] 故障 load 不消费为正常结果，不前递，不写回。

本步实现、波形判据及测试见[异常中断第8步数据地址非对齐说明](异常中断第8步数据地址非对齐说明.md)。

验收：所有非对齐半字/字访问都进入 handler；目标字及相邻字的存数哨兵不变；正常对齐访问和字节访问仍通过。

## 9. 接入跳转目标非对齐异常

- [x] ID 等操作数就绪后检查目标；JALR 先清 bit 0，再检查 4 字节对齐。
- [x] 只对 JAL、JALR 和实际采用的条件分支检查目标。
- [x] cause=0，mepc 为跳转指令 PC，mtval 为错误目标；禁止正常跳转及链接寄存器写回。
- [x] 保证 EX 老故障优先于 ID 年轻故障，正确分支取消错误路径上的故障项。

本步实现、程序和测试见[异常中断第9步跳转目标非对齐说明](异常中断第9步跳转目标非对齐说明.md)。

验收：不采用的非对齐分支目标不报错；load→branch/JALR 依赖解除后才判定；错误目标不会写链接值。

## 10. 建立退休事件和架构续执行地址

- [x] 每条指令携带实际后继 PC：普通指令和不采用分支为 PC+4，采用跳转为目标。
- [x] 正常退休时更新 `arch_next_pc`；trap 和 MRET 分别更新为入口与返回目标。
- [x] 分开输出正常退休、trap、MRET 和实际内存请求事件。
- [x] 不用预取 PC 或 debug_wb_rf_we 代替架构续执行地址、完整退休事件。

本步实现与验证见[异常中断第10步退休与续执行地址说明](异常中断第10步退休与续执行地址说明.md)。

验收：顺序执行、采用分支、JAL/JALR 和流水气泡后，排空时的 arch_next_pc 都指向下一条应执行的指令。

## 11. 接入三类机器中断

- [x] CPU 增加同步电平输入 irq_external、irq_software、irq_timer，分别映射 mip 位 11、3、7。
- [x] 每周期计算 pending/enable，使用 mstatus.MIE 和 mie 屏蔽，按 MEI > MSI > MTI 仲裁。
- [x] 候选到达时停止 ID 发射，让已发射指令排空；等待 EX/MEM/WB 和在途事务全空。
- [x] 排空后重新检查 pending 和新 CSR 状态，撤销的中断不再响应。
- [x] 接受时 mepc=arch_next_pc、mtval=0，mcause 的最高位为 1，进入 trap。
- [x] 排空期间若老指令异常，转同步异常通路；保留外部中断源状态。
- [x] CSR/MRET 完成后先重新评估中断，再允许下一条指令发射。
- [x] CPU 接受 trap 不自动清除源；清源由外设或 MMIO 操作完成。

本步实现与验证见[异常中断第11步机器中断说明](异常中断第11步机器中断说明.md)。

验收：关闭使能时 mip 仍可读；三源次序正确；store 位于 EX/MEM/WB 时进入中断均不漏写、不重复写；MRET 后仍 pending 可以再次 trap。

- [x] 跑完整普通指令回归和新增异常/中断回归，记录每项通过结果。

本步模型、边界断言和回归结果见[异常中断第12步差分与边界验收说明](异常中断第12步差分与边界验收说明.md)。第 13 步等待审查后开始。

验收：真实 IP 仿真通过，板级能够稳定进入处理程序并恢复执行；每条 store 的写入次数正确。

## 建议的完成节点

| 节点 | 对应步骤 | 可演示结果 |
|---|---|---|
| CSR 可用 | 1～4 | 六条 CSR 指令正确读改写 |
| trap 闭环 | 5～6 | ECALL 进入处理程序，MRET 返回 |
| 同步异常完整覆盖本阶段范围 | 7～10 | 非法指令、数据及跳转非对齐均准确处理 |
| CPU 中断可用 | 11～12 | 三类测试中断精确响应和恢复 |
| 板级可用 | 13～14 | 真实 IP 下的软件/定时中断演示 |

按用户约定，每完成一个步骤就停下等待审查。**年轻 store 不越过异常**与**中断排空后保存正确 PC**是本次内核改造的两项核心验收条件。

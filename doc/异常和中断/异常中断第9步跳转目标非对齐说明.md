# 异常与中断：第 9 步跳转目标非对齐

本步在 [`mycpu_sync.v`](/D:/riscv/RISCV/myriscv/mycpu_sync.v) 的 ID 级检查**被采用的** branch、JAL 和 JALR 目标。当前 RV32I 不支持 C 扩展，指令目标必须 4 字节对齐。目标不对齐时，故障归属跳转指令：cause 0，`mepc` 为该指令 PC，`mtval` 为错误目标地址。

## 判定与优先级

条件分支先用经前递的 `id_rs1/id_rs2` 判定是否采用；仅采用时检查 `bj_pc[1:0]`。JAL 总是采用；JALR 先计算 `id_rs1 + imm_i`、**清 bit 0**，再检查结果的 bit[1:0]。未采用的分支即使编码出的目标是 `PC+2` 也不报错。

`id_target_misaligned` 要求 `if_id_valid` 且 `!load_use`。load 结果未就绪时，ID 保持，不能用旧寄存器值误判分支条件或 JALR 目标。该信号与已有 ID 异常合成 `id_exc_valid/cause/tval`；故障项带原 PC 和指令字流向 WB，随后更新 trap CSR 并重定向到 `mtvec`。正常 `branch_redirect` 被 `id_exc_valid` 关断，因此不会先跳到非对齐地址。JAL/JALR 故障的链接结果在 EX/MEM/WB 前递和 WB GPR 写口均由异常标志屏蔽。

若较老的 EX 指令当拍发现故障，`fault_inflight` 立即阻止年轻 ID 跳转指令 `id_fire`。即使年轻指令也算出非对齐目标，也先处理老 EX 故障；返回后再重新执行该跳转。正确采用的对齐分支仍通过 `kill_if_id` 丢弃错误路径的取指结果，错误路径上的零编码不会变成非法指令异常。

这一步针对**跳转目标**，异常的 `mepc` 是跳转指令 PC，`mtval` 是目标地址。它不把 PC 自身的对齐检查误当成跳转目标检查。当前正常 PC 来源为对齐的顺序 PC、已检查的跳转目标以及强制 4 字节对齐的 `mtvec/mepc`。

## 验证

[misaligned_jump_step9.S](/D:/riscv/RISCV/difftest/prog/misaligned_jump_step9.S) 和 [`tb_misaligned_jump_step9.v`](/D:/riscv/RISCV/difftest/tb/tb_misaligned_jump_step9.v) 覆盖：

- 未采用分支的目标为 `PC+2`：无 trap。
- 被采用的 BEQ 和 JAL 目标为 `PC+2`：cause 0；JAL 的 `x5` 链接哨兵保持原值。
- 紧接 load 的分支、JALR：先发生 load-use 停顿，使用正确的装载结果后才判断目标；错误 JALR 的 `x9` 保持原值。
- JALR 原地址 bit0 为 1、清除后 4 字节对齐：正常跳转，链接值正确；顺序错误路径上的零编码被取消。
- 老 EX 的非对齐 load 与年轻 ID 的非对齐目标分支同时存在：先记录 load 的 cause 4，返回后再记录分支的 cause 0；另一个正确采用的分支跳过错误路径零编码。

handler 对六次 trap 逐项记录 `mcause/mepc/mtval`，再把 `mepc` 加 4 并 MRET。测试逐项比对异常顺序、PC、目标值、GPR 链接哨兵、前端取消和最终状态。结果：`RESULT: PASS taken target alignment, JALR bit0, load-use and old-fault priority`。

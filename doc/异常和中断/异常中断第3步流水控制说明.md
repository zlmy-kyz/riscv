# 异常与中断：第 3 步流水控制

> GitHub 发布说明（2026-10-10）：下文标为“仅本地”的历史档案/参考材料保留在开发机，未随本次源码发布；原验收结论和哈希不变。当前开发入口见 doc/CODEX_HANDOFF.md。

本步修改 [`mycpu_sync.v`](/D:/riscv/RISCV/myriscv/mycpu_sync.v)，建立异常与中断后续接入所需的控制边界。第 3 步交付时，**CSR、ECALL、EBREAK、MRET 和 FENCE 的实际指令语义尚未接入**；本步仅将它们识别为串行占位项，使其排空旧指令、只发射一次，并暂时禁止其 GPR 写回。第 4 步已接入六条 CSR 指令；第 5 步已接入 WB 同步异常控制重定向；第 6 步已接入 ECALL/EBREAK、trap CSR 更新和 MRET。

## 控制时序

| 信号或状态 | 本步含义 |
|---|---|
| `fetch_valid` | 同步 ROM 的当前响应有效；复位后第一个沿只建立 ROM 地址，第二个沿才允许进入 IF/ID。 |
| `frontend_hold` | PC、ROM 地址和 IF/ID 同时保持；用于 load-use、串行排空和串行执行。 |
| `id_fire` | ID 项实际进入 ID/EX 的一次性事件。等待和停顿时为 0。 |
| `bubble_id_ex` | 没有 ID 发射时清 ID/EX，老 EX/MEM/WB 继续推进。 |
| `kill_if_id` | 分支或未来 trap/MRET 重定向时丢弃旧 ROM 返回；串行项发射后清除已消费的 IF/ID。 |
| `kill_id_ex`、`kill_ex_mem`、`kill_mem_wb` | 为未来 WB 重定向预留的年轻流水级取消信号；EX store 的写使能也受 `kill_ex_mem` 门控。 |
| `FLOW_RUN` | 普通流水执行。 |
| `FLOW_SERIAL_DRAIN` | 当前特殊指令保持在 ID，等待 ID/EX、EX/MEM、MEM/WB 全空。 |
| `FLOW_SERIAL_RUN` | 特殊指令只发射一次并向 WB 前进，年轻指令仍被保持。 |
| `FLOW_IRQ_CHECK` | 串行项完成后的一个控制周期；第 11 步在此重评估待响应中断。 |

### 新增信号逐项说明

以下均为 [`mycpu_sync.v`](/D:/riscv/RISCV/myriscv/mycpu_sync.v) 内部信号，按第 3 步交付时的状态说明；后续步骤的接入状态见本页开头。

| 信号 | 位宽 | 赋值条件与作用 |
|---|---:|---|
| `fetch_valid` | 1 | 复位清 0，之后置 1；为 0 时 IF/ID 不接收 ROM 输出，给同步 ROM 一拍启动时间。 |
| `pc`、`inst_sram_addr`、`next_pc` | 各 32 | `pc` 与当前 ROM 输出配对；`next_pc` 在重定向、保持、顺序加 4 中选择，并同时送到 PC 寄存器和 ROM 地址口。 |
| `frontend_hold` | 1 | `flow_state != FLOW_RUN`、`load_use` 或 `serial_candidate` 时为 1；保持 PC、ROM 地址、IF/ID。重定向覆盖此保持。 |
| `serial_csr`、`serial_system`、`serial_fence` | 各 1 | 在 ID 识别六条 CSR、精确编码的 MRET/ECALL/EBREAK、以及 FENCE 占位项；第 3 步只识别类别，第 4/6 步接入前两类语义。 |
| `serial_candidate` | 1 | `if_id_valid` 且命中特殊类别时为 1；RUN 据此进入排空。 |
| `pipeline_empty` | 1 | ID/EX、EX/MEM、MEM/WB 的 valid 全为 0；确保串行指令不越过老指令。 |
| `serial_issue` | 1 | `FLOW_SERIAL_DRAIN && pipeline_empty && serial_candidate`；只在发射该项的一个周期成立，并清除 IF/ID 中已消费的副本。 |
| `id_fire`、`bubble_id_ex` | 各 1 | 前者表示当前 ID 项本沿进入 ID/EX；后者为 `!id_fire`，使没有发射时 ID/EX 插入气泡。串行排空时老级仍前进。 |
| `id_ex_serial`、`ex_mem_serial`、`mem_wb_serial` | 各 1 | 串行标记随流水项逐级传递；复位、气泡或取消时清零，用于确认到达 WB 的是同一串行项。 |
| `serial_done` | 1 | 在 `FLOW_SERIAL_RUN` 中观察到 `mem_wb_valid && mem_wb_serial`，进入 `FLOW_IRQ_CHECK`；第 3 步时不执行真实 CSR/MRET 提交，第 4 步已接入 CSR。 |
| `branch_redirect` | 1 | `FLOW_RUN` 中有效的分支/JAL/JALR 真正 `id_fire` 且采用跳转时成立；load-use 停顿时不能误跳。 |
| `trap_redirect_req`、`mret_redirect_req` | 各 1 | 第 3 步时均硬连 0，专项测试用 `force` 验证控制路径；第 5 步将前者接到 WB 同步异常事件，第 6 步将后者接到 MRET 提交事件。 |
| `trap_redirect_target`、`mret_redirect_target` | 各 32 | 第 3 步时硬连 0；第 4 步已分别接到 `csr_file.trap_target/mret_target`。重定向请求仍接 0。 |
| `redirect_valid`、`redirect_pc` | 1/32 | 统一重定向选择，优先级 trap > MRET > 普通分支；优先于 `frontend_hold`。 |
| `kill_if_id` | 1 | 发生重定向或 `serial_issue` 时清 IF/ID；前者丢弃旧 ROM 返回，后者防止串行项重复发射。 |
| `kill_id_ex`、`kill_ex_mem`、`kill_mem_wb` | 各 1 | 由 trap/MRET 请求产生，清除对应新流水寄存器内容；`kill_ex_mem` 同拍还关闭 EX store 写使能。当前正常运行时为 0。 |
| `flow_state` | 2 | 依次在 RUN、SERIAL_DRAIN、SERIAL_RUN、IRQ_CHECK 之间转移；复位或 trap 重定向回 RUN。 |

`load_use`、`if_id_valid`、`id_ex_valid`、`ex_mem_valid`、`mem_wb_valid` 是原有信号；第 3 步用它们构造保持和排空条件。`valid=1` 只表示流水寄存器含一项，不能代替 `id_fire` 或正常退休事件。第 3 步专项测试中的强制重定向只验证控制路径；第 5 步加入 WB 异常重定向，第 6 步加入 trap CSR 更新。

取指地址和 `pc` 由同一个 `next_pc` 选择，优先级为重定向 > 保持 > 顺序加 4。当前 ROM 在时钟沿锁存新地址，沿后数据立即与新 `pc` 配对；重定向沿清 IF/ID，丢弃旧返回，下一沿接收目标指令。后续接入真实 IP 时仍需按第 13 步复测其复位和输出延迟。

复位直接清各级 valid 和控制状态；RAM store 使能、GPR 写使能受 `resetn` 门控。现有 RAM 的地址/写数据仍在 EX 组合送入 IP，未改动访存时序。

## 验证

- 普通差分程序 `prog0_alu`、`prog1_mem`、`prog2_hazard_precision` 均通过指令流、写回轨迹以及 RF/RAM 终值比对。
- 独立 `tb_hazard_precision` 通过。
- 新增 `tb_pipeline_control.v`（仅本地：`/D:/riscv/RISCV/difftest/tb/tb_pipeline_control.v`）：旧 store 先于串行项完成；串行项只发射和到达 WB 一次；多拍前端保持不会重复发射；年轻 ALU/store 不丢且错误路径 store 不写；测试替身 trap/MRET 重定向后目标第一条可执行；load-use 保持与 trap 重定向同拍时重定向胜出；复位期间无 RAM/GPR 写入。结果为 `RESULT: PASS pipeline serial drain, one-shot issue, redirect refill and stores`。

第 3 步测试中通过 `force` 驱动的 trap/MRET 请求只验证控制硬件接口。CSR 写回在第 4 步实现，故障项传播在第 5 步实现，真实 trap/MRET 提交在第 6 步实现；中断仲裁仍待后续步骤。

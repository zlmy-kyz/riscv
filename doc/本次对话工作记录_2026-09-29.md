# 本次对话工作记录：PDS、片内 IP 与 DDR3 联仿

记录日期：2026-09-29。本文按对话脉络汇总已讨论和已留证的工作；测试结论取自对应工程文件、步骤文档和日志，**编写本文时没有重新运行仿真**。工程的持续交接状态以 [CODEX_HANDOFF.md](./CODEX_HANDOFF.md) 为准。

## 目的

让 PDS 的 **Run Behavior Simulation** 按钮启动 ModelSim，在同一次仿真中运行 CPU、指令/数据总线、**PDS 生成的真实片内 `inst_rom`/`data_ram` IP**、DDR 桥、Pango DDR3 IP 和 DDR3 物理模型；随后确认 RV32I 程序执行、复位和指令/数据争用。对话也约定每完成一个独立开发或验证步骤，就在 `doc/` 写目的、改动、复现方式、实测效果和未覆盖范围。

## 对话推进过程

1. **恢复工程状态。**先核对 `AGENTS.md`、`doc/CODEX_HANDOFF.md`、日期快照、当前 RTL/PDS 设置及 Git 工作树，区分历史 PASS、当前配置和未验证事项。工作树包含大量未提交及未跟踪文件，未把 IP、镜像或日志当作可清理产物。
2. **建立 PDS 按钮联仿入口。**讨论了仿真文件的移除与重新添加、`ddr3_mem` 模型节点的感叹号，以及为什么仿真替身 `tb_soc_ddr3_mem.v` 不满足“真正片内 IP”的目标。最终使用 `source/tb_soc_ddr3_pds_ip.v`、`sim/pds_ddr_ip_compile.tcl`、`sim/pds_ddr_ip_run.tcl` 编译和运行生成的 `inst_rom`/`data_ram`，并接入 DDR3 IP/物理模型。PDS 生成的 `sim/behav/run_behav.bat` 调用这两份 Tcl；ModelSim 实际测试顶层由运行 Tcl 选择为 `tb_soc_ddr3_pds_ip`。
3. **明确镜像和运行时间。**`inst_rom` 使用 `MyCpu_test/ddr_stage/boot_rom.dat` 作为启动程序；`data_ram` 使用当前被测程序的 `<test>.dat` 作为 CPU 向 DDR 搬运的代码和数据来源。每次切换 RAM 镜像，需要在 PDS 重新生成 `data_ram` IP，并同步修改测试名、`TOHOST`、预期复制字数和日志名。对话解释了 `ModelSim.simulate.runtime` 与 `timescale` 的作用；临时把 TB 精度改为 `1ns/1ps` 的测试未观察到提速，随后恢复为 `1ns/10fs`。这些设置不替代程序完成条件，也不保证墙钟时间缩短。
4. **完成三个真实片内 IP 的按钮测试。**`add`、`lb`、`ld_st` 均经 PDS 按钮调用 ModelSim，在 CPU 从片内 RAM 复制镜像到 DDR、跳转 DDR 取指后写出 `tohost=1`。各项独立日志均有 `RESULT: PASS`、无 `RESULT: FAIL`、末尾 `Errors: 0`；具体参数和证据见下表。
5. **补充复位与争用验证。**复位用例在装载过程中施加外部复位，观察 DDR 再训练和 CPU 重新复制 `ld_st` 镜像。TB 注入用例在已译码的 SoC DDR 请求入口同时提出指令/数据读，验证数据优先及两路读回。随后用 CPU 发出的真实请求验证争用：快速用户口模型运行五个程序；完整 DDR3 物理模型在 TB 延后一次取指 ready 两拍后观察到 CPU 指令/数据请求重叠，并使 `ld_st` 完成。
6. **整理文档。**本次对话后段更新了交接文档、PDS 一键联仿总文档及 `lb`/`ld_st` 步骤文档，纠正了过时的 PDS 顶层、镜像和“仅有 add PASS”的描述。本文是对话索引，不替代各步骤的详细记录。

## 碰到的问题及解决

| 现象或疑问 | 查明的原因或判断 | 处理和结果 |
| --- | --- | --- |
| 在 PDS 中重新添加仿真文件后，层次树显示 `u_inst_rom`、`u_data_ram` 来自 `tb_soc_ddr3_mem.v`，而不是期望的真实片内 IP。 | `tb_soc_ddr3_mem.v` 是前一阶段用于独立 DDR 联仿的**仿真存储替身**；仅看到模块实例名 `inst_rom`/`data_ram`，不能证明编译的是 PDS 生成 IP。 | 建立 `tb_soc_ddr3_pds_ip.v` 和专用编译 Tcl，明确编译 `ipcore/inst_rom/inst_rom.v`、`ipcore/data_ram/data_ram.v` 及其生成的 RTL；在独立 ModelSim 日志中核对加载的模块和三个用例的 PASS。详见[一键联仿记录](./PDS真实片内ROM_RAM与DDR3一键仿真.md)。 |
| PDS 层次树中 `mem_core - ddr3_mem` 出现黄色感叹号，担心 DDR3 物理模型缺失。 | 层次树警示表示该视图没有正确解析该仿真模块；**单凭图标不能确定是 DDR3 IP 故障，也不能证明物理模型已经参与仿真**。旧图标的唯一根因没有单独留证。 | 专用编译 Tcl 使用厂家 `sim_file_list.f` 并编译 DDR3 物理模型；最终 ModelSim 日志明确加载 `ddr3_mem`，测试 PASS、`Errors: 0`。以编译/运行日志判断实际联仿内容。 |
| DDR3 厂家仿真文件编译容易受工作目录影响。 | `ipcore/ddr3/sim/modelsim/sim_file_list.f` 含相对路径；从其它目录直接使用会找不到对应文件。 | 两份 PDS 专用 Tcl 先切到厂家 `sim/modelsim` 目录；独立命令也从该目录启动。厂家文件和 CPU/IP/TB 编译均在留存日志中达到 `Errors: 0`。 |
| 更换 `lb.dat`、`ld_st.dat` 后，担心仍在运行旧程序，或把旧的固定 `add` PASS 当成新结果。 | 片内 `data_ram` 的初始化内容属于**生成的 IP 配置**；只改脚本中的 `TEST` 或换文件名，不会自动更新已生成的 IP。旧 `tb_soc_top` 还有固定 `add` 标签。 | 每项在 PDS 重新生成 `data_ram`，同时改 `+TEST`、`+TOHOST`、`+EXPECTED_WRITES` 和独立日志名；核对 `INIT_FILE`、复制字数、`tohost=1`、`RESULT: PASS` 及 `Errors: 0`。`inst_rom` 保持 `boot_rom.dat`。详见 [lb](./PDS真实片内IP_lb测试准备_2026-09-29.md) 与 [ld_st](./PDS真实片内IP_ld_st测试准备_2026-09-29.md) 记录。 |
| `ModelSim.simulate.runtime=50000ns` 看起来要填写，完整 DDR3 仿真又运行很久；曾尝试修改 `` `timescale 1ns / 10fs ``。 | `runtime` 是仿真时间设置；自定义 Tcl 的 `run 5ms` 是最长仿真时长。DDR 初始化与物理模型事件计算决定较长的墙钟时间，改变时间单位本身不会让 CPU 更快完成。 | TB 精度临时改成 `1ns/1ps` 后 `add` 仍 PASS，但那次墙钟时间为 16 分 20 秒，未观察到提速；恢复为 `1ns/10fs`。两轮不是受控性能基准，不能据此断言精度改动造成减速。 |
| 外部复位联仿最初在 TB 检查处停止，另一次在复位后超时。 | 第一处检查要求只在 DDR 核心时钟边沿更新的标志在停钟期间立即清零；第二次对 `reg` 用 `force/release`，释放后没有后续过程赋值，`resetn` 一直保持低电平。 | 修正 TB 检查，并以层级过程赋值明确拉低、拉高 `resetn`；最终日志记录 DDR 再训练、CPU 重新复制 1056 字、`ld_st` PASS、`Errors: 0`。这些早期失败属于 TB 问题，不是 RTL 故障结论。详见[复位记录](./DDR3复位与指令数据争用验证_2026-09-29.md)。 |
| 自然物理时序下 `ld_st` 通过，但未看到指令/数据 DDR 请求同周期重叠。 | 该次自然运行统计重叠数为 0；TB 在 DDR 入口注入两路读能验证桥的仲裁，却不能证明请求来自 CPU。 | 先在快速模型观察五个程序的 CPU 原生重叠；再在真实片内 IP＋DDR3 物理模型中延后一次取指 ready 两拍，使 CPU 发出的两路请求相遇，确认数据优先且程序 PASS。此结果只适用于指定反压场景。详见 [CPU 原生争用记录](./CPU原生DDR指令数据争用验证_2026-09-29.md)。 |
| PDS 树节点、生成的批处理和实际 ModelSim 顶层名称不一致，容易误判按钮运行内容。 | 当前 `RISCV.pds` 设计树选择 `soc_ddr3_top`，仿真树列 `tb_soc_ddr3_top`；PDS 按钮生成的 `run_behav.bat` 调用自定义 Tcl，而运行 Tcl 指定 `tb_soc_ddr3_pds_ip`。 | 以 `run_behav.bat`、`sim/pds_ddr_ip_run.tcl` 和独立日志共同确认实际顶层、镜像和测试名；已在交接及一键联仿文档中记录这一差别。 |

复现 PDS 专用联仿时，先在 PDS 核对并重新生成目标 `data_ram` IP，再点击 **Run Behavior Simulation**。命令行也可从 `D:/riscv/RISCV/ipcore/ddr3/sim/modelsim` 目录执行：

```powershell
& 'D:\modelsim\win64pe\vsim.exe' -c -do 'do D:/riscv/RISCV/sim/pds_ddr_ip_compile.tcl; quit -f'
& 'D:\modelsim\win64pe\vsim.exe' -c -do 'do D:/riscv/RISCV/sim/pds_ddr_ip_run.tcl; quit -f'
```

当前 `inst_rom` 的初始化文件为 `boot_rom.dat`，`data_ram` 为 `ld_st.dat`；运行 Tcl 为 `+TEST=ld_st +TOHOST=80002000 +EXPECTED_WRITES=1056`，独立日志名为 `sim/pds_ddr_ip_ld_st.log`。`RISCV.pds` 的设计树选中 `soc_ddr3_top`，仿真树列出 `tb_soc_ddr3_top`，但上述自定义 Tcl 实际启动 `tb_soc_ddr3_pds_ip`。再次操作前仍须重新核对工程文件、生成脚本和日志。

## 尚未完成与下一步

- 真实片内 IP＋完整 DDR3 物理模型目前仅对 `add`、`lb`、`ld_st` 三个 RV32I 程序留有逐项 PASS；不能写成 42 项物理模型回归。片内路径“无退化”由用户确认，但这里没有片内 42 项的新逐项日志。
- 自然物理时序的 `ld_st` 没有出现两路 DDR 请求同周期重叠；CPU 原生争用 PASS 是**延后取指 ready 两拍的指定反压场景**。未验证持续数据请求下的指令公平性。
- 还没有综合、布局布线、时序或实板 PASS。下一步先核对板上 DDR3 器件、参考时钟、复位、引脚约束、程序装载来源和可见结果输出；再做最小 DDR 写入/读回自检，并在新的步骤文档中记录实际板上结果。

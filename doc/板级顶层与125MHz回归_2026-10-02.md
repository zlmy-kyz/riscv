# 板级顶层、引脚边界与 125 MHz 回归

任务日期：2026-10-02；测试实际开始/结束时间以各日志为准，长测试可能跨午夜。目的：将开发板物理 IO 与 SoC 内部观测信号分开，并使 PDS 编译真实选择 `board_top`。本次没有回退原工作树修改，也没有重生成或手改 DDR IP 参数。

## 板级顶层

```text
board_top
  R4/T4 差分输入 → GTP_INBUFDS → 内部 ddr_ref_clk
  └── u_soc : soc_ddr3_top
        ├── u_ddr3 : ddr3（ref_clk → PHY/PLL → core_clk）
        ├── u_leds : soc_ddr3_leds
        └── u_soc : soc_top
              └── u_cpu : mycpu_sync
```

`soc_ddr3_top` 继续承担 SoC、DDR IP、复位释放及 LED/MMIO 自检状态逻辑，原仿真接口保持兼容。`board_top` 只处理板级时钟缓冲、物理端口和无来源中断的常量连接。CPU、互连、桥、MMIO 功能逻辑未修改。

`core_clk/ddr_init_done/soc_resetn` 在板级内部接成一位 wire；`debug_wb_pc/debug_inst/debug_wb_rf_wdata` 为 32 位，`debug_wb_rf_we` 为 4 位，`debug_wb_rf_wnum` 为 5 位。它们继续来自原 SoC 输出，不再是外部 FPGA 端口。PDS 可能优化未使用的观测线，但没有删除原 RTL debug 功能。

`irq_external/irq_software/irq_timer` 各接 `1'b0`，因为尚无真实板级外设来源。以后接 PLIC、CLINT、UART、GPIO 等时再增加内部来源。`ddr_ref_clk` 本身也不是 FPGA 外部端口。

KEY0 球位 M15，未按为高、按下为低，与 `resetn` 极性一致，所以直接接入现有低有效复位链；不需要再反相。SoC 内已有 `core_clk` 域两拍释放，并要求 DDR 初始化及 PLL 锁定；DDR IP 保留自身复位处理。这里没有新增按键去抖，按键抖动可能导致再次复位，应在实物观察。

## 最终端口与 Pin Planner 边界

| 方向 | 端口 | 位宽 / 球位 |
| --- | --- | --- |
| input | `ddr_ref_clk_p`, `ddr_ref_clk_n`, `resetn` | 各 1 位，R4 / T4 / M15 |
| output | `led_clk_alive`, `led_ddr_ready`, `led_selftest` | 各 1 位，J16 / M17 / K17 |
| output | `mem_cs_n`, `mem_rst_n`, `mem_ck`, `mem_ck_n`, `mem_cke`, `mem_ras_n`, `mem_cas_n`, `mem_we_n`, `mem_odt` | 各 1 位 |
| output | `mem_a`, `mem_ba`, `mem_dm` | 15 / 3 / 2 位 |
| inout | `mem_dq`, `mem_dqs`, `mem_dqs_n` | 16 / 2 / 2 位 |

共 21 组端口、55 位物理 IO（DDR 49 位，其他 6 位）。新 `constraints/rk3568_board.fdc` 逐位给出全部 55 个球位，无缺项、无重复球位，也无 debug、IRQ 或内部时钟球位。完整明细可直接看该 FDC 或 `sim/board_top_validation/pin_audit.txt`。以当前 `board_top` 编译结果打开 Pin Planner 时，只应有这些端口；本次没有运行 GUI Pin Planner，结论依据 RTL 端口表、自动逐位审计及实际 PDS 顶层展开。

球位再次与板商[《RK3568_MES2L50H/MES2L100H 硬件使用手册 v1.1》](https://szlogicmatrix.com/wp-content/uploads/2025/12/RK3568_MES2L50H_100H_%E7%A1%AC%E4%BB%B6%E4%BD%BF%E7%94%A8%E6%89%8B%E5%86%8C_v1.1.pdf)核对：PDF 第 9 页时钟、第 12 页 DDR、第 17 页 KEY0、第 18–19 页 LED；该手册明确 DDR 地址 A15/Y3 预留，有效 A[14:0]，因此不新增 A15 顶层端口。已核对现有 `fdc/soc_ddr3.fdc` 的 DDR Location 与手册一致，但其电气属性不能直接使用。

三个 LED 仍为高电平点亮：J16 心跳 1 Hz；M17 在 DDR 就绪且 SoC 释放复位后常亮；K17 未开始灭、RUN 1 Hz 慢闪、PASS 常亮、FAIL/timeout 4 Hz 快闪，锁存规则保持原实现。心跳不能证明 DDR 数据正确。

## 差分参考时钟及当前 IP 配置

连接为 `R4 → ddr_ref_clk_p → GTP_INBUFDS.I`、`T4 → ddr_ref_clk_n → GTP_INBUFDS.IB`，`.O → board_top.ddr_ref_clk → u_soc.ddr_ref_clk → u_soc.u_ddr3.ref_clk`。

实例化依据工程已生成的 `ipcore/ddr3/example_design/rtl/test_ddr.v`，使用端口 `.O/.I/.IB`，不臆造参数。本机厂家 primitive `arch/vendor/pango/verilog/simulation/GTP_INBUFDS.v` 的参数名称是 `IOSTANDARD`、`TERM_DIFF`，默认分别为 `DEFAULT`、`ON`；这里与厂家例程一致，未覆写。默认值不是已经确认了振荡器电气标准/终端配置，上板前仍须核对。

| 项目 | 当前可核对值 |
| --- | --- |
| `ddr3.idf CLKIN_FREQ` | **125.000 MHz** |
| 生成 `ddr3_ddrphy_top.v CLKIN_FREQ` | **125.0 MHz** |
| 厂家 TB / 示例 FDC | 125 MHz / 8 ns |
| `DESIRED_DDR3_RATE` | 800 Mbps |
| `ACTUAL_RATE` | **750 Mbps** |
| PHY PLL | `PPLL_IDIV=1`, `PPLL_FDIV=12`, `PPLL_ODIVPHY=2`，DDR CK 375 MHz |
| 用户时钟 `core_clk` | **93.75 MHz = 750/8**；生成时钟比为 12/16 |

板卡手册正文的 125 MHz 与当前 IP 参考频率匹配。旧 100 MHz 记录描述的是此前生成版本，不能代表此次检查到的 IP。信号名 `GCLK_DDR_133_*` 不应代替手册正文/实物频率。实物修订版本仍应确认振荡器标号/输出标准。

本次没有修改 `ddr3.idf` 或生成 PHY 参数。`board_top` 把 `CORE_CLK_HZ=93_750_000`、`SELFTEST_TIMEOUT_CYCLES=468_750_000` 传给 SoC，保持实际心跳/慢闪/快闪和 5 秒超时含义；`soc_ddr3_top` 的参数默认 100 MHz 保留兼容旧仿真调用。两份共享物理模型 TB 原来仍输入 100 MHz，本次改为 `always #4`，与当前 IP 一致。

旧 `fdc/soc_ddr3.fdc` 和 `constraints/rk3568_leds.fdc` 都保留；前者从 PDS 导入列表撤下，后者不重复导入。旧 FDC 将 DDR 定义为 1.2 V / HSUL12、差分 HSUL12D；厂家 DDR3 示例则为 1.5 V / SSTL15_I、SSTL15D_I。两者不能因为文件存在就认为适配了实板。

| IO 类别 | 已有依据 | 本次采用 / 仍需确认 |

当前 IP `pnr/ddr_test.fdc` 是 Example Design 文件，`RISCV.pds` 没有自动导入它；本次也没有原样导入。其 `I_ips_ddr_top...` 层次与板级 `u_soc.u_ddr3...` 不同，且示例 DQ、CK 等球位与板卡不同。**当前 IP 的 PAD_* 字段也残留不同位置**，例如 `PAD_DQ0=C2`（板卡 P6）、`PAD_CK=R3`（板卡 Y4）、`PAD_RESET=W6`（板卡 T3）。完整比对在 `pin_audit.txt`；IP 还含未使用组的字段，最终须在 IP 配置界面核对实际选用组与生成 PHY 资源，不能只改 FDC 就假定其布局正确。

因此没有复制厂家不匹配的 DQS/clock/CPD/IOCLK 特殊 placement，也没有把不存在的 `free_clk/ref_clk_p` 时钟约束套到新顶层。后续需按板卡重配 PAD/byte lane 与实际 PHY 资源、生成约束并适配 `u_soc.u_ddr3` 层次；检验 generated clocks、例外与特殊 placement 是否确实命中。新 FDC 当前只是完整 Location 加已确认的主时钟，并非完整电气/时序签核文件。

3. 将真实片内 RAM 改成带 MMIO RUN/PASS/FAIL 的上板自检源，并统一启动代码、DDR_BASE/链接地址/tohost；当前板级默认 DDR 是 0x40000000，而测试镜像使用 0x80000000，主 RAM 留在旧 ld_st。先用配置比特流内初始化 ROM/RAM 可完成自检，不必等待 UART/Flash 装载器，但须明确实际初始化的镜像。
4. 完成 board_top 的新综合、映射、布局布线、完整时序与约束命中检查，得到可下载配置并实测 KEY0、DDR 初始化和三灯结果。此次仅有 PDS Compile/仿真证据，没有新实现/上板 PASS。

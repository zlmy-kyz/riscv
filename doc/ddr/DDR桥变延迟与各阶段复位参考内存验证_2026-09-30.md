# DDR 桥变延迟与各阶段复位参考内存验证

日期：2026-09-30。

## 目的

在上板前检查 `dual_sram_to_pango_ddr_bridge` 遇到不同长度的读地址、读数据、写地址和写数据等待时，命令、数据、字节掩码及 CPU 响应是否正确；在读写事务各阶段复位后，确认旧请求/响应被取消，已接受的写数据仍留在外部存储器中。

## 改动与检查方法

- 新增独立测试平台 `source/tb_ddr_bridge_wait_reset_scoreboard.v`。本步没有修改 CPU、互连、DDR 桥 RTL、PDS 工程或已有共用 TB。
- 使用两份独立的 1024 字节数组：参考内存只按 CPU 请求中的地址、32 位数据和 4 位字节掩码更新；设备侧内存只按桥输出的 128 位写数据和 16 位掩码更新。每次写接受后逐字节比较两份内存；每次读由设备侧内存产生 128 位返回拍，再以参考内存的目标 32 位字核对 CPU 响应。所有 AR/AW 命令逐笔检查控制器地址、ID、长度和 `axi_wdata`/`axi_wstrb`。
- 对四个等待位置分别覆盖 0～7 个周期；检查等待中命令与写数据保持、请求不被再次接受、响应不提前出现。另覆盖 AR/RVALID 同拍和 AW/WREADY 同拍、四个 32 位槽及局部字节写。
- 用固定种子产生 128 笔附加读写，包含全字、部分和零写掩码。复位分别插在 `RADDR`、`RDATA`、读响应待交付、`WADDR`、`WDATA`、写响应待交付六个阶段。复位期间 `ddr_init_done=0`，检查无旧命令/响应、初始化前拒绝请求，恢复后再次读取同一份内存。写数据已由 WREADY 接受但 CPU 尚未收到响应时复位，参考内存保留该次写入，并在恢复后读回。
- Pango 用户口按项目实际的 AXI-like 单拍接口建模：写侧无 WVALID/B 通道，读侧无 RREADY。此测试没有把它当作标准 AXI4。

## 复现命令

从仓库根目录使用 Icarus Verilog：

```powershell
& 'D:\iverilog\bin\iverilog.exe' -g2012 -s tb_ddr_bridge_wait_reset_scoreboard -o 'sim/ddr_bridge_wait_reset_scoreboard.vvp' 'myriscv/dual_sram_to_pango_ddr_bridge.v' 'source/tb_ddr_bridge_wait_reset_scoreboard.v'
$seeds = @(1, 17, 2026, 65535, 2147483647)
$lines = foreach ($testSeed in $seeds) {
  $runOutput = & 'D:\iverilog\bin\vvp.exe' 'sim/ddr_bridge_wait_reset_scoreboard.vvp' "+SEED=$testSeed" 2>&1
  if ($LASTEXITCODE -ne 0) { throw "Seed $testSeed failed: $runOutput" }
  $runOutput
}
$lines | Set-Content -LiteralPath 'sim/ddr_bridge_wait_reset_scoreboard.log' -Encoding utf8
$lines | Select-String 'RESULT:'
```

独立旧测试的复现方法：分别用 `-s tb_dual_sram_to_pango_ddr_bridge` 和 `-s tb_ddr_bridge_reset_contention` 编译对应 `source/tb_*.v` 与同一 DDR 桥 RTL，再用 `vvp` 运行。

## 本轮实测结果

- 新 TB 编译退出码 0。`sim/ddr_bridge_wait_reset_scoreboard.log` 中，5 个种子各有一条 `RESULT: PASS`，无 `RESULT: FAIL`。每个种子完成 **165 笔**事务（56 写、109 读）和 **6 个阶段复位**；每次复位均记录 `CHECK`。各进程退出码均为 0。
- 原有 `tb_dual_sram_to_pango_ddr_bridge` 本轮重新编译并运行，输出 `RESULT: PASS dual_sram_to_pango_ddr_bridge`，进程退出码 0。
- 原有 `tb_ddr_bridge_reset_contention` 本轮重新编译并运行，输出 `RESULT: PASS bridge reset cancellation and data-priority contention`，进程退出码 0。

## 未覆盖范围

本步骤使用桥级 Pango 用户口行为模型，未编译 DDR3 IP、PHY 或 x16 物理模型；既有真实物理模型 `add`、`lb`、`ld_st`、复位和争用结果见 `doc/CODEX_HANDOFF.md`。这里的 1024 字节数组也不代表完整 512 MiB 容量；窗口末端的地址转换已有旧桥测试覆盖。复位后的外部 DDR 内存保留是模型约定，不验证 DDR3 控制器复位时实物内存内容是否可保留。当前桥为单笔、数据端优先，持续数据请求下的指令公平性及 DDR 用户端故障响应仍未覆盖。本步没有修改共享 RTL/TB，因此未重跑两条完整 DDR3 物理模型定向脚本。

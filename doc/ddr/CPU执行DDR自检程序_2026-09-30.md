# CPU 执行 DDR 自检程序

日期：2026-09-30。

2026-10-02 增量：新增 MMIO RUN/PASS/FAIL 上报及三路 LED，当前自检程序为 **245 字**，装载字数从 manifest 读取。下文 237 字与 68679 周期是 2026-09-30 历史结果；本轮实现、复现与新日志结果见 [LED 状态指示与 MMIO 自检上报](../board/LED状态指示与MMIO自检上报_2026-10-02.md)。主 PDS RAM 镜像仍为 `ld_st`。

## 目的

在无法上板的阶段，用与上板后可复用的 RV32I 程序验证 CPU 从片内启动、复制代码到 DDR、从 DDR 取指，以及通过数据总线写读 DDR。失败时在固定诊断区留下第一个错误地址、期望值、实测值和测试阶段。

## 实现和地址约定

- `MyCpu_test/build_ddr_selftest.py` 生成 237 字的 RV32I 程序、4096 字的片内 RAM 装载镜像，以及与既有装载器相同的 `boot_rom.dat`。没有交叉编译器依赖，也不使用 M 扩展或 `FENCE.I`；代码在 `0x80000000` 执行，片内 ROM 启动程序从片内 RAM 复制代码到 DDR。
- DDR `0x80002000` 起 64 个字进行三组种子之一的 xorshift32 花样写入和逐字验证，`0x80002100` 起 32 个字做 walking-one，`0x80002200` 起覆盖 128 位拍的四个 32 位槽、相邻拍、`SB/SH/SW` 与 `LB/LBU/LH/LHU/LW` 的符号和字节掩码行为。成功路径执行 112 次比较。
- `0x80001000` 是 `tohost`：1 为 PASS，2 为 FAIL；`+0x4` 错误地址、`+0x8` 期望值、`+0xC` 实测值、`+0x10` 测试阶段、`+0x14` 完成比较次数、`+0x18` 成功标记。失败字段均在写 `tohost=2` 之前写入。
- `source/tb_ddr_selftest_fast.v` 只监视诊断字段，复用现有快速 SoC TB 的装载字数、DDR 取指、`tohost` 和超时判据。`MyCpu_test/run_ddr_selftest_fast.py` 检查三组正常镜像和一份故意改错期望值的镜像，后者必须明确 FAIL，并核对诊断字段。
- 为完整联仿，`MyCpu_test/build_ddr_selftest_ip.py` 使用 Pango `ip_generate.exe` 在 `MyCpu_test/ddr_selftest/ipcore/data_ram` 生成**独立的真实片内 RAM IP**，初始化为自检镜像；真实 `inst_rom` 仍取自工程的生成 IP。`sim/pds_ddr_selftest_compile.tcl` 和 `sim/pds_ddr_selftest_run.tcl` 使用独立 ModelSim 库和日志。当前 PDS 工程的 `ipcore/data_ram` 仍指向 `ld_st.dat`，PDS 按钮入口未切换。

## 复现命令

仓库根目录运行快速模型和故障路径：

```powershell
python MyCpu_test/run_ddr_selftest_fast.py
```

生成隔离的 Pango 片内 RAM IP：

```powershell
python MyCpu_test/build_ddr_selftest_ip.py
```

完整真实片内 IP＋DDR3 IP＋x16 物理模型联仿，从 `D:/riscv/RISCV/ipcore/ddr3/sim/modelsim` 执行：

```powershell
& 'D:\modelsim\win64pe\vsim.exe' -c -do 'do D:/riscv/RISCV/sim/pds_ddr_selftest_compile.tcl; do D:/riscv/RISCV/sim/pds_ddr_selftest_run.tcl; quit -f'
```

## 本轮实测

快速用户口模型三组正常镜像均 PASS，均复制 237 字后从 DDR 取指，并写入 `tohost=1`、比较次数 112。三组种子分别为 `0x13579bdf`、`0x2468ace1`、`0xa5c3f00d`。故意改错期望值的镜像按预期写 `tohost=2`：地址 `0x80002200`、期望 `0x11223345`、实测 `0x11223344`、阶段 5、此前完成 96 次比较。四项由 `run_ddr_selftest_fast.py` 判为 **4/4 符合预期**；原始日志在 `MyCpu_test/ddr_selftest/fast_*.log`。

Pango 隔离 IP 生成进程退出码 0；新 `data_ram.v` 的 `INIT_FILE` 指向 `ddr_selftest.dat`，原工程 `ipcore/data_ram/data_ram.v` 仍指向 `ld_st.dat`。

完整 DDR3 IP＋x16 物理模型于 2026-09-30 01:09:03 结束，ModelSim 墙钟耗时 17 分 06 秒。独立日志 `sim/pds_ddr_selftest.log` 明确加载 `pds_ddr_selftest_work.inst_rom`、`pds_ddr_selftest_work.data_ram` 和 `pds_ddr_selftest_work.ddr3_mem`，随后输出：

```text
CHECK: ddr_selftest CPU copied 237 words then fetched from DDR
RESULT: PASS ddr_selftest DDR RV32I tohost=1 cycles=68679
Errors: 0, Warnings: 353
```

日志中恰好一条 `RESULT: PASS`、没有 `RESULT: FAIL`，末尾一条 `Errors: 0`。这一轮只运行默认种子的正常镜像；另外两组种子和故意失败镜像只在快速用户口模型运行。

## 未覆盖范围

目前诊断记录位于 DDR；实板要观察它仍需板级调试/通信通道。测试区域约 0.5 KiB，不能证明 512 MiB 全容量或长时间保持性；xorshift 是确定性花样，不是完整随机压力。快速模型不含 DDR3 控制器、PHY、物理时序。自检没有实现板上程序装载源、DDR 器件/时钟/引脚约束、综合时序或实板运行。本步没有修改 CPU、互连、桥、DDR 顶层或共用 TB；原第 1/2 步完整物理模型脚本无需因本步改动重新运行。

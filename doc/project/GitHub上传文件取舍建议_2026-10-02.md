## 3. 这些文件应当保留

### 3.1 源码、工程与约束

- `myriscv/` 中的 CPU、CSR、SoC、互连、适配器、MMIO 和 DDR 桥 RTL。
- `source/` 中的测试台。
- `RISCV.pds`：当前 PDS 工程入口，不能和 `.lock` 一起排除。
- `constraints/`：包括 `rk3568_leds.fdc`。该文件当前只是约束片段，保留它不代表已完成板级验证。
- `AGENTS.md`、`doc/CODEX_HANDOFF.md`、设计/验证记录及其配图，例如 `doc/assets/mermaid-diagram.png`。

### 3.2 Pango IP 的配置和源文件

目前应保留 `ipcore/inst_rom/`、`ipcore/data_ram/`、`ipcore/ddr3/` 中的有效配置与源文件，尤其是：

- `.idf`、IP 顶层 `.v`、`rtl/` 中的 `.v`/`.vp`/`.vh`。
- ROM/RAM 的 `*_init_param.v`、`*_Reset_Value.v` 等初始化实现。
- DDR 的 `sim_lib/`、`example_design/`、`sim/modelsim/sim_file_list.f` 和各 Tcl 脚本。
- DDR 的 `pnr/` 中工程/约束参考文件。这里不能套用“所有 pnr 都是布局布线输出”的判断；例如现存 `ddr_test.fdc` 是参考约束，并不等于当前板卡可直接使用的约束。

依据：`RISCV.pds` 直接列出多项 IP 源文件；`sim_file_list.f` 明确引用 `sim_lib/` 和 `example_design/`。这些文件虽然由工具生成或来自厂家，仍是当前构建/仿真的输入。公开分享时保留原文件的来源及许可说明；本次未审核第三方文件的再分发许可。

### 3.3 测试程序与镜像

- `MyCpu_test/dat/`：RV32I ROM/RAM 测试镜像，不能统一忽略 `*.dat`。
- `MyCpu_test/dump/`：**建议保留**。`build_ddr_stage.py` 从这里读取符号与数据段信息；`extract_inst.py`、`extract_data.py` 也读取 dump。它是现有脚本的输入。
- `MyCpu_test/*.py`：镜像生成、回归运行、结果汇总脚本。
- `MyCpu_test/ddr_stage/` 中的 `.dat`、`cases.txt`、`tohost.tsv`。
- `MyCpu_test/ddr_selftest/` 中的 `.dat`、`manifest.tsv` 及当前所需的自检 RAM IP。
- `difftest/` 中除构建产物外的源程序、模型、黄金参考、测试台与脚本；历史参考 RTL 先保留，是否淘汰另行审查。

当前 ROM `.idf` 指向 `MyCpu_test/ddr_stage/boot_rom.dat`，RAM `.idf` 指向 `MyCpu_test/ddr_stage/ld_st.dat`。DDR RV32I Tcl 读取 `cases.txt`、`tohost.tsv`，自检 Tcl 读取 `manifest.tsv`。这些依赖不能随整个输出目录一起消失。

- `sim/behav/run_behav.bat`：当前内容调用 `sim/pds_ddr_ip_compile.tcl` 和 `sim/pds_ddr_ip_run.tcl`，应保留这一仿真入口。

## 4. 日志怎么取舍

本项目用日志证明 PASS/FAIL，不能把“日志可重新生成”理解成“历史验证证据都没有用”。建议：

1. 重复编译输出、波形和本机操作流水不上传。
2. 为重要验证保留一份有日期、命令、工具版本、代码/镜像对应关系的记录；必要时附原始日志。
3. 被忽略目录中的代表日志可复制到专门的 `doc/verification/` 等目录，再更新文档引用。该目录是建议，本次没有创建。
4. 尚未整理证据前，保守地保留 `sim/`、`MyCpu_test/ddr_stage/`、`MyCpu_test/ddr_selftest/` 及 DDR ModelSim 目录中的定向验证日志。

例如 `soc_ddr3_sim.log`、`soc_ddr3_regress_sim.log`、`sim/pds_ddr_selftest.log`、`sim/led_status.log` 和 `difftest/build/mmio_e2e/sim.log` 都与现有验证文档有关。忽略 `difftest/build/` 前应单独处理要发布的证据。旧日志的 PASS 也不能自动代表新代码 PASS。

## 6. 已经被 Git 跟踪的文件要单独处理

当前 `compile/`、`.workbuddy/`、`ip_backup/`、`RISCV.pds.lock`、部分日志和旧 ModelSim 库文件已经在索引中。**添加 `.gitignore` 不会自动停止跟踪它们，也不会清掉历史提交。** 本次只检查了本地状态，未查询 GitHub 远端，因此“已跟踪”不等于“已推送到 GitHub”。

之后实际整理时，先查看状态，并对每一类确认范围：

```powershell
Set-Location 'D:\riscv\RISCV'
git status --short
git ls-files -- compile sim/behav/work .workbuddy ip_backup RISCV.pds.lock

# 创建 .gitignore 后，检查规则是否按预期生效
git check-ignore -v --no-index -- RISCV.pds.lock sim/pds_ddr_ip_work/_info
git ls-files -ci --exclude-standard
```

对于已经确认不需要版本管理的文件，可先预览取消跟踪，再执行。例如仅处理锁文件和三个临时文本：

```powershell
# 预览，不改索引
git rm -n --cached -- RISCV.pds.lock _final.txt _ls.txt _rom.txt

# 确认预览后再执行；--cached 保留仍存在的本地文件
git rm --cached -- RISCV.pds.lock _final.txt _ls.txt _rom.txt
```

执行取消跟踪后，Git 会暂存这些路径的删除；需要检查 `git diff --cached --name-status` 再决定提交。已有大量未提交改动，本次不建议通过全仓 `git rm -r --cached .` 重建索引，也不要用 `git clean` 或 `git reset --hard` 来整理上传清单。

## 7. 本次核对记录与未覆盖范围

- **目的**：识别当前工程中不适合日常上传 GitHub 的文件，避免误排除仿真/构建输入。
- **改动**：只新增本文。
- **检查方式**：`git status --short`、`git diff --stat`、`git ls-files`、`rg --files --hidden -g '!.git'`；读取工程、脚本、IP 初始化配置，并搜索目录引用。
- **核对结果**：确认主要大文件来自 ModelSim 编译库；确认 PDS 与 DDR 脚本依赖 IP 源文件、测试 dump、镜像和运行清单；确认旧文档仍引用 `.workbuddy/` 和部分构建日志。
- **未覆盖**：没有删除文件后的完整克隆重建验证，没有重跑 RTL/DDR 仿真，没有检查 GitHub 远端或清理 Git 历史；没有完成第三方材料许可审计。当前脚本/IP 配置仍有本机绝对路径，保留依赖文件不代表换机器即可直接运行。

复核目录体积可在 PowerShell 中执行：

```powershell
Set-Location 'D:\riscv\RISCV'
$auditFiles = @(rg --files --hidden -g '!.git' | ForEach-Object {
    Get-Item -LiteralPath $_
})
$auditFiles | Measure-Object Length -Sum
```

体积数字是检查时的快照；后续运行工具、生成日志或新增本文都会改变统计值。MiB 按 1,048,576 字节计算。

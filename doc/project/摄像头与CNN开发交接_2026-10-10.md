# 摄像头与 CNN 开发交接

日期：2026-10-10。目标是让同学在当前SoC上开展摄像头/CNN开发。本次仅发布现有工程与接口交接，不新增摄像头或CNN RTL。设计直接放myriscv，工程入口RISCV.pds；PDS实现由开发者执行。

## 当前可复用基础

| 项目 | 当前实际状态 |
| --- | --- |
| 处理器 | 单核RV32I五级流水，core_clk=93.75 MHz；无RV32M、Cache、BTB |
| CPU接口 | 分离IF/data，32-bit字节地址的请求/响应总线；接受为valid&&ready，响应无ready |
| DDR | x16、512 MiB；Pango 128-bit用户拍，现有桥只处理一笔单拍事务，IF/MEM共享且数据优先 |

| UART | 115200 8N1，轮询和RX电平IRQ；沿用已验证UART/FIFO/MMIO |
| 软件 | 裸机BSP、Hello/CRC32/CoreMark；固定2B测量BIN可打印13项MMIO计数 |
| 最新硬件验证 | 主RTL六组回归通过；新增计数器的新主工程实现/实板待验，不沿用旧位流PASS |

## 需要遵守的接口边界

- 板级层次：board_top → soc_ddr3_top → soc_top → mycpu_sync。外部引脚放board_top；译码/连接放soc_top与互连，不将摄像头控制写入CPU流水线。
- ROM指令和RAM数据分挂总线；数据总线不能直接读取启动ROM。普通soc_top默认DDR关闭，板级soc_ddr3_top明确开启。
- 在请求接受边沿执行MMIO副作用并锁存响应；等待期间不能重复启动计算、弹出FIFO或清状态。沿用write strobe及access-fault语义。
- 当前CPU数据互连单主机，DDR桥也只有CPU的IF/data两路。新增摄像头写入/CNN访存不能直接把多个valid或数据线OR到IP上；必须新增并验证仲裁、owner响应返回、背压和复位排空。
- Pango用户口不是标准AXI4：无RREADY、无标准B响应、写通道无WVALID。读拍到达必须立即接收；Burst需要足够缓存，地址/长度/last语义须以本地IP及厂家例程核对。
- CPU地址单位为字节；现有桥先减DDR_BASE，用户地址按16-bit字计。128-bit拍含8个半字，命令低3bit对齐，addr[3:2]选32-bit槽。不要将CPU字节地址直接传给DDR IP。
- 写数据被WREADY接受不等于已定义多主机下的全局可见性。DMA的DONE、CPU读结果和帧缓冲切换必须定义并验证写入排空/可见性。
- 摄像头像素时钟通常与core_clk不同；按所选传感器确认实际域，用异步FIFO等处理CDC。复位按各域同步解除；KEY0消抖继续使用参考时钟，DDR初始化后才允许访问DDR。
- 当前IRQ为UART原因与外部输入OR后的电平；新增camera/CNN IRQ需独立使能、原因/清除状态和ISR分发，保持原UART IRQ语义。
- 当前无Cache；今后如CPU加入Cache，DMA缓冲需同步定义非缓存区或flush/invalidate。当前DDR性能计数没有owner区分，加入DMA后会混计，需单独按owner统计。

## 地址和软件布局

| 区域 | 已使用地址 |
| --- | --- |
| 片内ROM/RAM | 各自总线0x00000000–0x00003FFF |
| simple_mmio | 0x10000000–0x10000FFF；含原5寄存器及2B计数器0x100–0x1A4偏移 |
| UART | 0x10001000–0x1000100F，精确16字节 |
| DDR CPU窗口 | 0x40000000–0x5FFFFFFF |
| 当前BSP应用/栈 | linker.ld规划首60KiB程序、后4KiB栈，即0x40000000–0x4000FFFF |

可讨论的控制地址草案：camera从0x10002000、CNN从0x10003000各4KiB。**这是待协同分配的建议，当前互连未译码这些地址。** 帧缓冲、权重、激活及结果的DDR范围需要在软件链接布局和诊断区之外分配，并记录对齐、跨度、双缓冲owner；不先写死尚未确认的容量。

## 分工与实施顺序

1. 摄像头同学先确认型号、DVP/MIPI等接口、数据宽度、像素格式、分辨率/帧率、配置总线和官方引脚资料；这些当前未给定，不猜引脚。独立验证像素计数、行/帧边界、FIFO溢出/丢帧，再接SoC控制。
2. CNN同学先固定模型与量化契约：算子集合、尺寸/通道布局、INT8符号、INT32累加、bias、尺度/移位、舍入/饱和和padding。使用固定输入/权重与软件参考逐元素比较，先做单算子，不直接宣称整网通过。
3. 初次联调用合成帧/已知张量验证控制和计算；最终摄像头写DDR、CNN读写DDR和CPU控制的性能测试必须经过实际DDR路径。片内RAM单模块验证不能替代整机DDR验收。
4. 共享DDR/DMA接口由双方先统一：请求owner、地址、长度、beat顺序、done/error、仲裁公平性、输入FIFO容量、复位取消和缓冲移交。一次只接入一个新主机，保留CPU取指/load/store回归。
5. 集成到主工程后运行DDR两条物理定向、CPU/UART/异常/IRQ及新模块测试；用户完成PDS并检查时序/资源，然后实板采集到CNN输出闭环验收。

建议使用各自Git分支，涉及soc_top、data_bus_interconnect、DDR仲裁、board_top或约束时先统一接口和提交顺序。新增设计模块仍直接放myriscv，不建立候选设计目录。

## 新克隆与构建

建议Windows克隆至D:/riscv/RISCV，PDS2022.2-SP6.4、ModelSim10.6c；Python3、Icarus、GCC15.2.0按README安装，编译器安装包不在仓库中。CPU、SoC、IP生成RTL/初始化和成功Loader两块DAT已发布；按当前主工程从Compile开始完整实现，不能复用界面历史完成状态。

本地完整成功档案/旧上板门控/波形与大量仿真输出不上传，只发布精选结果和必要输入。基于这些档案的历史上传脚本不保证新克隆即可执行；先做新源码仿真和本次PDS审查，再绑定新位流门控。没有由Codex运行PDS或操作板子。

最小检查入口：`python sim/cpu_performance_2b/run.py --suite oracle --tag new_oracle`、`python sim/cpu_performance_2b/main_rtl.py --suite fast --tag new_rv32i`；均读取当前myriscv。两条DDR Tcl按AGENTS从厂家modelsim目录运行。CoreMark使用固定发布测量BIN，统计窗口和正确性必须保持一致。

## 验收指标

- 摄像头：帧/行/像素计数、像素顺序、格式、丢帧/溢出、跨域/复位恢复；实板读取已知测试图并核对。
- CNN：逐算子数值误差、整网参考结果、尺寸边界/非法配置、busy/done/error、IRQ、背压与复位。
- 整机：真实DDR下持续帧率、采集到结果延迟、DDR读写有效字节/命令数、FIFO水位、CPU并发CPI、资源及93.75MHz时序，附结果正确性。
- 吞吐及预期收益均须实测；不能把理论DDR带宽或MAC数量当整网FPS。

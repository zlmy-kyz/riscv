## 1. 当前结论

- 主工程器件为 PG2L100H、FBG484、速度等级 -6，PDS 版本 2022.2-SP6.4，设计顶层为 `board_top`。
- 主 ROM/RAM 初始化入口已经是 `MyCpu_test/board_selftest/boot_rom.dat` 和 `ddr_selftest.dat`，不是旧 `ddr_stage/` 镜像。旧镜像仍供独立回归使用。
- PDS 仿真入口为 `sim/board_main_selftest/compile.tcl`、`run.tcl`，顶层 `tb_board_top_selftest`；TB 本身也在这个目录，不能整个忽略 `sim/`。
- `RISCV.pds` 当前直接引用 `constraint_check/temp_constraint_file.fdc`。该文件含实际引脚与时钟约束，不能把 `constraint_check/` 整目录排除。
- 当前根目录没有 README、.gitignore 或 LICENSE。Git 已跟踪 183 个路径，其中 121 个落在本机工作资料、备份或编译输出目录；同时大量当前 RTL、镜像、脚本与文档尚未跟踪。
- 目前不具备“任意目录克隆后直接运行”的发布条件：IP 初始化、板级 Tcl/BAT、部分 Python/PowerShell 脚本及库映射仍含本机绝对路径。
- 搜索仅发现 CoreMark 准备文档，未发现 CoreMark 源码、移植层、C 启动文件、链接脚本或构建入口。上传现有工程不会自动获得 CoreMark 运行能力。

## 4. 同学能复现之前要补齐什么

### 工程入口和工具路径

1. 根 README 写清板卡型号/修订版、PG2L100H FBG484 -6、PDS 2022.2-SP6.4、参考时钟 125 MHz、core_clk 93.75 MHz、下载器与连接方法。
2. 仓库路径从脚本位置推导；ModelSim、PDS、Icarus、Python 和 Pango 库路径通过参数或本地配置设置，提供配置模板。
3. 修复 `sim/board_main_selftest/*.tcl`、`sim/behav/run_behav.bat`、`difftest/*.ps1`、相关 Python 脚本中的硬编码路径。DDR `sim_file_list.f` 也有 PDS 安装绝对路径。
4. ROM/RAM IDF 与生成包装模块中均有绝对 INIT_FILE；通过可靠相对路径或首次准备脚本解决，并核对生成初始化内容。只改 IDF 不代表所有生成文件同步。
5. 为 Pango 仿真库提供映射/生成步骤；`modelsim.ini` 和 PDS 的 `compiled_lib_location` 依赖当前安装布局，不能上传本机配置后宣称可移植。

### 上板与烧录文件

双击 `RISCV.pds` 是打开工程；同学仍需安装工具、使用匹配板卡，执行构建和下载。README 应给出“打开工程 → 生成 bitstream → 下载 → KEY0 复位 → LED 检查”的完整操作。

初次使用可在 GitHub Release 提供经过验证的 `.sbit`、必要配套下载文件、SHA256、对应提交、镜像、板卡、工具版本、时序与实板记录。日常源码仓库排除整个构建目录。

### 仿真说明

README 至少区分：板级主自检、两条完整 DDR 定向、RV32I 快速回归和异常/中断差分回归。标注 TB、镜像、运行目录、工具、结果日志及通过条件。

### CoreMark

建议新增独立 `software/coremark/`，保留官方源码/版本/许可、`core_portme.*`、`startup.S`、`linker.ld`、构建脚本、镜像转换脚本和运行说明。这是建议目录，当前尚未创建。

必须补齐 RV32I/ILP32 工具链与运行库、C 启动与 BSS 初始化、0x40000000 DDR 链接布局、现有 RAM 装载容量检查、MMIO 计时、成绩/CRC 读回渠道。当前 LED 仅报告状态；没有 UART，不能仅凭亮灯取得 CoreMark 分数。默认 5 秒 LED 超时也与正式计时冲突，应给 CoreMark 独立配置。

EEMBC 要求有效成绩至少运行 10 秒，指定两组种子均验证成功。短仿真可做功能检查；正式性能应记录迭代数、ticks、频率、编译器与参数、CRC 和存储布局。参见 [EEMBC 官方仓库与运行规则](https://github.com/eembc/coremark)、[裸机移植说明](https://github.com/eembc/coremark/blob/main/barebones_porting.md)，及本工程 [CoreMark准备文档](../coremark/CoreMark运行准备_2026-10-04.md)。

## 5. Git 整理与发布验收顺序

1. 保存当前工作树，按上述分类建立 `.gitignore`；先迁出要分享的验证证据。
2. 已跟踪产物需按明确路径取消跟踪。`.gitignore` 不自动改变索引，也不会清除历史。不要全仓重建索引或执行 `git clean`/`reset --hard`。
3. 添加有效未跟踪 RTL、IP、约束、镜像、脚本、文档；检查暂存差异。
4. 完成路径配置和 README；补齐 CoreMark 后才能把它列为可运行能力，之前标记“待移植”。
5. 仅从准备提交的文件导出/克隆到另一个目录，不借用原工程缓存。验证 PDS 打开、完整构建、主镜像、两条 DDR 定向、相关回归及文档链接。
6. 实板验收发布烧录文件，并将提交/镜像/bitstream 哈希与结果绑定后发布。

整理时可先执行以下只读检查：

```powershell
git status --short
git ls-files -- compile synthesize device_map sim/behav/work RISCV.pds.lock
# 创建忽略规则后检查：
git ls-files -ci --exclude-standard
git check-ignore -v --no-index -- RISCV.pds.lock constraint_check/temp_constraint_file.fdc
# 只预览指定产物的取消跟踪范围；本条不改变索引：
git rm -n -r --cached -- compile sim/behav/work RISCV.pds.lock
git diff --cached --stat
```

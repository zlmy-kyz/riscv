# 总线阶段评估

日期：2026-10-04。目的：判断当前单核 SoC 总线是否可以结束基础功能开发，转向 CoreMark 移植。依据当前 RTL 和已有日志；本次只读取与记录，未改 RTL 或重新运行回归。

结论：面向当前单核、分离指令/数据接口、单笔访问的 SoC，基础总线功能已经基本完成，可以作为后续软件运行基础。不存在必须先实现标准 AXI4、burst、DMA 或 Cache 才能运行 CoreMark 的结构要求；当前性能和覆盖范围仍应按实际存储配置报告。

## 已实现功能

| 功能 | 模块及行为 |
| --- | --- |
| 取指路由 | inst_bus_interconnect：ROM/DDR 译码、基址减法、请求目标锁存及响应路由 |
| 数据路由 | data_bus_interconnect：RAM/MMIO/DDR 译码、局部地址转换及响应路由 |
| 变延迟接口 | CPU 与从机使用 req_valid/req_ready/rsp_valid；等待期间保持请求和流水状态 |
| 片内存储适配 | inst_bram_adapter/data_bram_adapter 接同步存储，数据端支持字节写使能 |
| 错误路径 | 未映射请求返回 rsp_error；CPU 转为指令或数据访问异常，MMIO 非法访问有错误响应 |
| DDR 仲裁与转换 | dual_sram_to_pango_ddr_bridge：两路数据优先仲裁、单事务单拍、32/128 位槽选择、写使能扩展和厂家用户口握手 |
| 实际程序链路 | 启动 ROM → CPU 复制 RAM 镜像到 DDR → DDR 取指和数据访问 → MMIO 自检上报 |

## 后续范围

- 验证收尾：按最终版本固定回归入口和对应日志，后续共享 RTL 改动仍按 AGENTS.md 重跑。尚未证明长时随机压力或持续数据请求下的指令公平性；指定争用测试不能扩大解释。
- 可靠性扩展：永久反压/从机不响应的超时恢复未实现；DDR 用户口没有标准 BRESP/RRESP，当前桥不生成 DDR 错误响应，也不校验所有 ID/last 旁带。
- 性能扩展：burst、多笔未完成事务、轮询公平仲裁及 Cache 根据后续测量按需添加。当前数据互连和桥按单事务工作，功能可用但吞吐有限。
- 系统扩展：DMA/多主机仲裁、标准总线外设接口及其他跨时钟接口应在实际接入对应模块时设计。
- CoreMark 下一步：裸机工具链、启动/链接、装载镜像容量、计时和结果输出，详见 CoreMark运行准备_2026-10-04.md。

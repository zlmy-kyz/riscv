## ② 校验并运行 Hello

在新隔离候选中一起实现正式 VERIFY、RUN 和 Hello，先完成各项仿真，再提供一套完整的实板验收工具与候选位流输入，减少分阶段来回生成位流。内部仍按 `LOAD → VERIFY → RUN → Hello` 顺序验收。

- VERIFY 对完整镜像做实际 DDR CRC32，只在长度、身份和 CRC 全部匹配后授予 `VERIFIED`。覆盖错误 CRC、子范围、缺失 END；CMD14 诊断 CRC 不能授予该状态。
- RUN 检查已验证状态、镜像身份和合法入口；拒绝未验证、未对齐、ROM/MMIO/栈区及非法入口。RUN 前重新核验 DDR CRC，覆盖 VERIFY 后内存损坏；失败不得跳转。RUN ACK 的 UART 发送完成后才跳转，不自动重复 RUN。
- 仿真不得预装 DDR 应用，必须由真实 UART 下载。以实际 DDR 指令退休证明执行进入下载程序，核对入口指令、应用 gp/sp、非空 data 和 BSS 清零，再进入 main。
- 实板基本验收使用含非空 data/bss 检查的 Hello 应用，严格核对 `Hello World\r\n` 与原始 UART 日志；不能仅凭 LED、取指请求或旧串口输出认定成功。

各检查保留独立结果，但不再把 VERIFY、RUN、DDR 取指和基本 Hello 拆成四个对用户的阶段。全部通过后归档候选 DAT、BIN/manifest、位流身份和实板证据。

## ③ 同位流换程序与 CoreMark

继续使用第②关成功的同一 Loader 位流，只更换应用 BIN，不更换 IP 初始化或重新生成位流。

- 用户 KEY0 复位后重新执行完整下载/校验/运行，至少 10 轮成功；再换第二份不同 BIN，按对应 manifest 和预期输出核验，记录两个 BIN 与相同位流的身份。
- 上述 Hello 链路通过后，再下载现有 RV32I 裸机 CoreMark。两种配置先验证短迭代算法 CRC，再做 60 次迭代的正式运行；正式运行需不少于 10 秒且 32 位 cycle 计数不溢出。
- 分别记录下载协议 CRC32 和 CoreMark 算法 CRC16，短迭代 CRC 通过不能作为正式跑分或实板完整 PASS。

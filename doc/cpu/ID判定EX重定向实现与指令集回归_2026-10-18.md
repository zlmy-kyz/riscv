# ID 判定 + EX 重定向：实现与指令集回归

日期：2026-10-18。本轮实际修改 `myriscv/mycpu_sync.v`，新增隔离回归
`sim/br_ex_redirect/`。未运行 PDS / 未上板 / 未跑 SoC 级与全量 ISA。

## 1. 改动目的

当前 core 域 WNS 路径（`report_timing/board_top.rtr`，2026-10-18 02:49:56，+0.240 ns）
是一条 17 级链：

```
data_q → 7 选 1 → l_alu → mem_wb_wdata → id_rs1 → br_alu → id_taken
       → id_exc_valid → inst_if_id_accept → 互连 → 桥 take_inst_overlap → CE
```

其中 `id_taken` 之后到桥的那 3.07 ns，来自"ID 判定分支 → 组合取指地址 → 互连译码 → 桥地址装载"
全部发生在同一个时钟沿。本次把**重定向**这一动作从 ID 移到 EX：

- ID 仍然负责算出 `taken` 与目标地址（保留 ID 判定的低惩罚特性）；
- 判定结果随指令寄存器进入 EX，由 EX 在该指令真正能前进到 EX/MEM 的那一拍发起重定向；
- 目标取指不再与 ID 比较同拍启动，而是等 `pc` 更新后的下一拍发出。

按 rtr 分段估算，断掉的是 `13.284 → 16.352`（约 3.07 ns）这一段；改后最长段仍是
`data_q → id_taken` 约 6.7 ns，对 125 MHz 的 7.32 ns 组合预算属边界通过，对
109.375 MHz 宽裕。**实际结果以重跑 P&R 的新报告为准，本轮未做 STA。**

## 2. 六处改动（`myriscv/mycpu_sync.v`）

### 2.1 新增 ID/EX 字段（声明段，约 88 行）

```verilog
wire       ex_br_redirect;
reg        id_ex_br_taken;
reg [31:0] id_ex_br_target;
```

`branch_fetch_turnover` 声明删除；`BRANCH_FETCH_TURNOVER_ENABLE` 参数保留以兼容外部传参，
但已不再影响任何逻辑。

### 2.2 ID/EX 寄存判定结果（约 796 行，紧跟 `id_ex_next_pc`）

与其它 ID/EX 字段同一套保持/清空规则：

```verilog
always @(posedge clk) begin
    if (!resetn || kill_id_ex) begin
        id_ex_br_taken  <= 1'b0;   id_ex_br_target <= 32'b0;
    end else if (data_pipeline_stall) begin
        id_ex_br_taken  <= id_ex_br_taken;   id_ex_br_target <= id_ex_br_target;
    end else if (bubble_id_ex) begin
        id_ex_br_taken  <= 1'b0;   id_ex_br_target <= 32'b0;
    end else if (id_fire) begin
        id_ex_br_taken  <= id_taken;   id_ex_br_target <= bj_pc;
    end
end
```

### 2.3 IF 侧回退 030 的同拍目标取指（约 373 行）

```verilog
assign inst_req_valid = resetn && fetch_valid && !redirect_valid &&
                        inst_turnover_safe &&
                        (!inst_buffer_valid || inst_buffer_pop);
assign inst_req_addr = pc;
...
else if (redirect_valid) pc <= redirect_pc;
else if (inst_req_fire) pc <= pc + 32'd4;
```

重定向当拍不发请求，目标地址先写入 `pc`，下一拍再以 `pc` 发起。
这是本方案唯一新增的时序代价：**每次 taken 分支晚一拍启动取指**。

### 2.4 EX 级重定向（约 979 行）

```verilog
assign ex_br_redirect = resetn && id_ex_advance && id_ex_br_taken &&
                        !id_ex_exc_valid && !older_fault_for_ex &&
                        !trap_redirect_req && !mret_redirect_req;
```

- `id_ex_advance` 保证只有本条确实能进 EX/MEM 时才跳，**停顿时不重复重定向**；
- `!id_ex_exc_valid`：本条自身异常（含目标错位）不跳，交给 trap；
- `!older_fault_for_ex`：更老指令已有故障时让位；
- `!trap_redirect_req && !mret_redirect_req`：WB 提交的同步 trap/IRQ/MRET 比 EX 分支更老，必须优先。

### 2.5 重定向选择（约 1376 行）

```verilog
assign branch_redirect = ex_br_redirect;
assign redirect_valid  = trap_redirect_req || mret_redirect_req || branch_redirect;
assign redirect_pc     = trap_redirect_req ? trap_redirect_target :
                         mret_redirect_req ? mret_redirect_target : id_ex_br_target;
```

### 2.6 ID 发射抑制（约 1367 行）

```verilog
assign id_fire = ... && !trap_redirect_req && !mret_redirect_req &&
                 !branch_redirect;
```

EX 重定向当拍 ID 里必然是错误路径指令，必须变成气泡；目标指令在下一拍由 `pc` 重新取回。
`bubble_id_ex = !id_fire && !data_pipeline_stall` 因此自动为 1，ID/EX 装载气泡。

## 3. 为什么能断开长链

重定向前：`bj_pc`（ID 组合）→ `inst_req_addr` → 互连 → 桥 CE，全在同一沿。

重定向后：`id_ex_br_target`（寄存器）→ `pc` 的 D 端 → **时钟沿** → `pc`（寄存器）→
`inst_req_addr` → 互连 → 桥。链被两级寄存器夹断，起点变成寄存器输出。

## 4. 回归环境 `sim/br_ex_redirect/`

历史入口（`sim/cpu_branch_turnover/run.py`、`sim/cpu_performance/run.py`）在
`inputs.json` 中封存了源码 SHA256，改 RTL 后会被断言拒绝，因此新建隔离环境：

| 文件 | 作用 |
|---|---|
| `asm.py` | 最小 RV32I 汇编器（含 `li`/`la`/`nop` 伪指令），输出 `imem.hex`/`program.lst`/`labels.txt` |
| `program.S` | 六个定向用例（分支、JAL/JALR、load→分支、load→JALR、循环、停顿中分支） |
| `program_trap.S` | `jalr` 目标 = 0x2（2 字节对齐）必须 trap，而不是被当成重定向 |
| `tb_br_ex_redirect.v` | 1 拍同步 IMEM/DMEM 模型，按架构可见结果断言（DMEM、trap、退休数） |
| `mul_behavioral.v` | 乘法 IP 的行为替身（用例不含乘法，仅为可编译） |
| `run.py` | 汇编 + iverilog 编译 + 两个 MODE 运行，结果写入 `build/<tag>/` |

入口：

```powershell
python -X utf8 sim/br_ex_redirect/run.py --tag br_ex_redirect_20261018_d
```

## 5. 回归结果（`build/br_ex_redirect_20261018_d/`）

编译：`iverilog -g2012 -Wall -Wno-timescale`，**无警告**。

## 6. 代价：实测每次 taken 跳转多 1 拍

用同一个 testbench 对两个 RTL 版本跑同一段基准（`program_bench.S`：1000 次 taken 条件分支，
每圈 4 条指令），只替换 `mycpu_sync.v`：

| RTL | 完成周期 | 退休指令 |
|---|---:|---:|
| 改动前（030，ID 判定 + 同拍目标取指），commit `f2ea9e3` | **10022** | 4006 |
| 改动后（EX 重定向），commit `18a7231` | **11021** | 4006 |

差值 999 拍 ≈ 1000 次分支 × **1 拍/分支**。所以"多浪费一个周期"的说法是准确的，
且只发生在 **taken 的条件分支、JAL、JALR** 上：not-taken 分支不重定向，顺序取指不受影响；
trap / MRET 的重定向路径未改动。

按 CoreMark P300 约 1900 万次 redirect 估算：+19M 周期，相对 210.2M 基数约 **+9.0%**。
（此前按 030 的净收益锚定得到 +6.2%，偏乐观；030 的同拍接续并非每次都成功，实测差值是整 1 拍。）

| 目标频率 | 预计 P300 时间 | 相对改前 2.2426 s |
|---|---:|---:|
| 维持 93.75 MHz | 约 2.44 s | **+9.0%（净亏）** |
| 109.375 MHz | 约 2.10 s | −6.6% |
| 125 MHz | 约 1.83 s | −18.3% |

即：这一刀只有配合提频才有正收益；只改结构不提频是净亏。


## 7. 未覆盖与风险

1. **未做 STA**：本轮没有跑 PDS，WNS 改善是按 rtr 分段估算。需用户重新综合/布局布线验证。
2. **未跑 SoC 级与全量 ISA**：本次只验证 CPU 核的分支/跳转/异常语义；
   `sim/cpu_branch_turnover`、`sim/cpu_performance` 的封存回归需要重建输入清单才能复用。
3. **未上板**：DDR 上的实际 CPI 变化（+1 拍/分支）需实板 P300/V300 实测。
4. **perf 计数口径变化**：`perf_events[5]`(branch_redirect) 现在晚一拍产生，
   与历史日志的分支分类不可逐拍对齐，比较总周期时需注明。
5. **`BRANCH_FETCH_TURNOVER_ENABLE` 已成为无效参数**，外部若仍传值不会报错，但不再改变行为。

改动后用户重跑 PDS，`report_timing/board_top.rtr`（03:58:19）：

| 时钟域 | 改动前 WNS | 改动后 WNS | 改动后估计频率 |
|---|---:|---:|---:|
| `ddrphy_sysclk` | +0.240 | **+0.609** | 95.91 → **99.43 MHz** |
| `camera_pclk` | +0.893 | **+2.838** | 109.81 → 139.63 MHz |
| `ddr_ref_clk` | +5.191 | +4.982 | 331.35 MHz |
| `rst_clk` | +4.056 | +4.380 | 276.24 MHz |

`Design Summary: All Constraints Met`，0 failing endpoint，hold 全正（最低 0.144）。
camera 域余量大幅回升，说明原分支链占用的布局资源被释放。

### 原分支链已不在关键路径

改动前 WNS 是 `data_q → 7 选 1 → l_alu → mem_wb_wdata → id_rs1 → br_alu →
id_taken → id_exc_valid → 互连 → 桥 take_inst_overlap → CE`（17 级）。
改动后该路径未出现在报告前列，断链生效。

### 新的 WNS 是访存地址通路，与分支无关

```
u_cpu/id_ex_src1[30]（ID/EX 寄存器）
  → u_alu                        0.427 + 0.444
  → data_req_addr[13] fanout 25  布线 1.199
  → data_bus_interconnect 减法器 COUT 链   0.353+0.090+0.224
  → pp_req_addr[24] → u_cnn     0.235+0.078+0.311
  → preprocess command fanout 203  0.833
  → start_cmd fanout 140           0.607
  → N1754 fanout 40                0.620
  → pixels[*] CE 进位链 8 级        8 × 0.146
18 级，3.501 逻辑 + 5.911 布线
```

第二位 WNS 同源：`id_ex_src1[5] → u_alu → 访存地址 → 桥 inst_line_tag` 的 CE。
两条都是"EX 算地址、同拍发请求"的结构性通路，与本次改动无关。

### 距提频目标

按当前 arrival 15.829 / required 16.438 推算：

| 目标 | 需再砍 |
|---|---:|
| 109.375 MHz（9.143 ns） | **0.92 ns** |
| 125 MHz（8.000 ns） | **2.06 ns** |

新瓶颈集中在 `preprocess` 的命令广播（`command` fanout 203、`start_cmd` fanout 140）
和 `pixels[*]` 写使能的进位链串联（8 级 1.17 ns）。这些是 PP 模块内部结构，
修它们不需要改 CPU、也不影响 CoreMark 周期数。

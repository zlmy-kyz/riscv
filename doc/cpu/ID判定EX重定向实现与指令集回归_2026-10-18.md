### 当前首选静态缺陷

冻结EX候选CPU仍为`ef6bfec7…cc87e6`，工作树旧ID源码保持，未恢复/覆盖。静态追踪发现：

1. `flow_state`在FLOW_RUN看到`fetch_valid && serial_candidate`即进入FLOW_SERIAL_DRAIN。
2. EX候选的`branch_redirect`会清IF/ID并抑制ID发射，却没有取消由年轻ID串行指令启动的排空状态。
3. `serial_issue`要求FLOW_SERIAL_DRAIN、pipeline_empty且serial_candidate仍有效；被分支冲刷后serial_candidate消失，而frontend_hold因flow_state非RUN持续为1，目标指令可滞留在取指缓冲而进不了ID。

| 情形 | 分支发生前/同沿 | 分支发生后 |
|---|---|---|
| 同沿启动排空 | EX分支推进，年轻ID是CSR/FENCE，FLOW_RUN将进入排空 | ID已清，状态留在SERIAL_DRAIN，无串行令牌可issue |
| 提前进入排空 | 更老MEM等待，EX分支暂不能推进；年轻ID串行先启动排空 | 老MEM完成后EX跳转清ID，已存在的SERIAL_DRAIN仍不退出 |

这是一个静态可达的控制缺陷；**是否为本次实板首个故障，尚需真实触发轨迹或冻结候选最小复现证明**，不伪称已观察板上PC。

冻结P300在BSP trap路径已有具体形态：PC`0x40000120`为`104080e7`（JALR到trap_dispatch），顺序下一条PC`0x40000124`为`34151073`（CSRW MEPC,a0）。EX延后跳转时，该顺序CSR可能先作为错误路径出现在ID；它会在函数正常返回后成为合法指令，必须区分两次生命周期。仅用初等branch/load微程序不足以覆盖。

现有隔离TB还存在相关覆盖缺口：指令请求E接受，E+1才NBA置rsp_valid，CPU到E+2消费，是两拍可见返回；真实ROM/I-cache hit支持E接受、E+1消费且同沿下一接受。慢模型未必让年轻CSR和EX分支在所需周期重叠，已有PASS不能反证上述缺陷。

修复方向应是**EX重定向取消所有由更年轻错误路径指令启动的串行排空**，同时保留更老trap/MRET/IRQ与合法串行语义。不能只在FLOW_RUN入口加`!branch_redirect`，因为第二种已进入排空的场景仍可能死锁。本轮没有直接修改CPU或提供未经复现的位流。

## 1. 改动目的

当前 core 域 WNS 路径（`report_timing/board_top.rtr`，2026-10-18 02:49:56，+0.240 ns）
是一条 17 级链：

```
data_q → 7 选 1 → l_alu → mem_wb_wdata → id_rs1 → br_alu → id_taken
       → id_exc_valid → inst_if_id_accept → 互连 → 桥 take_inst_overlap → CE
```

其中 `id_taken` 之后到桥的那 3.07 ns，来自"ID 判定分支 → 组合取指地址 → 互连译码 → 桥地址装载"
全部发生在同一个时钟沿。本次把**重定向**这一动作从 ID 移到 EX：

- ID 仍然负责算出 `taken` 与目标地址（保留 ID 判定的低惩罚特性）；
- 判定结果随指令寄存器进入 EX，由 EX 在该指令真正能前进到 EX/MEM 的那一拍发起重定向；
- 目标取指不再与 ID 比较同拍启动，而是等 `pc` 更新后的下一拍发出。

按 rtr 分段估算，断掉的是 `13.284 → 16.352`（约 3.07 ns）这一段；改后最长段仍是
`data_q → id_taken` 约 6.7 ns，对 125 MHz 的 7.32 ns 组合预算属边界通过，对
109.375 MHz 宽裕。**实际结果以重跑 P&R 的新报告为准，本轮未做 STA。**

### 2.3 IF 侧回退 030 的同拍目标取指（约 373 行）

```verilog
assign inst_req_valid = resetn && fetch_valid && !redirect_valid &&
                        inst_turnover_safe &&
                        (!inst_buffer_valid || inst_buffer_pop);
```

重定向当拍不发请求，目标地址先写入 `pc`，下一拍再以 `pc` 发起。
这是本方案唯一新增的时序代价：**每次 taken 分支晚一拍启动取指**。

### 2.4 EX 级重定向（约 979 行）

```verilog
assign ex_br_redirect = resetn && id_ex_advance && id_ex_br_taken &&
                        !id_ex_exc_valid && !older_fault_for_ex &&
                        !trap_redirect_req && !mret_redirect_req;
```

- `id_ex_advance` 保证只有本条确实能进 EX/MEM 时才跳，**停顿时不重复重定向**；
- `!id_ex_exc_valid`：本条自身异常（含目标错位）不跳，交给 trap；
- `!older_fault_for_ex`：更老指令已有故障时让位；
- `!trap_redirect_req && !mret_redirect_req`：WB 提交的同步 trap/IRQ/MRET 比 EX 分支更老，必须优先。

### 2.5 重定向选择（约 1376 行）

```verilog
                         mret_redirect_req ? mret_redirect_target : id_ex_br_target;
```

### 2.6 ID 发射抑制（约 1367 行）

```verilog
assign id_fire = ... && !trap_redirect_req && !mret_redirect_req &&
                 !branch_redirect;
```

EX 重定向当拍 ID 里必然是错误路径指令，必须变成气泡；目标指令在下一拍由 `pc` 重新取回。
`bubble_id_ex = !id_fire && !data_pipeline_stall` 因此自动为 1，ID/EX 装载气泡。

## 3. 为什么能断开长链

重定向前：`bj_pc`（ID 组合）→ `inst_req_addr` → 互连 → 桥 CE，全在同一沿。

重定向后：`id_ex_br_target`（寄存器）→ `pc` 的 D 端 → **时钟沿** → `pc`（寄存器）→
`inst_req_addr` → 互连 → 桥。链被两级寄存器夹断，起点变成寄存器输出。

## 6. 代价：实测每次 taken 跳转多 1 拍

用同一个 testbench 对两个 RTL 版本跑同一段基准（`program_bench.S`：1000 次 taken 条件分支，
每圈 4 条指令），只替换 `mycpu_sync.v`：

| RTL | 完成周期 | 退休指令 |
|---|---:|---:|
| 改动前（030，ID 判定 + 同拍目标取指），commit `f2ea9e3` | **10022** | 4006 |
| 改动后（EX 重定向），commit `18a7231` | **11021** | 4006 |

差值 999 拍 ≈ 1000 次分支 × **1 拍/分支**。所以"多浪费一个周期"的说法是准确的，
且只发生在 **taken 的条件分支、JAL、JALR** 上：not-taken 分支不重定向，顺序取指不受影响；
trap / MRET 的重定向路径未改动。

按 CoreMark P300 约 1900 万次 redirect 估算：+19M 周期，相对 210.2M 基数约 **+9.0%**。
（此前按 030 的净收益锚定得到 +6.2%，偏乐观；030 的同拍接续并非每次都成功，实测差值是整 1 拍。）

| 目标频率 | 预计 P300 时间 | 相对改前 2.2426 s |
|---|---:|---:|
| 维持 93.75 MHz | 约 2.44 s | **+9.0%（净亏）** |
| 109.375 MHz | 约 2.10 s | −6.6% |
| 125 MHz | 约 1.83 s | −18.3% |

即：这一刀只有配合提频才有正收益；只改结构不提频是净亏。


## 7. 未覆盖与风险

1. **未做 STA**：本轮没有跑 PDS，WNS 改善是按 rtr 分段估算。需用户重新综合/布局布线验证。
2. **未跑 SoC 级与全量 ISA**：本次只验证 CPU 核的分支/跳转/异常语义；
   `sim/cpu_branch_turnover`、`sim/cpu_performance` 的封存回归需要重建输入清单才能复用。
3. **未上板**：DDR 上的实际 CPI 变化（+1 拍/分支）需实板 P300/V300 实测。
4. **perf 计数口径变化**：`perf_events[5]`(branch_redirect) 现在晚一拍产生，
   与历史日志的分支分类不可逐拍对齐，比较总周期时需注明。
5. **`BRANCH_FETCH_TURNOVER_ENABLE` 已成为无效参数**，外部若仍传值不会报错，但不再改变行为。

### 新的 WNS 是访存地址通路，与分支无关

```
u_cpu/id_ex_src1[30]（ID/EX 寄存器）
  → u_alu                        0.427 + 0.444
  → data_req_addr[13] fanout 25  布线 1.199
```

第二位 WNS 同源：`id_ex_src1[5] → u_alu → 访存地址 → 桥 inst_line_tag` 的 CE。

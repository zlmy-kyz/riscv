### 边沿静态审查

下表push仅指真实D store接受，pop仅指旧head的实际W完成；主前端槽、DDR就绪及原顺序门仍必须允许接受。设沿前head=A、tail=B、新store=C：

| 沿前条数 | pop | push | 沿后head / tail | 该沿物理W |
|---:|---:|---:|---|---|
| 0 | 0 | 0/1 | 空 / C成为head | 无 |
| 1 | 0 | 0 | A / 空 | 无 |
| 1 | 0 | 1 | A / C | 无 |
| 1 | 1 | 0 | 空 / 空 | A |
| 1 | 1 | 1 | C / 空 | A |
| 2 | 0 | 0 | A / B | 无 |
| 2 | 0 | 1 | 禁止接受，保持A / B | 无 |
| 2 | 1 | 0 | B / 空 | A |
| 2 | 1 | 1 | B / C | A |

满队同沿接续仍受`WRITE_BUFFER_TURNOVER_ENABLE`控制；深度2已有空tail时可接收，与是否允许满队同沿复用无关。归纳上，tail有效始终蕴含head有效，只有实际接受创建条目，只有实际W或复位删除。AW接受后未W时允许填tail但head字段不动；提升head清其aw_sent，新head须取得自己的AW。init暂失只暂停两条和AW状态，reset取消未排空记录；旧W/旧响应消费者在该沿使用沿前字段，不会消费新store数据。

load的full tag/lane分别匹配两条，字节展开mask为Mh/Mt，响应mask=`Mh|Mt`，响应forward data=`(head_data & Mh & ~Mt) | (tail_data & Mt)`；与DRM合成时未覆盖字节保留cache。此值在load真实接受沿锁存，后续出队/入队不改旧响应归属。无转发时任一条同行均不准重叠读。

资格和同行关系仍先寄存，不把新地址比较放入ready。同行关系取两条OR：load保持等待时没有另一个D store可入队，队首出队后剩余line只能是前一快照的子集，故即使tail已提升，旧快照也不会漏掉实际写碰撞。若仅tail同行而异行head本沿完成，会保守多挡该沿；这是明确的吞吐取舍，尚未实测代价。原碰撞规则按整line保守阻挡。

`write_buffer_busy=head_valid|tail_valid`（posted有效时）不在head完成且tail存在时短暂归零，现有AR与SoC非DDR、CPU FENCE/IRQ排空自然等待整个队列。I仍每个store接受即失效，035同拍I/store同行毒化、park提升/单DDR读保持；D仍用旧head地址、数据和strobe在实际W沿更新，tail接受不提前更新D。没有更改034 posted ACK和已有load响应寄存。

## 1. 改动目的

当前 core 域 WNS 路径（`report_timing/board_top.rtr`，2026-10-18 02:49:56，+0.240 ns）
是一条 17 级链：

```
data_q → 7 选 1 → l_alu → mem_wb_wdata → id_rs1 → br_alu → id_taken
       → id_exc_valid → inst_if_id_accept → 互连 → 桥 take_inst_overlap → CE
```

其中 `id_taken` 之后到桥的那 3.07 ns，来自"ID 判定分支 → 组合取指地址 → 互连译码 → 桥地址装载"
全部发生在同一个时钟沿。本次把**重定向**这一动作从 ID 移到 EX：

- ID 仍然负责算出 `taken` 与目标地址（保留 ID 判定的低惩罚特性）；
- 判定结果随指令寄存器进入 EX，由 EX 在该指令真正能前进到 EX/MEM 的那一拍发起重定向；
- 目标取指不再与 ID 比较同拍启动，而是等 `pc` 更新后的下一拍发出。

按 rtr 分段估算，断掉的是 `13.284 → 16.352`（约 3.07 ns）这一段；改后最长段仍是
`data_q → id_taken` 约 6.7 ns，对 125 MHz 的 7.32 ns 组合预算属边界通过，对
109.375 MHz 宽裕。**实际结果以重跑 P&R 的新报告为准，本轮未做 STA。**

## 2. 六处改动（`myriscv/mycpu_sync.v`）

### 2.1 新增 ID/EX 字段（声明段，约 88 行）

```verilog
wire       ex_br_redirect;
reg        id_ex_br_taken;
reg [31:0] id_ex_br_target;
```

`branch_fetch_turnover` 声明删除；`BRANCH_FETCH_TURNOVER_ENABLE` 参数保留以兼容外部传参，
但已不再影响任何逻辑。

### 2.2 ID/EX 寄存判定结果（约 796 行，紧跟 `id_ex_next_pc`）

与其它 ID/EX 字段同一套保持/清空规则：

```verilog
always @(posedge clk) begin
    if (!resetn || kill_id_ex) begin
        id_ex_br_taken  <= 1'b0;   id_ex_br_target <= 32'b0;
    end else if (data_pipeline_stall) begin
        id_ex_br_taken  <= id_ex_br_taken;   id_ex_br_target <= id_ex_br_target;
    end else if (bubble_id_ex) begin
        id_ex_br_taken  <= 1'b0;   id_ex_br_target <= 32'b0;
    end else if (id_fire) begin
        id_ex_br_taken  <= id_taken;   id_ex_br_target <= bj_pc;
    end
end
```

### 2.3 IF 侧回退 030 的同拍目标取指（约 373 行）

```verilog
assign inst_req_valid = resetn && fetch_valid && !redirect_valid &&
                        inst_turnover_safe &&
                        (!inst_buffer_valid || inst_buffer_pop);
assign inst_req_addr = pc;
...
else if (redirect_valid) pc <= redirect_pc;
else if (inst_req_fire) pc <= pc + 32'd4;
```

重定向当拍不发请求，目标地址先写入 `pc`，下一拍再以 `pc` 发起。
这是本方案唯一新增的时序代价：**每次 taken 分支晚一拍启动取指**。

### 2.4 EX 级重定向（约 979 行）

```verilog
assign ex_br_redirect = resetn && id_ex_advance && id_ex_br_taken &&
                        !id_ex_exc_valid && !older_fault_for_ex &&
                        !trap_redirect_req && !mret_redirect_req;
```

- `id_ex_advance` 保证只有本条确实能进 EX/MEM 时才跳，**停顿时不重复重定向**；
- `!id_ex_exc_valid`：本条自身异常（含目标错位）不跳，交给 trap；
- `!older_fault_for_ex`：更老指令已有故障时让位；
- `!trap_redirect_req && !mret_redirect_req`：WB 提交的同步 trap/IRQ/MRET 比 EX 分支更老，必须优先。

### 2.5 重定向选择（约 1376 行）

```verilog
assign branch_redirect = ex_br_redirect;
assign redirect_valid  = trap_redirect_req || mret_redirect_req || branch_redirect;
assign redirect_pc     = trap_redirect_req ? trap_redirect_target :
                         mret_redirect_req ? mret_redirect_target : id_ex_br_target;
```

### 2.6 ID 发射抑制（约 1367 行）

```verilog
assign id_fire = ... && !trap_redirect_req && !mret_redirect_req &&
                 !branch_redirect;
```

EX 重定向当拍 ID 里必然是错误路径指令，必须变成气泡；目标指令在下一拍由 `pc` 重新取回。
`bubble_id_ex = !id_fire && !data_pipeline_stall` 因此自动为 1，ID/EX 装载气泡。

## 3. 为什么能断开长链

重定向前：`bj_pc`（ID 组合）→ `inst_req_addr` → 互连 → 桥 CE，全在同一沿。

重定向后：`id_ex_br_target`（寄存器）→ `pc` 的 D 端 → **时钟沿** → `pc`（寄存器）→
`inst_req_addr` → 互连 → 桥。链被两级寄存器夹断，起点变成寄存器输出。

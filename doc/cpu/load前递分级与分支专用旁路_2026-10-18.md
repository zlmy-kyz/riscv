本轮只出设计输入，未修改 RTL、未运行仿真/PDS/实板。

## 2. 这条链在 RTL 里由四段拼成

| 段 | 代码位置 | 内容 |
|---|---|---|
| ① 响应 → 提取 | `mycpu_sync.v:1065-1070` | `l_alu` 用 `data_rsp_rdata` 做字节/半字抽取与符号扩展 |
| ② 提取 → 写回值 | `mycpu_sync.v:1074-1075` | `mem_fwd_data` 用 `ex_mem_i_l` 选 `mem_result` 或 `ex_mem_alu_result` |
| ③ 写回值 → ID 操作数 | `mycpu_sync.v:1237-1252` | `fwd_mem_en` 在 load 响应当拍成立，`id_fwd_mem1/2` 把 `mem_fwd_data` 送进 `id_rs1/id_rs2` 的 3 选 1 mux |
| ④ 操作数 → 分支 → 取指 | `mycpu_sync.v:1260-1274`、`1341-1345` | `br_alu` 比较 → `id_taken` → `branch_redirect` → `redirect_pc` → `inst_req_addr` → 互连 → 桥 |

关键是 ③：`fwd_mem_en` 允许 **load 的响应当拍**就把数据经 `mem_fwd_data` 前递到 ID。
于是同一个时钟沿内必须依次完成“提取 → 前递 → 比较 → 跳转判定 → 取指地址 → 桥地址寄存器”。

## 3. 方案：给分支一条不使用 MEM 级 load 前递的专用旁路

不是把所有 load 前递都延后（那会惩罚每一条 load→ALU），而是**只把 `mem_fwd_data` 从分支比较器的输入上摘掉**：

- ALU / store / 其它消费者继续用 `id_rs1/id_rs2`，保留同拍 MEM 前递，零代价。
- `br_alu` 与 `jalr_pc` 改用 `id_rs1_br/id_rs2_br`，只允许 EX 前递、WB 前递、寄存器堆三个来源。
- 补一条停顿判据：当 MEM 级是 load、而 ID 级是分支且要读它时，ID 多停一拍，等 load 进 MEM/WB 后从 `rf_wdata` 前递。

这样 ③④ 之间的组合链被物理切断（`mem_fwd_data` 不再驱动 `br_alu`），STA 上省掉 ①②③ 的绝大部分。

### 3.1 代码改动

**(a) 新增分支专用操作数（`mycpu_sync.v` 前递段，1247 行之前）**

```verilog
// 分支/jalr 专用源操作数：不接受 MEM 级 load 同拍前递，
// 使 l_alu → mem_fwd_data → br_alu 的组合链断开。
assign id_rs1_br = id_fwd_ex1 ? ex_wb_data :
                   id_fwd_wb1 ? rf_wdata   : rdata1;
assign id_rs2_br = id_fwd_ex2 ? ex_wb_data :
                   id_fwd_wb2 ? rf_wdata   : rdata2;
```

**(b) 分支比较与 jalr 目标改用新操作数（1260、1267 行）**

```verilog
br_alu u_br_alu (
    .inst_6b (inst_6b),
    .xrs1    (id_rs1_br),
    .xrs2    (id_rs2_br),
    .br_taken(br_taken)
);

assign jalr_pc = (id_rs1_br + imm) & ~32'h1;
```

`id_rs1/id_rs2` 原定义（1247-1252）保持不变，继续供 ALU/EX 使用。

**(c) 新增停顿判据（`mycpu_sync.v:655` 附近，与 `load_use` 并列）**

```verilog
// MEM 级 load 尚未进 MEM/WB，而 ID 是分支且要读它 → 等一拍走 WB 前递。
// 只惩罚 load→branch/jalr，load→ALU 仍走同拍 MEM 前递。
wire br_reads_rs1 = inst_b | inst_jalr;
wire br_reads_rs2 = inst_b;
wire load_use_br  = if_id_valid && ex_mem_valid && ex_mem_i_l && ex_mem_gf_we &&
                    ~ex_mem_exc_valid && ~ex_mem_bus_error &&
                    (ex_mem_rd != 5'd0) &&
                    ((br_reads_rs1 && (ex_mem_rd == rs1)) ||
                     (br_reads_rs2 && (ex_mem_rd == rs2)));

assign load_use = id_ex_valid & id_ex_i_l & id_ex_gf_we & (id_ex_rd != 5'd0) &
                  ((uses_rs1 & (id_ex_rd == rs1)) |
                   (uses_rs2 & (id_ex_rd == rs2)))
                  | load_use_br;          // 新增这一项
```

`load_use` 已经参与 `id_fire`(1330) 与 `frontend_hold`(1336)，不需要额外接线。

### 3.2 为什么正好多一拍

`ex_mem_i_l` 在 `ex_mem` 里保持到 `ex_mem_complete`（即 `data_rsp_valid` 那一拍，`mycpu_sync.v:941-942`）。
所以：

- load 等响应期间：`data_pipeline_stall=1`，ID 本来就停，`load_use_br` 同时为 1，无额外影响。
- 响应到达那一拍：`data_pipeline_stall` 归 0，但 `load_use_br` 仍为 1 → ID 不发射；同沿 `mem_wb_wdata <= mem_fwd_data` 进 MEM/WB。
- 下一拍：`ex_mem` 已换指令，`load_use_br=0`，`rf_wdata` 可用，分支发射并重定向。

## 4. 逐拍例子

### 例 1：load 后紧跟分支（本条链的病灶）

```asm
        lw    a3, 0(a2)        # I1
        beq   a3, zero, done   # I2  ← 立刻依赖 I1
        addi  a2, a2, 4        # I3
done:   ...
```

设 load 请求在 T0 发出，DDR 响应在 T8 到达。

**改动前（同拍 MEM 前递）**

| 拍 | I1 | I2 (ID) | 说明 |
|---|---|---|---|
| T0 | EX 发 load | 停 | `load_use=1` |
| T1–T7 | MEM 等响应 | 停 | `data_pipeline_stall=1` |
| **T8** | 响应到 → `l_alu` → `mem_fwd_data` | **同拍发射** | 提取→前递→`br_alu`→`id_taken`→redirect→`inst_req_addr`→桥，全在 T8 的一个沿内 |
| T9 | 进 WB | 目标指令进 ID | — |

**改动后（分支专用旁路）**

| 拍 | I1 | I2 (ID) | 说明 |
|---|---|---|---|
| T0–T7 | 同前 | 停 | 同前 |
| **T8** | 响应到，`mem_wb_wdata <= mem_fwd_data` | **仍停** | `load_use_br=1`；`br_alu` 的输入不再是 `mem_fwd_data` |
| **T9** | 在 WB | 发射 | `rf_wdata` → `id_rs1_br` → `br_alu` → redirect → 取指 |
| T10 | — | 目标进 ID | 比改动前晚 1 拍 |

### 例 2：load 后紧跟 ALU（不该被惩罚）

```asm
        lw    t0, 0(a1)        # I1
        add   t1, t0, t2       # I2  ← ALU 消费者
```

| 拍 | 改动前 | 改动后 |
|---|---|---|
| T8（响应到） | I2 用 `mem_fwd_data` 发射 | **同样用 `mem_fwd_data` 发射** |
| T9 | 进 EX | 进 EX |

零代价：`id_rs1` 未改，`load_use_br` 只对 `inst_b | inst_jalr` 成立。

### 例 3：load 后隔一条再用（本来就不用 MEM 前递）

```asm
        lw    a0, 0(a1)        # I1
        addi  a2, a2, 1        # I2（独立）
        beq   a0, a3, done     # I3 用 I1，但已隔一条
```

I3 在 ID 时 I1 已在 MEM/WB 或 WB，走 `id_fwd_wb1`，`load_use_br` 不成立，无额外拍。

## 5. 收益与代价

**时序收益（估计）**：断掉的是 rtr 里 `7.214 → 11.148` 这段（`data_ddr_rsp_rdata` 到 `id_rs1[5]`，约 3.9 ns）中的绝大部分。
新起点变成 MEM/WB 寄存器输出，ID 侧只剩 `rf_wdata → id_rs1_br(2 级 mux) → br_alu(约 0.72 ns) → id_taken`，估 1.6~1.9 ns；
加上 `id_taken` 之后原有的 3.07 ns，合计约 4.7~5.0 ns，对 125 MHz 的 7.32 ns 组合预算有余量。

**性能代价（必须实测，不能沿用 3.6% 这个数）**：只在“load → branch/jalr 紧邻”时 +1 拍。
`load-use` 分类的 3.6% 只统计了 EX 级 load 的停顿，**不等于**本方案命中的次数。
CoreMark 中分支约占 17%，其中依赖前一条 load 的比例未知。

建议先加一个诊断事件再决定：

```verilog
assign perf_events[x] = if_id_valid && (inst_b | inst_jalr) &&
                        ((ex_mem_i_l & (ex_mem_rd == rs1) & br_reads_rs1) |
                         (ex_mem_i_l & (ex_mem_rd == rs2) & br_reads_rs2));
```

跑一次 P300 得到“load→branch 命中次数”，乘以 1 拍即为新增周期数。
若命中 < 400 万次（约 +2%），本刀非常划算；若 > 1500 万次（约 +7%），需要重新评估是否只对 taken 分支生效。

## 6. 验证清单

1. **语义边界**：`ex_mem_bus_error` 时分支不发射（`load_use_br` 已含 `~ex_mem_bus_error`），乱序/故障优先级不变。
2. **同拍双命中**：`add r4,r1,r1` / `add r4,r2,r2` / 分支读 r4 时，EX 前递优先于 WB 前递，`id_rs1_br` 的两级 mux 顺序必须与 `id_rs1` 一致（EX > WB > 寄存器堆）。
3. **x0**：`ex_mem_rd != 0` 与 `id` 侧 `rd != 0` 门控都要保留。
4. **`inst_b` 的 rs2**：`bne/blt/bge/bltu/bgeu` 用 rs2，`beq` 也用；判据用 `br_reads_rs2 = inst_b` 覆盖全部。
5. **jalr**：`jalr_pc` 改用 `id_rs1_br`，`id_target_misaligned` 随之取 `bj_pc[1:0]`，两处必须同源，否则目标地址错位异常会误报。
6. **必须复跑的定向用例**：
   - `load_branch` / `load_branch_jalr`（030 那两档 profile）
   - load-use 最小用例（原 `load_use` 路径未变，确认没有多停）
   - 数据冒险三连（EX/MEM/WB 同拍双命中）
   - 一次 RV32I 随机抽 2 项（按 AGENTS：记录了种子和用例名）
   - 一次真实 SoC 事件级回归
7. **确认没有新增停顿**：对比改动前后同一段程序的退休数与总周期，除 `load→branch` 场景外应当完全一致。

## 7. 未覆盖与风险

- 本刀只处理 ①②③。`id_taken → inst_if_id_accept → 互连 → 桥 take_inst_overlap`（rtr 13.284→16.352，约 3.07 ns）原样保留，
  里面仍有 `take_inst_overlap`(fanout 30)、`id_taken`(37)、`inst_bus_interconnect/N47`(15) 三个大网。
  若本刀后 125 MHz 仍差 0.3~0.6 ns，下一刀在这里做逻辑复制或桥内再寄存一级。
- 未评估 `id_rs1` 复制成两份后的扇出与面积影响（原 `id_rs1` fanout 7，影响小）。
- 未做 STA 验证。收益是按当前 rtr 分段估算，实际以重跑 P&R 为准。
- 本方案不改变流水线级数、不改变分支判定位置（仍在 ID），与 030 的“确定目标后同拍取指”兼容：
  只是把“能确定目标”的时刻从 load 响应当拍推迟到 load 进 WB 的那一拍。

## 8. 备选方案评估：ID 判定 + EX 重定向

另一个候选是“ID 算出 taken/target 并寄存到 ID/EX，EX 阶段才产生重定向”。
本节记录评估结论，未实施。

### 它能断哪一段

按 rtr（2026-10-18 02:49）分段：

| 段 | 时间 | 该方案 |
|---|---:|---|
| `data_q → 7 选 1 → l_alu → mem_wb_wdata` | 2.15 ns | 仍在一段 |
| `→ id_rs1 → br_alu → id_taken → id_exc_valid` | 3.55 ns | 仍在一段 |
| `→ redirect_pc → inst_req_addr → 互连 → 桥 CE` | 3.07 ns | 断到 EX |

改后最长组合段约 **6.7 ns**，对 125 MHz 的 7.32 ns 预算只剩 0.6 ns，属边界通过；
对 109.375 MHz（8.68 ns）宽裕。相比之下第 3 节的 load 前递分级改后最长段约 **5.9 ns**。

### 代价有实测锚点：约 +6.2%，不是 +8.4%

纯算术“每次重定向多 1 拍 × 1900 万次”会高估，因为忽略了 MEM 等待的重叠抵消。
项目已做过反向实验：

- 029 = 226,998,804 周期；030（分支目标同拍取指）= 213,993,695 周期。
- 030 原始记录：分支恢复少 17,078,422，MEM 等待增加 4,092,946，**净少 13,005,109**。

把“确定目标就同拍取指”退回成“晚一拍”，代价即这 13.0M 周期，
相对当前 210.2M 基数约 **+6.2%**。因此该方案的定位是“用 030 的收益换时序”，不是新增开销。

### 与第 3 节方案的对比

| | load 前递分级（第 3 节） | ID 判定 + EX 重定向 |
|---|---|---|
| 断开位置 | 前段（数据通路） | 后段（取指启动） |
| 改后最长段 | ~5.9 ns | ~6.7 ns |
| 代价 | 仅 `load→branch` 紧邻 +1 拍，估 +2~7%（待测） | 所有 taken 分支 +1 拍，+6.2%（有 030 实测锚点） |
| 触碰异常/冲刷语义 | 否 | **是**：`kill_if_id`、`branch_redirect`、`id_exc_valid` 归属、`flow_state` 排空 |
| 是否回退已有优化 | 否 | **必须回退 030 的 `branch_fetch_turnover`** 与 `inst_turnover_safe` 边沿关系 |
| 改动面 | 2 个 mux + 1 个停顿条件 | 控制路径重构 + 030 回退 |
| 风险 | 低 | 中 |

### 结论

- 本轮不作为首选：收益与第 3 节接近，但代价更高、还要回退 030、且触碰精确异常语义。
- 若将来引入 BTB 或把分支判定整体下沉到 EX，这条路径会自然被重写，届时再实施更合适。
- 若两个方案叠加，代价是相加（+2~7% 与 +6.2%），而最长段只从 5.9 ns 再降到约 3 ns，
  边际收益不足以抵偿，不建议同时做。

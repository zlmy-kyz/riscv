# CPU 性能计数器 2B 并入主 RTL

日期：2026-10-10。用户要求设计文件直接维护在 `myriscv/`，不再新增设计候选目录，PDS 实现由用户执行。

## 本轮改动

已将通过2B验证的三份实现直接并入已有文件：

- `myriscv/mycpu_sync.v`：只读性能事件、分支目标、实际IF/ID接收PC输出。
- `myriscv/soc_top.v`：观察信号/DDR AR、AW握手接线，PERF_ENABLE默认1。
- `myriscv/simple_mmio.v`：MMIO控制/状态及13项64-bit计数器；`cpu_perf_counters`模块放在同一 `.v` 内，无需新增PDS源文件。

三文件迁入后与最终2B候选逐字节相同，没有新的流水线、握手或计数口径改动。迁入前检查原主RTL与candidate origin哈希一致，未覆盖其他用户修改。其余49项关键保护输入不变；旧246项输入副本和339项证据完整保留。随后用户要求清理，重复candidate目录已删除，其源码仍可在冻结副本找到；后续修改直接在主文件进行。

根目录 `RISCV.pds` 的设计/仿真源列表已经引用以上主路径，本轮不修改工程、IP、初始化、约束、成功BIN或现有位流。性能软件继续使用 `tests/cpu_performance_2b/build/measure_20261010_c`，后续优化固定同一BIN。窗口、MMIO地址和计数口径见[2B设计记录](CPU性能计数器2B_MMIO与隔离候选_2026-10-10.md)。

入口：`sim/cpu_performance_2b/main_rtl.py`。直接编译当前 `myriscv/*.v`，不选择历史candidate源码，不运行PDS；沿用已审查TB和结果判断，日志隔离在sim下。

```powershell
python sim/cpu_performance_2b/main_rtl.py --tag main_oracle_20261010_a --suite oracle
python sim/cpu_performance_2b/main_rtl.py --tag main_ddr_20261010_a --suite ddr
python sim/cpu_performance_2b/main_rtl.py --tag main_fast_20261010_a --suite fast
python sim/cpu_performance_2b/main_rtl.py --tag main_irq_20261010_a --suite irq

python sim/cpu_performance_2b/main_rtl.py --tag main_coremark_20261010_a --suite coremark
```

以上为已用标签，复跑须换新tag，不能覆盖旧日志。每个完成目录保存 `main_rtl_receipt.json` 和3份实际主源码SHA256。六组回归全部完成，汇总 `sim/cpu_performance_2b/build/main_integration_20261010_a.json` 为 `PERF2B_MAIN_RTL_INTEGRATION_REGRESSION_PASS`。

| 回归 | 本轮主路径结果 |
| --- | --- |
| MMIO计数器窗口/分类/冻结/64-bit carry | PASS |
| 原两条DDR完整IP/PHY/物理模型定向Tcl | 两条PASS，Errors:0，无物理ERROR；各357条既有warning保留 |
| RV32I/取指与数据并发/背压 | 40个支持指令用例及6个并发/背压PASS；两个原有缺口独立复现 |

RV32I 的 FENCE.I/ma_data 两个已知缺口需用保留的迁入前RTL重新复现相同失败；不把新主RTL当成旧基线。两组短CoreMark使用真实CPU/DDR桥及带等待的用户口功能模型，只核验CRC、MMIO/UART读出和13项硬件计数与独立observer一致，不作物理DDR性能证据。原2B候选完整物理DDR微基准与当前主RTL逐字节相同，但仍明确标识其历史编译路径。

短一迭代输出包含官方“至少执行10秒”提示和Errors detected；严格解析确认只有短时长提示，算法CRC正确，因此结论是短迭代功能PASS，不是正式跑分PASS。正式60次及计数器实板仍待用户新位流。

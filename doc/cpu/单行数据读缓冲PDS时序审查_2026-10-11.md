## 实际最差路径

最终报告第1011–1119行：

```text
uart_mmio/wait_count[19] / CLK
  → UART响应有效逻辑
  → data_bus_interconnect
  → CPU控制/操作数与br_alu比较逻辑
  → inst_if_id_accept
  → simple_mmio/g_perf.u_perf/classification_q[3] / I4
```

16级逻辑，数据路径逻辑2.241 ns、布线7.969 ns（78.051%），clock skew−0.195 ns；arrival16.398 ns、required16.370 ns，故slack−0.028 ns。这条报告路径未直接经过新增data_line_valid/tag/data；D增加资源可能间接改变布局，尚无证据分离这种影响。后两条主时钟setup到CPU pc使能仍仅+0.042/+0.047 ns，不能只隔断计数器后就假定所有路径有充足余量。

RTL核对：uart_mmio保留32-bit wait_count，并以`pending && (wait_count == 0)`产生响应；板级UART_RSP_DELAY_CYCLES默认0且soc_ddr3_top没有覆盖。综合网表仍保留此计数路径。下一项优先考虑只精简UART等待计数：按延迟参数确定宽度、零延迟时消除计数比较链，保持接受请求后下一拍响应及TX/RX/IRQ副作用。该方案尚未实施，是否消除最差路径须新实现报告确认；不要用false path、multicycle或放宽时钟掩盖有效同步路径。用户无需在本轮再追加重复seed运行。

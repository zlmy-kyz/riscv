只修改[dual_sram_to_pango_ddr_bridge.v](../../myriscv/dual_sram_to_pango_ddr_bridge.v)。新增末尾参数`INST_HIT_UNDER_DATA_MISS_ENABLE=1`，仅x32且I缓存开启时生效，当前board_top经soc_top的已有桥实例使用默认开启，无需改变PDS源表或顶层端口。x16、关闭I缓存或参数0沿原路径。

- 保留同沿“旧I命中响应消费＋新I请求接受”；新接受优先于清pending。I miss未提升前，不接受下一笔I请求。

**当前额外接受一笔I查询不要求先知道hit；miss会被停放，但不会发第二笔DDR读。** 这是为保持寄存查询时序而确定的实现细节。保留单CPU在途取指/单响应缓冲，不承诺能隐藏整段D miss等待。

### 逐边沿静态审查

| 场景 | 边沿及不变量 |
|---|---|
| D等待时接受I | E0锁I地址/pending、采样I tag和DRM；主D字段保持 |
| I hit | E0后I rsp有效，E1消费；若同沿再接受I则pending保持并绑定新地址/新DRM输出 |
| I miss | E0后不发I响应，pending及miss向量保持；即使实时I地址变成其他命中行也不能误响应 |
| D R到达 | 保持原D lane/target捕获R，进入D RSP；可与I接受或I命中返回重合 |
| D响应完成＋I miss提升 | 无新D接受时，边沿先消费旧D响应，再用保存I地址建立主I RADDR，清独立pending；之后才允许I AR |
| 新D抢占提升 | 主D优先不变；独立miss仍保持，不能因主槽idle_ready重新采样任意I地址而变成假hit |
| 新store接受＋旧I响应 | 旧I先消费，新store照旧按地址失效I；该沿不接受新I查询，避免依赖同沿失效/查询优先级 |
| 复位 | 主槽与独立pending同复位取消；不生成补响应。init丢失不接受新查询，既有事务仍沿原SoC复位/排空语义处理 |

独立查询只在主D读状态打开，故不会与I填充同沿新查询，不新增store与读填充同沿接受。I miss提升不经过第二次外部握手，必须按原接受计数只产生一笔I响应。D读可以是不可缓存Camera/PP区域，I仍须由指令互连合法译码；原Camera/PP无缓存屏蔽、不可执行窗口和所有权保持。posted写条、D字节转发、CPU冲刷/异常/IRQ/FENCE接口均未改。

## 优先评估的结构候选：I/D命中路径解耦

直接RTL依据在dual_sram_to_pango_ddr_bridge：

- I与D各用独立同步DRM，但front_slot_available只在IDLE、RSP或I LOOKUP命中时成立。
- inst_req_ready依赖idle_ready且排除take_data；主状态为RADDR/RDATA时，两侧新请求都被挡住。
- 一个response_target及请求字段服务两侧；即使另一侧可命中自身缓存，也不能利用独立DRM完成新请求。
- D命中已经在接受后的响应周期直接使用同步DRM输出，指令互连也已有同拍接续；不能再把这两项当作尚未实现的一拍优化。

候选方向是在桥内部拆出独立的缓存命中请求/响应归属，保留单笔物理DDR读和原写缓冲。第一种可具体分析的场景是D读miss等R时接收并返回I命中；另一种是I/D同时命中的串行仲裁。只改ready表达式不够，必须先设计独立字段、有效位、DRM取数边沿和响应所有权。

这是真实存在的结构限制，但尚未证明它是最大耗时来源。当前CPU只有一个在途取指槽和一个响应缓冲，D miss又会停住前端；等待期间最多提前准备有限指令，不能把整段D miss延迟都算成可隐藏收益。应先给出从接受→查询→响应→CPU消费的逐边沿方案，并指出哪些周期能减少总完成时间。若场景只改变分类、不减少总周期，不作为提速完成。

此候选是进一步设计评估输入，尚未正式选定033或实施。扩写缓冲、扩缓存、分支预测和改乘法流水分别涉及不同瓶颈；现证据不足以同时推进或承诺收益。

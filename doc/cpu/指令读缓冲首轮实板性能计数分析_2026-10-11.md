performance CPI可分为IF 5.085270 + MEM 4.203478 + branch恢复6.180644 + other1.000000 = 16.469392；validation为5.000178 + 3.972742 + 6.229120 + 1.000000 = 16.202040。other恰好等于instret是本轮观察，不是通用计数恒等式。零分类只表示本窗口无归入该类的周期，不代表相关控制逻辑不存在。

**取指改善是本轮主要收益。** IF等待减少74.7351%/75.2494%；节省的总cycles中，IF分类贡献88.6382%/89.3499%。DDR AR命令减少57.2455%/57.6607%，AW不变；DDR总命令减少55.3917%/55.8978%。读缓冲确实伴随大幅减少的读命令和IF等待，没有靠减少退休工作量取得时间下降。但AR同时含指令读/数据读，现有实板计数没有owner和命中/miss分项，不能把AR下降百分比当I-Cache命中率，也不能计算准确的DDR数据读平均延迟。

**MEM分类也下降约29.7%。** 本轮没有D-Cache或更改数据访存算法；共享桥减少取指读命令后，数据访问受到的竞争可以降低。这是与现有仲裁结构一致的解释，尚无实板仲裁等待/数据请求分解计数，不把具体等待来源量化为已测事实。当前剩余MEM约占四分之一。

**branch恢复现在是最大分类，但绝对值只下降约2.1–2.4%。** 分支数不变；平均每次重定向归入branch恢复的周期从29.8395→29.1328、29.7663→29.1444。占比由约19%升到约38%，主要因为其他开销下降，不是分支次数增加或分支路径变慢。实际定义在`simple_mmio.v`中包含重定向至目标指令交给IF/ID前的等待，且MEM等更高优先级分类会先取走周期；它不是独立分支延迟或误预测率，不能推断BTB可消除38%。

## 建议的下一阶段

1. 先保留现版本作为优化后的实板参考，用现有工具再重复两组60次各至少两轮，合计至少三轮；新目录保留原始日志，仍用同BIN对比，不因不足10秒改动当前软件。此次读缓冲收益已很明显，多轮用于确定稳定性和波动。
2. 下一项优先**研究剩余取指/分支目标等待**，单独修改桥的候选仍比直接修改CPU预测器更符合当前接口和风险约束。现有缓冲仅一个16-byte行，且任意被接受的DDR写均使它失效；分支目标切换和数据写都可能降低局部性。先通过已有退休/访存轨迹分析地址相关失效与小型多行I-Cache的候选效果，再选其中一项实施。未取得失效原因/命中率测量前，不宣称其中任何一项已有收益。
3. 测量若需扩展，可分别记录IF hit/miss、代码行冲突、因写失效及分支目标hit/miss、指令/数据AR数量和仲裁等待，避免把一个大branch分类全部当预测问题。重复仿真仍写DeepSeek任务；此次没有新仿真任务，也未实施下一项RTL优化。
4. D-Cache、RV32M、Burst和BTB继续独立评估。D-Cache需处理写策略/字节写/MMIO旁路及未来DMA一致性；BTB必须先区分目标访存与流水冲刷；RV32M会改变软件指令序列，不能与当前同BIN读缓冲A/B混为一项。当前证据支持进一步研究访存路径，不足以直接承诺上述收益。

若后续要正式CoreMark成绩，可另选足够迭代次数。该新BIN须先单独验证，并用于两版重新建立对照；本轮8.75/9.15秒结果不能通过把迭代次数写大或只重建新版本来补成正式分数。

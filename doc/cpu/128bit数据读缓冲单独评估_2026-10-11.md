# 128-bit数据读缓冲单独评估

结论：建议把“单行16-byte数据读缓冲、写直达DDR、同行写失效”作为下一项独立候选。它可以只接入现有`myriscv/dual_sram_to_pango_ddr_bridge.v`，复用128-bit返回拍并保留CPU32-bit接口，新增逻辑范围比完整D-Cache小。现有数据不足以预测CoreMark收益，不能把约37%的MEM等待当成可全部消除的读延迟。

状态：评估完成，未修改RTL/软件/测试判据，未运行HDL、PDS或串口。没有新增待执行DeepSeek任务；本文是实施规格和验收建议，尚非实现或功能PASS。

## 已确认路径与测量边界

当前路径为`mycpu_sync → data_bus_interconnect → dual_sram_to_pango_ddr_bridge → Pango DDR用户口`。互连先译码并减DDR_BASE，桥只见DDR局部字节地址。RAM、MMIO、UART请求不会进入该桥，因此在桥内放置缓冲无需改变这些设备副作用或地址窗口。

CPU请求从EX经valid/ready发出，MEM等待响应；桥在IDLE且DDR就绪时接受，I/D同时有效时数据优先。当前数据读必经RADDR/RDATA，返回的128-bit拍只选`request_lane`对应32-bit字，其他96-bit没有保留。数据写的32-bit移位值和4-bit strobe由CPU产生，桥再次移到128-bit槽，等待既有AW/W接受后返回；用户口无RREADY、WVALID或标准B响应，不按AXI4改写。

当前四行指令缓存只在指令读返回时填充；数据读不分配任何缓存。总线和互连各自仍最多一笔未完成请求；即使数据命中，首版也必须等桥进入IDLE，不能绕过正在执行的指令DDR事务。

[四行缓存实板分析](四行指令缓存实板性能分析_2026-10-11.md)是本轮基线：performance/validation实际10.868786944/10.995790731秒、CPI10.233382/9.734036；MEM383,733,685/384,554,450周期，占37.66%/37.30%。`perf_events[3]=data_pipeline_stall`同时覆盖MEM未完成及EX无法推进，包含读、写和等桥空闲，并非纯数据读DDR返回延迟。AR混合IF与数据读，AW只有写命令数；现有13计数不能反推数据读命中率、读/写等待分布或同行复用次数。

评估时看到的旧短迭代功能模型延迟统计属于旧硬件/旧软件窗口，不用于预测当前实际DDR收益；本轮没有用纯BRAM或模型时间替代实板。

## 推荐的首版规格

| 项目 | 建议行为 |
| --- | --- |
| 容量 | 1行×16-byte，单项全地址比较，无组相联/替换策略 |
| 状态 | valid 1-bit + tag局部地址[31:4] 28-bit + data128-bit，共157 bits理论状态 |
| 命中 | 启用、valid、数据读、完整tag相同；[3:2]选32-bit槽 |
| 命中响应 | 请求接受后沿用下一拍STATE_RSP，不产生AR，不作组合零拍响应 |
| miss | 原单拍ARLEN=0读流程；有效返回填充全128-bit并返回原请求槽 |
| 替换 | 有效数据读miss替换唯一数据行，不改变四行指令缓存 |
| 写 | 继续原AW/W流程，不吞写、不延迟写、不分配，不缓存脏数据 |
| 写失效 | 接受的DDR写tag匹配时清数据valid，同时保留现有I-Cache同行失效 |
| 部分写 | SB/SH/SW和零strobe同行写均保守失效，无关行写保留 |
| 清空 | reset及DDR未就绪清valid |
| 参数 | 若实施，桥新增DATA_LINE_BUFFER_ENABLE；0作定向对照，实例无需新增端口 |

157 bits不等于实测FF/LUT增量。单行无需四路bank选择，但会增加28-bit比较及命中选择路径；只有用户PDS时序/资源报告才能确认93.75MHz下的实际代价。CPU端字节/半字符号扩展仍由现有`l_alu`执行，桥返回完整对齐32-bit字，不能按访问size重复移位或扩展。

同一冷行连续读4个对齐32-bit槽、无同行写或其他行数据读替换时，计划行为是1次AR而非4次；这是定向场景的设计目标，不能写成CoreMark整体提升4倍。

## 接入细节与风险控制

1. **锁存数据请求tag。** 当前`request_line_tag`只在take_inst时更新；数据miss填充必须在take_data读接受边沿保存原局部`[31:4]`，不能用后来变化的实时`data_req_addr`。可复用现有请求tag寄存器：单事务下I/D请求互斥，但I填充条件仍仅TARGET_INST，D填充仅TARGET_DATA。
2. **严格限定填充边沿。** D填充只在`axi_rvalid && axi_rid==1 && axi_rlast`，且STATE_RDATA或STATE_RADDR与ARREADY同时成立时发生。支持AR接受同拍返回；等待ARREADY期间的其他rvalid不能填充。写状态或其他ID的返回不填充。异常旁带沿用现有CPU error语义，不借本次缓存改动修订fault行为；无效拍不替换已有D行。
3. **写接受即失效。** 只在`take_data && data_req_write`触发，等待ready时不执行副作用。I与D若都持有同一行，一次写必须同时清两处valid；两个缓存维护块独立，不能用一个互斥else-if使其中之一漏失效。写在途期间不接受新读，后续读经原顺序取DDR最新内容。
4. **保持请求/响应守恒。** D命中仍有一次请求、一次数据响应，TARGET_DATA不变；只减少DDR AR。保持数据优先、单在途、RSP后回IDLE的原状态策略，避免一轮内同时改吞吐调度/仲裁/响应时序。
5. **I/D独立。** 指令读不填D，数据读不填I；命中D不能替换I，命中I不能替换D。写无关D行仍需按地址检查I失效，反之亦然，不把“D未命中”误作“所有缓存无须失效”。

本轮不采用同行写字节合并更新：保守失效更容易验证，代价是读改写序列难以复用同一拍。也不做I/D共享数据存储、两行D、预取、写回、Burst、多笔在途或CPU旁路改动。

## CoreMark局部性：机会与限制

`core_matrix.c`的matrix_sum顺序读32-bit C，若中间没有其他数据行访问，是同拍四槽复用机会。matrix_add_const为16-bit元素读改写，同行写会反复使缓冲无效；matrix_mul_vect/matrix_mul_matrix交替读A/B并写C，单行可能因跨数组访问频繁替换。`core_list_join.c`需要读取next/info及节点数据，既有相邻字段，也有跨行指针追踪和链表写操作。

这些是源码结构，不是运行时命中率。固定测量BIN的实际编译访问顺序、栈溢出/保存恢复、地址对齐和指针布局会影响有效复用。链接布局显示程序和栈位于DDR，栈也可能驱逐唯一D行。不能仅凭连续数组就断言高命中率。

若只作说明性估算：保持其他分类不变、MEM分类周期下降比例为r，则总时间约下降`MEM占比×r`。例如假定r=25%，仅该项对应约9.4%/9.3%的时间减少；r未经测量，因此不是预计成绩。实际MEM中有写与固定流水代价，I/D竞争与分类也会变，37%不是本候选严格可达收益或整个系统的硬上限。若无数据复用，预计机制上只能增加比较/状态，可能无收益或时序负担；通过真实结果决定保留。

## DMA和设备可见性

当前没有旁路DDR写主机，CPU所有DDR写都经过桥，能使I/D同行失效。未来摄像头/CNN/DMA若绕桥更新DDR，D缓冲会返回旧数据；软件volatile不会使硬件缓存自动失效。

接入DMA前必须在后续独立任务选择明确协议：不可缓存的共享窗口，或DMA/CPU显式失效及所有权交接。DMA写代码还必须处理I-Cache。桥内这个缓冲没有dirty数据，但并不因此自动具备DMA一致性。现有Loader下载/校验的CPU写路径可用，不能据此认定未来DMA接入已完成；FENCE.I功能和DMA协议不纳入本候选。

## 若实施的最小验证与验收

保持现有四行I-Cache不变，以当前成功桥a1bf18ff版及measure_20261011_125621_924作为前后对照。实施前冻结当前成功输入/位流/两模式原日志；RTL直接改现有myriscv桥，不建新设计文件夹。

只准备一个桥定向TB，验证：冷读/同拍四槽/不同数据行替换，接受后地址变化仍填原行，I/D独立保留，同行/无关行写、SB/SH各字节槽/零strobe，I/D同时持有同行后双失效，读排队写，数据优先，AR背压/同拍返回，错误ID/last不分配，reset/DDR未就绪及在途reset。端口及独立DDR模型检查返回数据、逐笔AR/AW增量和请求/响应守恒，不通过窥探valid制造PASS。缓存开/关用同一TB对照即可。

另从支持集随机抽2个ISA并记录seed/名称；数据load大小/符号及store strobe行为若随机未覆盖，在同一关键定向测试中补最小检查，不追加全套ISA。准备后按用户约定停止，交DeepSeek执行，Codex复核原始证据后才交用户PDS/下载。首版不改DDR握手/控制器/顶层，不自动追加两条物理DDR、IRQ/MMIO/Loader、九微基准或历史重复回归。

实际性能仍用DDR上的固定performance_120/validation_120各1轮，核对同BIN/CRC/instret/branch事件/AW以及cycles/CPI/AR/MEM。需正确性与93.75MHz时序均满足，并观察到真实同工作负载收益，才建议保留；单轮微小差异不足以强断言收益。命中率不从AR总数推导；无需本轮同时改13计数/MMIO，如收益来源仍不清晰再单独评估读请求/hit/miss计数。

**正式时长的工具依赖需要先处理。** 当前run_measurement.py/review_formal120.py对120次不足10秒会拒绝，若只读现有代码而直接部署下一加速版，可能使第一组运行后脚本停下。当前只需再缩短约8.0%/9.1%就会低于10秒。实施阶段应先让固定120次工具保留完整CRC/计数正确但不足10秒的结果，标为“同BIN性能对比”，继续第二模式；正式PASS条件仍必须至少10秒。只有新结果不足10秒时才另建更长正式软件及CRC参考，保留120次成功BIN与旧收据，不扩大本次评估的软件构建范围。

# 板级启动镜像与 DDR 自检修复

日期：2026-10-03。用户实板表现为 KEY0 按下三灯灭、释放后 J16 心跳/M17 常亮、约 5 秒后 K17 快闪。当前程序布局与板级 DDR 窗口不匹配，并且主 RAM 仍装着未上报 TEST_STATUS 的 ld_st 镜像。本次修复启动链路；实板结果仍须用户下载新 bitstream 后验证。

## 镜像与 IP 更新

保留 board_top 默认 RESET_PC=0、DDR_BASE=0x40000000、125 MHz 参考、93.75 MHz core、5 秒看门狗及 20 ms 消抖。新增 `MyCpu_test/board_selftest/` 镜像：ROM 将 245 字程序从片内 RAM 复制到 0x40000000 再跳转，程序在 0x40001000 记录诊断/tohost，在 0x40002000 起执行原有读写花样，MMIO 0x10000010 上报 RUN/PASS/FAIL；正常镜像包含 112 次数据比较。

`build_ddr_stage.boot_program(base)` 支持基址，默认 0x80000000 兼容旧回归；`build_ddr_selftest.py --base --out` 将全部诊断/测试地址跟随基址生成。`prepare_board_selftest_ip.py` 使用本机 Pango ROM/RAM 1.8 官方生成器生成隔离候选，仅改变 INIT_FILE，原容量/端口/时序参数保持。检查生成初始化参数的全部 4096 个字与 .dat 完全相同；ROM 首字应为 0x40000437。

旧主 ROM/RAM、PDS、bitstream 与脚本已保存在 `sim/board_boot_fix_20261003/before/`，原 bitstream/DDR IDF/board_top/FDC SHA256 在 before/hashes.json。旧 0x80000000 自检物理脚本改用独立 ROM/RAM 对，避免随着主 ROM 切换而失配。

旧 ld_st/复位/争用/CPU overlap 物理脚本的公共编译入口同样改用 MyCpu_test/ddr_stage/ipcore 下的独立旧布局 ROM/RAM；生成命令为 `python MyCpu_test/build_ddr_selftest_ip.py --suite ld_st`。两块 INIT 参数文件与修复前主 IP 的 SHA256 完全一致，pds_ddr_ip_compile.tcl 与 pds_ddr_reset_compile.tcl 编译检查通过（legacy_compile_console.log）；本轮没有重跑这些额外的长联仿。主仿真按钮设置和 sim/behav/run_behav.bat 已同步指向板级完整自检。旧 0x80000000 自检对用默认 `python MyCpu_test/build_ddr_selftest_ip.py` 生成。

复现（Python 使用本机可用解释器）：

```powershell
python MyCpu_test/prepare_board_selftest_ip.py
python MyCpu_test/run_ddr_selftest_fast.py --base 0x40000000

```

`--promote` 在两个候选都核对通过后更新主 ipcore/inst_rom 和 ipcore/data_ram 的生成文件；不生成或修改 DDR IP，不修改 FDC。重跑工具不会覆盖首次备份。

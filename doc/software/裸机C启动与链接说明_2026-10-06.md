本文对照当前 [startup.S](../../tests/development/startup.S)、[linker.ld](../../tests/development/linker.ld)、[main.c](../../tests/development/main.c) 和 main.dis（仅本地：`../../tests/development/build/main.dis`），解释 C 程序如何在当前 RV32I SoC 上准备运行环境，以及变量地址如何确定。文中的具体指令地址、栈偏移和数值以本次读取的反汇编为准；修改源码、编译选项或链接脚本后，应重新核对。

## 1. 三个文件分别解决什么问题

裸机环境没有操作系统替程序准备栈、初始化全局数据或调用 main。CPU 只按照 PC 取机器指令。

| 文件 | 输入给谁 | 作用 |
| --- | --- | --- |
| `main.c` | C 编译器 | 描述程序要完成的计算和行为 |
| `startup.S` | 预处理器、汇编器 | 生成启动机器指令，准备 C 环境，再调用 main |
| `linker.ld` | 链接器 | 合并目标文件，确定代码、数据和栈布局，定义地址符号 |
| `build.ps1` | PowerShell | 固定编译、链接和输出检查命令，方便重复构建 |

构建关系如下：

```text
main.c    ── C 编译、汇编 ──→ main.o     ┐
                                       ├─ 按 linker.ld 链接 → main.elf
startup.S ── 预处理、汇编 ──→ startup.o  ┘
                                                    ├─ objcopy → main.bin / HEX
                                                    └─ objdump → main.dis
```

目标文件可以在一条 GCC 命令中临时生成并链接，不一定保存到目录中。大写 `.S` 会先经过 C 预处理，允许使用 `#include`、`#define`；小写 `.s` 默认直接汇编。

地址安排发生在编译和链接过程中。转换 BIN/HEX、生成反汇编不会重新分配变量地址。BIN/HEX 的具体格式取决于转换工具及选项，不能仅凭扩展名认定可直接用于本工程存储 IP。

## 2. 先区分硬件地址范围与软件布局

当前 SoC 的片内 ROM 只接指令总线，片内 RAM 只接数据总线，DDR 可以同时用于取指和数据访问。

| 区域 | 指令访问 | 数据访问 |
| --- | --- | --- |
| 片内 ROM | 支持 | 不支持 |
| 片内 RAM | 不支持 | 支持 |
| DDR | 支持 | 支持 |

硬件规定哪些地址可以访问哪些设备。链接脚本必须在合法范围内安排程序；链接器不会自动检查工程 RTL 的译码方式。

当前测试选择 DDR 首个 64 KiB：`0x40000000–0x4000FFFF`。这只是本程序的链接区域，不是硬件 DDR 的全部容量。所有代码、常量、全局数据和栈都安排在这个区域内。

板级 CPU 的默认复位 PC 仍为 0。ROM 装载器需要先把程序放入 DDR，再跳转到 `0x40000000`。ELF 的入口字段不会自行改变 CPU 复位地址，也不会自行执行装载。

## 3. gp、sp 和 BSS 是什么

### 3.1 gp：全局指针寄存器

`gp` 是整数寄存器 `x3` 的 ABI 名称，通常作为小型全局数据访问的参考地址。若代码采用这种访问方式，就可以用 `gp + 偏移` 读写附近数据。

它不是“所有全局变量的地址”，也不负责给变量分配内存。全局变量可以通过其他地址计算方式访问。

当前链接脚本定义：

```ld
__global_pointer$ = __data_start + 0x800;
```

这是一个地址符号，不会额外占用 2048 字节。startup 把这个符号的地址写入 gp。当前构建的值为 `0x40000864`。

构建参数包含 `-msmall-data-limit=0`，当前 main 的指令也未通过 gp 访问变量，因此本例初始化了 gp，但随后没有使用它。

### 3.2 sp：栈指针寄存器

`sp` 是整数寄存器 `x2` 的 ABI 名称，保存当前栈位置。栈可以存放局部变量、保存的寄存器、返回地址或参数；具体是否放入栈以及如何布局，由编译器决定。

RISC-V 常用调用约定下栈向低地址增长，本构建保持 16 字节栈对齐。

```text
申请栈空间：sp 减小
释放栈空间：sp 增大
```

设置 sp 只是给寄存器赋值，不会清零整块栈内存。局部变量也不保证初值为零，必须按 C 语言规则初始化后再使用。

### 3.3 BSS：零初始化数据段

BSS 是 `.bss` 段的习惯称呼，不是寄存器。未显式初始化或初始化为零的全局变量、静态变量通常放在这里，例如：

```c
int count;
static int flag;
int value = 0;
```

这类对象在程序启动时应为零。链接器确定 BSS 的范围，启动代码在运行时负责清零。

以下概念要分开：

| 内容 | 通常所在位置 | 如何准备初始内容 |
| --- | --- | --- |
| 函数机器指令 | `.text` | 装载程序镜像 |
| 需要保存在内存中的只读常量 | `.rodata` | 装载程序镜像 |
| 非零初始化的全局、静态变量 | `.data` | 装载初始内容；某些布局还需要 startup 复制 |
| 零初始化的全局、静态变量 | `.bss` | startup 清零 |
| 普通局部变量 | 寄存器或栈 | 执行函数内的初始化指令 |

优化、段属性和编译选项会影响实际存放方式，应以 ELF 和反汇编为准。

## 4. startup.S 如何准备 C 环境

### 4.1 声明启动代码与入口

```asm
    .section .text.startup, "ax", @progbits
    .globl _start
    .type _start, @function
_start:
```

- `.section` 将随后指令放入 `.text.startup` 输入段；`a` 表示需要分配运行时空间，`x` 表示可执行。
- `.globl` 让 `_start` 能被其他目标文件和链接器引用。
- `.type` 将 `_start` 标记为函数类型。
- `_start:` 定义位置标签。标签和这些汇编指示本身不是 CPU 指令。

### 4.2 初始化 gp

```asm
    .option push
    .option norelax
    la gp, __global_pointer$
    .option pop
```

`la` 是加载地址的伪指令。这里将链接器定义的地址放入 gp。

`push/pop` 保存和恢复汇编选项；`norelax` 防止 gp 初始化序列被松弛优化成依赖尚未初始化的 gp 的形式。当前构建还在链接参数中关闭了松弛。

对应反汇编：

```asm
40000000: auipc gp,0x1
40000004: addi  gp,gp,-1948
```

计算为：`gp = 0x40000000 + 0x1000 - 1948 = 0x40000864`。AUIPC 使用该条指令自身的 PC。

### 4.3 初始化 sp

```asm
    la sp, __stack_top
```

对应反汇编：

```asm
40000008: auipc sp,0x10
4000000c: addi  sp,sp,-8
```

计算为：`sp = 0x40000008 + 0x10000 - 8 = 0x40010000`。这个地址是栈区末尾的后一字节；后续先减小 sp，再访问栈内地址。

### 4.4 清零 BSS

```asm
    la t0, __bss_start
    la t1, __bss_end
1:
    bgeu t0, t1, 2f
    sw zero, 0(t0)
    addi t0, t0, 4
    j 1b
2:
```

- t0 指向当前待清零地址，t1 保存结束地址。
- `bgeu` 进行无符号比较，到达终点就退出。
- `sw zero,0(t0)` 把当前 4 字节写成零；x0/zero 永远为零。
- 每次推进 4 字节，循环直到清完 `[__bss_start, __bss_end)`。
- `2f` 指代码后方的下一个 `2:` 标签；`1b` 指代码前方的上一个 `1:` 标签。

当前起点和终点都为 `0x40000064`，BSS 为空，因此第一次比较就跳过清零循环。链接脚本把 BSS 起点、终点按 4 字节对齐，配合这里的按字清零。

### 4.5 调用 main，并处理返回

```asm
    call main
3:
    j 3b
    .size _start, . - _start
```

`call main` 在当前构建中展开为：

```asm
40000030: auipc ra,0x0
40000034: jalr  ra,12(ra)
```

JALR 先使用原 ra 计算目标 `0x4000003c`，再将返回地址 `0x40000038` 写入 ra/x1，然后跳转到 main。反汇编的 `jalr 12(ra)` 省略了默认目的寄存器 ra。

如果 main 返回，CPU 在 `0x40000038` 循环停留。当前 main 自身无限循环，不会返回。`.size` 记录函数大小，不生成执行指令。

当前 startup 没有复制 `.data`，因为链接布局要求装载器把它直接放到最终 DDR 地址。它也没有配置异常入口、中断或完整 C 库启动流程。

## 5. linker.ld 如何安排地址

### 5.1 架构、入口和区域

```ld
OUTPUT_ARCH(riscv)
ENTRY(_start)
MEMORY
{
    DDR (rwx) : ORIGIN = 0x40000000, LENGTH = 64K
}
```

架构为 RISC-V，ELF 入口为 `_start`。具体 RV32I/ILP32 由构建参数指定。

`DDR` 是链接器区域名称；`rwx` 用于链接布局属性，不会配置硬件权限。`ORIGIN` 和 `LENGTH` 定义可用范围。

### 5.2 指令与常量

```ld
.text :
{
    KEEP(*(.text.startup))
    *(.text .text.*)
} > DDR

.rodata :
{
    *(.rodata .rodata.* .srodata .srodata.*)
} > DDR
```

外层 `*` 匹配所有输入目标文件；括号内列出需要收集的输入段，`.text.*` 等为名称通配。

启动段先放置，其他函数接在后面；`KEEP` 防止启动段在启用段垃圾回收时被删除。已经收集的输入段不会再次收集。

`> DDR` 表示把输出段安排进 DDR 区域。只读数据安排在代码之后，满足相关对齐要求。

### 5.3 可写初始化数据

```ld
.data : ALIGN(4)
{
    __data_start = .;
    *(.data .data.* .sdata .sdata.*)
    . = ALIGN(4);
    __data_end = .;
} > DDR
__global_pointer$ = __data_start + 0x800;
```

`.` 是链接器当前位置计数器。`__data_start = .` 将当前位置记录为符号；`. = ALIGN(4)` 将位置向上补齐到 4 字节边界；`__data_end` 标记段末尾。

例如 `0x40000101` 向上对齐后为 `0x40000104`。地址符号本身不占存储空间。

本布局没有另设 AT 装载地址，当前 `.data` 的 LMA（装载地址）与 VMA（运行地址）相同。加载镜像必须包含其初始内容，并写到最终地址。

### 5.4 BSS

```ld
.bss (NOLOAD) : ALIGN(4)
{
    __bss_start = .;
    *(.bss .bss.* .sbss .sbss.*)
    *(COMMON)
    . = ALIGN(4);
    __bss_end = .;
} > DDR
```

这里收集零初始化数据以及可能存在的 COMMON 符号。`NOLOAD` 让 BSS 具有运行时地址和大小，但不要求镜像保存同样数量的零字节。清零由 startup 执行。

### 5.5 栈与重叠检查

```ld
__stack_top = ORIGIN(DDR) + LENGTH(DDR);
__stack_bottom = __stack_top - 4K;
ASSERT(__bss_end <= __stack_bottom,
       "Program overlaps the reserved 4 KiB stack")
```

栈顶为 `0x40010000`，栈底为 `0x4000f000`。链接时检查当前依次排列的代码和数据是否侵入预留的 4 KiB 栈区。

这里通过地址符号和重叠检查预留栈，没有单独创建 `.stack` 段。ASSERT 不会在运行时检查栈溢出。

### 5.6 丢弃段

```ld
/DISCARD/ : { *(.comment) *(.eh_frame .eh_frame.*) }
```

丢弃编译器说明和栈展开相关段。当前简单裸机程序不使用这些信息。

## 6. main.c 如何使用准备好的环境

当前源代码：

```c
#include<stdio.h>
int main(void)
{
    volatile int a = 10;
    volatile int b = 20;
    volatile int c = a + b;

    while (1) {
    }

    return 0;
}
```

`#include<stdio.h>` 提供声明，本例没有调用 printf 等函数，因此它不会自行产生输出，也不意味着已经具备串口输出或完整 libc 支持。

`volatile` 让本例保留变量的读写；它不负责分配某个固定地址，也不代表操作是原子的。当前编译器把三个变量放在栈中。普通局部变量也可能只存在寄存器里，或被优化掉。

main 首条指令：

```asm
4000003c: addi sp,sp,-16
```

此后 `sp = 0x4000fff0`。变量位置由本次编译生成的栈偏移决定：

| 变量 | 指令中的位置 | 实际地址 | 预期最终 32 位值 |
| --- | --- | --- | --- |
| a | `4(sp)` | `0x4000fff4` | 10 / `0x0000000a` |
| b | `8(sp)` | `0x4000fff8` | 20 / `0x00000014` |
| c | `12(sp)` | `0x4000fffc` | 30 / `0x0000001e` |

逐条对应为：

| 指令地址 | 指令 | 含义 |
| --- | --- | --- |
| `0x4000003c` | `addi sp,sp,-16` | 申请 16 字节栈帧 |
| `0x40000040` | `li a5,10` | 把 10 放入 a5/x15；实际为 ADDI 别名 |
| `0x40000044` | `sw a5,4(sp)` | 将 10 写到 a 的地址 |
| `0x40000048` | `li a5,20` | 把 20 放入 a5 |
| `0x4000004c` | `sw a5,8(sp)` | 将 20 写到 b 的地址 |
| `0x40000050` | `lw a5,4(sp)` | 从内存读取 a，得到 10 |
| `0x40000054` | `lw a4,8(sp)` | 从内存读取 b，得到 20 |
| `0x40000058` | `add a5,a5,a4` | 在寄存器中计算 10+20 |
| `0x4000005c` | `sw a5,12(sp)` | 将 30 写到 c 的地址 |
| `0x40000060` | `j 0x40000060` | 对应 while(1)，持续循环 |

`j` 是 `jal zero,目标` 的别名。`return 0` 不可到达，因此当前没有生成对应返回路径。

指令地址 `0x4000005c` 表示 CPU 从哪里取这条 SW；SW 的数据地址是 `sp+12=0x4000fffc`。二者不能混淆。CPU 使用字节地址，DDR 桥再转换成 Pango 用户口的地址和数据槽位。

## 7. 本例布局与执行顺序

```text
0x40000000  _start 启动代码
            初始化 gp、sp
            检查并清零 BSS
            调用 main
0x4000003c  main 指令
0x40000060  main 最终循环指令
0x40000064  代码末尾；当前 data/bss 为空
            ……未使用空间……
0x4000f000  预留栈区起点
            ……
0x4000fff0  main 中的 sp
0x4000fff4  a：10
0x4000fff8  b：20
0x4000fffc  c：30
0x40010000  初始 sp，位于栈区末尾后一字节
```

因此，变量访问指令已经包含地址计算方法，但局部变量的绝对地址依赖运行时 sp。这里可以算出具体地址，是因为已知 startup 设置的 sp 和 main 的栈调整。

## 8. 怎样验收这份程序

本程序的预期验收条件为：在超时之前完成对 a、b、c 的读写，最终内存值分别为 10、20、30，并持续提交 `0x40000060` 的循环指令。

验收时可先把三个变量位置初始化为与预期不同的数值，再检查程序确实将它们改写。数据总线应依次完成：

```text
写 a=10 → 写 b=20 → 读 a → 读 b → 写 c=30
```

该 CPU 有五级流水，取指 PC 可能因预取与冲刷短暂出现其他地址。判断执行结束应优先使用退休/提交 PC，而不是要求取指 PC 每拍固定在循环地址。读取最终 DDR 内容应确认相关写事务已经完成，并按 CPU 字节地址正确映射模型存储。

这验证的是本例的启动、栈访存和加法路径。当前 BSS 为空、没有初始化全局数据，不能用本例宣称非空 BSS 清零或 `.data` 装载已通过运行验证。

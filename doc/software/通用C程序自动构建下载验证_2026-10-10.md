# 通用 C 程序自动构建、下载与验证

日期：2026-10-10。用户要求在 tests 新建独立文件夹，实现新 C 程序的自动编译、审查、下载和验证。新增 `tests/c_app/` 和 `sim/c_app/`；未改 CPU、互连、DDR 桥、Loader/BSP 源码、IP、位流及原成功工具/门控。

## 实现和边界

`tests/c_app/run_app.py --source ... --expect ...` 接入项目内用户 C 文件，支持多文件和 `--expect-file` 精确输出。每次自动新建唯一构建目录，复用成功 BSP 编译 RV32I/ILP32/-Os，使用原 ELF/BIN 审查器检查段布局、入口、指令及栈。GCC 依赖发现收集本地头文件，源/工具/依赖/ELF/BIN 哈希和输入副本保存在该目录。

用户 main 单独编译为 app_main，wrapper main 先进行 BSP 自检，再执行用户程序，打印结束和返回值。用户程序需要 return 0，预期文字恰好一次，或精确输出文件匹配；这是用户定义的应用验收，不能自动推断未知算法正确性。保留 60KiB 应用/4KiB 栈和轻量 libc 边界；不支持自动交互输入、无限循环结束验收、浮点 printf 或通用中断测试。

独立仿真入口复用真实 CPU/SoC、Loader、MMIO/FIFO 和带延迟 DDR 模型，完整覆盖下载、整镜像 VERIFY、RUN、DDR 取指/退休、data/BSS/gp/sp/栈和输出。通过后才生成本应用 deployment_gate.json：绑定已有成功主工程位流及其 415 项输入、新应用和本次仿真证据。未修改原六应用白名单，也未让原硬件门控自动接受新硬件。

`--prepare` 只准备，不开串口；默认完整命令在全部门控通过后提示用户准备板子，回车后自动 COM11 LOAD/VERIFY/RUN，记录实际 UART 与输出。`--deploy` 复用准备结果，`--verify-log` 离线逐帧重验日志。所有上板、KEY0 和串口执行仍由用户完成；Codex 本轮未打开 COM11。

## 复现和下一步

准备任意新项目内 C 程序：

```powershell
& C:/python/python.exe D:/riscv/RISCV/tests/c_app/run_app.py --source D:/riscv/RISCV/tests/c_app/main.c --expect MY_PROGRAM_PASS --prepare
```

用户直接下载本轮已准备的示例，无需重新构建或仿真：

```powershell
& C:/python/python.exe D:/riscv/RISCV/tests/c_app/run_app.py --deploy D:/riscv/RISCV/tests/c_app/build/20261010_161146_75750db9 --log D:/riscv/RISCV/sim/c_app/board/my_program_01.json
```

保持此前成功的 `generate_bitstream/board_top.sbit`，按提示关闭串口助手、KEY0 后等待 DDR 初始化再回车。成功标志为 `C_APP_ACTUAL_BOARD_PASS`；实际新应用日志随后用 --verify-log 独立核验。本轮完成开发、完整仿真和离线检查，**新入口实板尚未验证**。操作和全部使用限制见 [c_app README](../../tests/c_app/README.md)。

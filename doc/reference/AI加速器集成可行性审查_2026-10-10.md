# AI 加速器集成可行性审查

日期：2026-10-10（Asia/Shanghai）。只读审查现有RTL、DDR IP配置、仿真入口以及已经成功的VERIFY/RUN/Hello候选PDS报告；没有修改RTL、重建镜像或重新综合。

结论：现有SoC具备CPU通过MMIO控制独立CNN计算模块的基础。加速器自主访问DDR需要新增接口适配、仲裁和响应路由；当前不能直接插入标准AXI4 Master。具体CNN规模、精度和速度可行性仍需模型与吞吐指标，资源余量不能代替性能验收。

| 审查项 | 当前事实与集成影响 |
| --- | --- |
| CPU时钟/宽度 | CPU、互连、DDR桥同为93.75 MHz；CPU字节地址32位、读写数据32位、写strobe4位，分离指令和数据请求/响应接口。 |
| 总线协议 | 自定义类SRAM简单总线，req_valid/req_ready接收请求，rsp_valid/rdata/error返回响应；不是AXI、AHB或Wishbone。 |
| DDR实际接口 | 外部DDR3 x16，IP用户口128位数据、16位写strobe、28位用户地址。地址按16位字计数；128位拍按8个半字对齐。接口为AXI-like：无WVALID/B通道，无RREADY，不能当标准AXI4连接。当前桥AWLEN/ARLEN=0，最多一笔事务，CPU32位访问选取128位拍内一个槽。 |
| 多Master | 数据互连仅一个CPU数据Master。DDR桥已有CPU指令/数据两个来源的仲裁，数据优先；没有通用多Master互连或加速器接口。新Master需增加公平仲裁、来源跟踪、返回路由、背压/缓冲和复位处理，尤其DDR读响应不能被暂停。 |
| MMIO控制 | 可以沿用CPU load/store控制新外设寄存器，例如启动、参数地址、状态。需为新外设增加独立地址译码与响应端口，保留既有MMIO/UART窗口及副作用规则。当前尚无CNN寄存器或CNN中断连接。 |
| DDR空间 | CPU译码范围0x40000000–0x5FFFFFFF，共512MiB；DDR配置row15/column10/bank3/DQ16，对应配置容量512MiB。可以规划图像、权重和特征图区域，避开当前低64KiB的应用/栈；这不等于已验收整个容量。现Loader仅允许低60KiB程序下载，顶部4KiB栈，不能直接下载任意大模型/图像到高地址，需另行扩展数据装载方案。 |
| 仿真 | 已有ModelSim、真实CPU/DDR用户口延迟/背压模型和完整厂家DDR3物理联仿，可新增独立CNN TB和CPU-MMIO联仿；需新增软件参考结果和逐项比较。当前应用TB的DDR模型仅覆盖64KiB，要测试高地址大缓冲需扩展模型；现有环境没有CNN验证。 |

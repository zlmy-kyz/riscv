# ROM / RAM 时序处理的两种方案总结

> **共同前提**:`inst_rom` 与 `data_ram` 都是**同步单端口、读延迟 1 拍**的 IP(地址在时钟上升沿被锁存,`rd_data` 紧接该沿之后有效)。
> 本文把"取指 ROM"和"访存 RAM"各自的两种接法整理成对照,并给出本工程的选型与验证结论。

---

## 0. 一句话本质

> **两个 IP 内部各自只有"一个"地址输入寄存器。你把它当作哪一级流水边界,数据就在哪一级出来。**

| | 把这个内部寄存器当作 | 对应方案 |
|---|---|---|
| **ROM(取指)** | **IF 边界** —— ROM 内部寄存器与 PC 寄存器重合 | 方案二(`addr = nextPC`) |
| | pc_r 的**下一级**冗余寄存器 | 方案一(`addr = PC`) |
| **RAM(访存)** | **EXE/MEM 边界** —— RAM 内部寄存器/或 EX/MEM 寄存器 | 方案一(ALU 结果组合直连) |
| | **MEM/WB 边界** | 方案二(ALU 结果先寄存) |

ROM 与 RAM 的处理手法**完全同构**,因为两者是同一个 36Kb DRM 原语、同一套 1 拍读时序。
差别只在一处:取指的数据源是 PC(有"复位向量"问题),访存的数据源是 ALU 结果(没有复位问题,但有 load-use 冒险问题)。

---

## 1. 取指 ROM 的两种方案

### 方案一-A:以 **PC** 作 ROM 读地址,指令也寄存(教材不推荐)

```verilog
assign inst_sram_addr = pc_r;        // 读请求在"取指级"发起
// rdata 下一拍才有效 → 用 pc_d1(pc_r 打一拍)与 rdata 配对
if_id_pc <= pc_d1;                   // pc_d1 <= pc_r
if_id_inst <= inst_sram_rdata;
```

| 时钟 | `pc_r` | ROM 地址 | ROM 内部寄存器 | `rd_data` | 配对的 PC(`pc_d1`) |
|---|---|---|---|---|---|
| T0 | 0 | 0 | — | — | — |
| T1 | 4 | 4 | 0 | `mem[0]` | 0 ✓ |
| T2 | 8 | 8 | 4 | `mem[4]` | 4 ✓ |

**性质**

- ROM 内部寄存器锁存的是 `pc_r` 的**输出** → 它是 `pc_r` 的下一级寄存器,与 `if_id_pc` 内容只是**冗余复制**。
- 链路上 `pc_r → ROM 内部寄存器 → if_id` 是**三个串联寄存器** → **前端多一级**(整机 6 级而非 5 级),分支冲刷代价多 1 拍。
- 读数据与 `pc_r` **不是同一拍配对**,必须额外打一拍 `pc_d1` 去对齐。
- ✅ **复位行为确定**:ROM 内部寄存器的 D 端接的是 `pc_r` 的输出,而 `pc_r` 的复位值是确定的复位向量(0),所以**下一个沿自动对齐**,不依赖 IP 内部复位行为。
- ❌ 代价:复位后多 **1 个气泡**(复位后的第 1 拍配对不可信,需要丢弃)。

### 方案一-B:以 **PC** 作 ROM 读地址,但**指令不寄存**(同样正确,5 级)

```verilog
assign inst_sram_addr = pc_r;        // 以 PC 作读地址
if_id_pc <= pc_r;                    // 只把 PC 寄存进 IF/ID
// 指令不寄存:rd_data 组合直通 ID —— ID 使用 {if_id_pc, inst_sram_rdata}
```

| 拍 | `pc_r` | ROM 地址 | ROM 内部寄存器 | `rd_data` | `if_id_pc` | ID 看到的配对 |
|---|---|---|---|---|---|---|
| Cn | P | P | P | `mem[P-4]` | P-4 | (P-4, `mem[P-4]`) ✓ |
| Cn+1 | P+4 | P+4 | P+4 | `mem[P]` | P | **(P, `mem[P]`) ✓** |
| Cn+2 | P+8 | P+8 | P+8 | `mem[P+4]` | P+4 | (P+4, `mem[P+4]`) ✓ |

不变式:`rd_data(t) == mem[if_id_pc(t)]` —— 因为 `rd_data` 比 `pc_r` 落后一拍,而 `if_id_pc` 也正好落后一拍,**PC 与指令天然配对**。

**为什么是 5 级而不是 6 级**:指令到达 ID 只跨 **1 个**寄存器(`pc_r → ROM 内部寄存器 → 组合进 ID`),不像方案一-A 要跨 2 个。
**为什么复位安全**:ROM 内部寄存器的 D 端接的是 `pc_r` 的**输出**,而 `pc_r` 复位值是确定的 0 → 复位期间它自然收敛到 0。**既不依赖 IP 的复位值功能,也不需要任何门控技巧,而且 0 气泡。**

**代价(必须权衡)**

- **ID 级的指令输入是"活线"**:ID 关键路径变成 `ROM tCO → 阵列 → 走线 → 译码 → RF 读地址 → ID/EX setup`,是全机最长路径之一。
- **译码级阻塞时必须冻结 `pc_r`**:`rd_data` 是组合直通,不能只冻结 `if_id`。冻结 `pc_r` 后 ROM 地址不变 → 内部寄存器不变 → `rd_data` 保持,配对仍成立。
- 好消息:ROM 读地址直接来自 `pc_r` 的寄存输出,所以 **ROM 的地址建立时间不吃 PC 加法器/分支 mux 的延迟**(方案二的 IF 路径才吃这一段)。

### 方案二:以 **nextPC** 作 ROM 读地址(教材推荐)

```verilog
wire [31:0] pc_next = (!resetn) ? pc_r : next_pc;   // ★复位期间强制 next_pc = pc
assign inst_sram_addr = pc_next;                    // 读请求在"更新 PC 的阶段"发起
if_id_pc   <= pc_r;                                 // 与 rdata 同一拍配对
if_id_inst <= inst_sram_rdata;
```

| 时钟 | `pc_r` | ROM 地址 = `next_pc` | ROM 内部寄存器 | `rd_data` | `if_id_pc` |
|---|---|---|---|---|---|
| T0 | 0 | 4 | 0 | `mem[0]` | 0 ✓ |
| T1 | 4 | 8 | 4 | `mem[4]` | 4 ✓ |
| T2 | 8 | 0xC | 8 | `mem[8]` | 8 ✓ |

不变式:`rd_data(每一拍) == mem[pc_r>>2]` —— 恒成立,复位期间也成立。

**性质**

- ROM 内部寄存器与 PC 寄存器锁存**同一个输入**(`next_pc`)→ **同一个逻辑寄存器**(教材说的"重合")→ 它**本身就是 IF 流水边界**,不浪费级数。
- IF/ID 边界上放的是 `{pc, inst}` 而不是只放 `pc`,指令被正常寄存。
- 前端省掉一级(整机 **5 级**),分支冲刷代价少 1 拍;取指路径也不进 ID 的时序。
- ⚠ **隐含前提**:复位后 ROM 内部寄存器的初值必须等于复位向量。而它的 D 端是 `next_pc = pc_r + 4`,**不会自动回 0**。

**复位陷阱与后果**

| ROM 复位后内部寄存器初值 | 释放后第 1 拍 | 第 2 拍 | 结果 |
|---|---|---|---|
| 0(被复位清零) | `inst[0]` ✓ | `inst[4]` ✓ | 完美,0 气泡 |
| X(未定义,当前 `RST_VAL_EN=false` 属此列) | 垃圾(冲掉) | `inst[4]` | ⚠ **`inst[0]` 被永久跳过**(丢指令,不是多一个气泡) |

**解法 A(复位期间强制 `next_pc = pc`)**

```verilog
wire [31:0] pc_next = (!resetn) ? pc_r : next_pc;   // ⚠ 只写这一行是不够的,见下
```

原理:复位期间把复位向量从 ROM 内部寄存器的 **D 端灌进去**(走它自己的**正常写入路径**),而不是指望 IP 的复位值功能(你的 `inst_rom.idf` 里 `RST_VAL_EN = false`,本来就不能指望)。

> ⚠️ **重要更正(2026-09-12):单独这一行不足以拿到第一条指令。**
> 之前本节"0 气泡、已采用"的结论是用**简化 ROM 模型**跑出来的,那个模型没有模拟 Pango IP 的两条真实特性:
> ① ROM 内部地址寄存器**不带复位**(复位期间照常锁存 `ADDRA`);
> ② 输出在 `rst` 撤销后仍被强制为 `RSTA_VAL`(= 0)**一个时钟**(IP 内部把 `rst` 打了一拍)。
> 换成官方 `GTP_DRM36K_E1.v` 行为模型后,还必须**再让 CPU 侧复位比 ROM 侧复位晚一拍释放**,否则 `mem[0]` 照样被跳过。
> 完整因果链、RTL 行号证据与修复见 `doc/取指ROM复位后丢第一条指令_原因与修复.md`。

**解法 A'(推荐落地形态):门控 + CPU 复位晚一拍释放**

```verilog
reg resetn_1;  always @(posedge clk) resetn_1 <= resetn;
wire pc_hold = !resetn_1;                            // 复位中 + 释放后一拍
wire [31:0] pc_next = pc_hold ? pc_r : next_pc;      // ★ 复位期间 next_pc = pc
assign inst_sram_addr = pc_next;
// pc 多保持一拍;if_id 用 resetn_1 复位,首拍即为有效取指
```

→ 真 IP 实测:复位后 **1 个气泡**,第一条指令 `(0, mem[0])` 正确取出。

**解法 B(保守)**:复位后让 PC 停一拍、再把这拍当气泡冲掉 —— 与解法 A' 等价,只是写法更直白。

**实测**

> ⚠️ 66ns / 76ns 那一组用的是**简化 ROM 模型**(只有"地址寄存 + 组合输出"),**偏乐观**,不能当作真 IP 的结论。请以"真 IP"那一组为准。

| 版本 | 模型 | 首条有效指令 | 错误 | 判定 |
|---|---|---|---|---|
| 方案一-A(`addr=PC`,指令也寄存) | 简化 | 76 ns | 0 | PASS(1 气泡) |
| 方案一-B(`addr=PC`,指令直通) | 简化 | 66 ns | 0 | PASS(0 气泡) |
| 方案二 | 简化 | 66 ns | 0 | PASS(0 气泡) |
| 方案二 无门控 | 简化 | 66 ns | 1 | FAIL(丢 `mem[0]`) |
| **方案一-B(`addr=PC`,指令直通)** | **真 IP** | **100 ns** | 0 | ✅ **PASS,0 气泡,且不需要任何额外逻辑/FF** |
| **方案二 + 门控 + 复位晚一拍** | **真 IP** | **110 ns** | 0 | ✅ PASS(**1 气泡** + 1 个额外 FF) |
| **方案二 + 门控(未晚一拍)** | **真 IP** | 110 ns | 丢 `mem[0]` | ❌ FAIL |
| **当前实现(纯 `addr = next_pc`)** | **真 IP** | 110 ns | 丢 `mem[0]` | ❌ FAIL(你观察到的现象) |

> 结论:**方案一(A/B)对 IP 复位行为天然免疫**(内部寄存器的 D 端接 `pc_r`,而 `pc_r` 复位值确定);**方案二必须额外做"门控 + 复位晚一拍"**。
> 三者的级数:方案一-A 是 6 级;方案一-B 与方案二都是 5 级。

→ 真 IP 下三种接法的逐拍对照与取舍分析,见 `doc/取指ROM复位后丢第一条指令_原因与修复.md` 第 6 节。

## 2. 访存 RAM 的两种方案

### 方案一:ALU 结果**组合直连** RAM 地址端口(教材推荐)

```verilog
assign data_ram_addr = alu_result[11:2];     // EXE 组合直连,中间不夹寄存器
assign data_ram_wr_en = mem_write & ex_valid;
```

| 时钟 | 阶段 | 正在发生什么 |
|---|---|---|
| 第 T 拍 | **EXE** | `alu_result` 组合算出访存地址 → 直连 RAM 地址端口 |
| **① EXE/MEM 沿** | 边界 | RAM 内部地址寄存器锁存该地址(**它充当 EXE/MEM 边界**) |
| 第 T+1 拍 | **MEM** | `rd_data = mem[addr]` **整拍有效** |
| ② MEM/WB 沿 | 边界 | 把它抓进 WB 寄存器,下一拍写寄存器堆 |

**性质**

- **RAM 自己的地址输入寄存器充当 EXE/MEM 边界寄存器** → 读数据从 ① 沿之后立即有效,**贯穿整个 MEM 阶段**。
- store 也在 **① 同一个沿**提交写。
- ✅ 访存**恰好占满 MEM 这一个流水级**,不额外加级、不额外插气泡。
- ✅ load 数据在 MEM 级就绪 → 可做 **MEM→EX 旁路,load-use 不插气泡**(续航取决于旁路路径)。
- ⚠ 代价:EXE 级时序路径变成 `ID/EX tCO → 前递 mux → ALU → 走线 → RAM 地址寄存器 setup`,比"只算一个 ALU"长。
- ⚠ 硬前提:**地址路径全程组合**,ALU 与 RAM `addr` 端口之间**一个寄存器都不能有**。

### 方案二:ALU 结果**先寄存到 EX/MEM**,再由它驱动 RAM 地址

```verilog
// EX/MEM 寄存器里存地址,再由它驱动 RAM
data_ram_addr <= alu_result[11:2];   // 在 EX/MEM 沿寄存
// RAM 要到下一个沿才采到地址 → 数据落到 WB
```

| 时钟 | 阶段 | 正在发生什么 |
|---|---|---|
| 第 T 拍 | **EXE** | `alu_result` 算出地址,进 EX/MEM 寄存器 |
| **EX/MEM 沿** | 边界 | 锁存地址 + 其他数据 |
| 第 T+1 拍 | **MEM** | EX/MEM 输出地址 → 连到 RAM 地址端口 |
| **MEM/WB 沿** | 边界 | RAM 内部寄存器锁存地址 |
| 第 T+2 拍 | **WB** | RAM 输出正确的内存值 |

**性质**

- 地址路径被 EX/MEM 打断 → EX 段变短。
- ❌ RAM 晚启动一拍 → load 数据**到 WB 阶段才正确**,`load-use` 必停 1 拍。
- ⚠ **易错点:MEM/WB 寄存器不能锁存内存值。**
  MEM→WB 沿上 RAM 输出还是**上一个地址**的值(新值在沿之后才出现),锁进去就是错的。
  → 内存值必须**绕过 MEM/WB**,从 RAM 输出**组合**直送 WB 的写回 mux(`mem_to_reg` 选择);MEM/WB 只锁存"其他数据"(ALU 结果、`pc+4`、`rd`、控制信号)。
- **等价说法**:方案二里 RAM 内部地址寄存器扮演的是 **MEM/WB 边界寄存器** —— 这就是"多花一拍"的准确来源。
- **关键路径是 3 段**(不是 2 段):

| 段 | 所在级 | 路径 |
|---|---|---|
| ① | EXE | `ID/EX tCO → 前递 mux → ALU → EX/MEM setup` |
| ② | MEM | `EX/MEM tCO → 走线 → RAM 地址端口 → RAM 内部寄存器 setup` |
| ③ | WB | `RAM 内部寄存器 tCO → 阵列 → DOA → 写回 mux → 寄存器堆 setup` |

- ⚠ **方案二未必真的能提高频率**:它把方案一的 EXE 长路径切短了,代价是把一段很长的路径搬到了 WB(寄存器堆输入端)。

## 3. 横向对照总表

### 取指 ROM 三方案

| | 方案一-A(`addr=PC`,指令寄存) | 方案一-B(`addr=PC`,指令直通) | 方案二(`addr=nextPC`) |
|---|---|---|---|
| 内部寄存器相当于 | pc_r 的下一级 | pc_r 的下一级 | **IF 边界**(与 PC 寄存器重合) |
| 指令何时可用 | 译码(ID)级 | 译码(ID)级(组合) | **取指(IF)级** |
| ID 的指令输入来自 | 寄存器 `if_id_inst` | **RAM 输出(活线)** | 寄存器 `if_id_inst` |
| 级数 | 前端多一级 → **6 级** | **5 级** | **5 级** |
| 复位后气泡 | 1 | **0** | ⚠ **1**(需门控 **+ CPU 复位晚一拍**;此前"0"是简化模型得出的,见第 7 节更正) |
| 依赖 IP 复位行为 | 否 | 否 | ⚠ **是** |
| 配对方式 | `pc_d1` 与 `rdata` 同拍 | `if_id_pc` 与 `rdata` 同拍 | `pc_r` 与 `rdata` 同拍 |
| IF 关键路径 | adder/mux → pc_r setup | adder/mux → pc_r setup | adder/mux → 走线 → **ROM 地址 setup** |
| ID 关键路径 | 寄存器输入(短) | **ROM tCO+阵列+译码+RF 读(长)** | 寄存器输入(短) |
| 阻塞时要求 | 冻结 `if_id` 即可 | **必须冻结 `pc_r`** | 冻结 `if_id` 即可 |
| 教材态度 | 不推荐(费一级) | 未提及(可压回 5 级) | **推荐** |

### 访存 RAM 两方案

| | 方案一(ALU 结果组合直连) | 方案二(ALU 结果先寄存) |
|---|---|---|
| 内部寄存器相当于 | **EXE/MEM 边界** | **MEM/WB 边界** |
| load 数据何时可用 | **MEM 级** | WB 级 |
| 额外拍数 | **不额外加级** | **多一拍** |
| load-use | **可不停拍**(MEM→EX 旁路) | **必停 1 拍** |
| 内存值走哪条路 | MEM 级直接使用 / 旁路 | **绕过 MEM/WB**,组合送写回 mux |
| 时序代价 | EXE 路径变长 | WB 路径变长(第③段) |
| 教材态度 | **推荐** | 折中 |

> **统一结论**:选型的核心是 —— 让 IP 内部那个不可避免的地址寄存器**顺理成章地当一个流水边界**,而不是让它变成"多出来的一级"。
>
> - 取指侧:方案一-A 是"多出来的一级"(6 级);**方案一-B 与方案二都把它用满**(5 级),两者差别只在 **"谁承担 ROM 读延迟"**:方案一-B 放在 **ID**,方案二放在 **IF**。
> - 访存侧:选**方案一**(让 RAM 内部寄存器当 EXE/MEM 边界),数据在 MEM 级返回。

> ⚠️ 2026-09-12 更正:此处原先写"方案二 + 复位门控 = 0 气泡、已 PASS",那是**简化 ROM 模型**的结果。换成真 IP 后必须补上"CPU 复位晚一拍释放",详见 `doc/取指ROM复位后丢第一条指令_原因与修复.md`。

**方案一-B 与方案二怎么选?**(真 IP 实测数据)

| 维度 | 方案一-B(`addr=PC`,指令直通) | 方案二(`addr=nextPC`) |
|---|---|---|
| 复位后气泡 | **0**(天然,无需任何额外逻辑) | **1**(需门控 + CPU 复位晚一拍) |
| 额外硬件 | 无 | +1 个 FF(`resetn_1`) |
| 首条指令进 ID | **复位释放后第一个沿(~100 ns)** | 晚一拍(~110 ns) |
| ROM 读延迟落在 | ID 级(tCO + 阵列 + 走线 + 译码 + RF 读) | **IF 级**(与算 nextPC 并行) |
| 流水线均衡 | ID 段明显更长,容易成瓶颈 | 各段更均衡 |
| 阻塞处理 | 必须冻结 `pc_r` | 冻结 `if_id` 即可 |

> 取舍的核心只有一句:**ROM 那一段同步读延迟,你让它落在 ID 还是落在 IF。**
> 落 ID(方案一-B)换来 0 气泡 + 少一个 FF,但 ID 本身已有译码 + 立即数生成 + 寄存器堆读,叠加一整段同步读风险偏大;
> 落 IF(方案二)各段更均衡,但代价是复位多 1 拍 + 多 1 个 FF。
> **两者都是 5 级、吞吐率一样**,差别只在复位填充深度与关键路径分布。
>
> **务实建议:先按方案二做完主干**(接口不用动),综合跑静态时序分析后再定 —— 若 IF 级"PC 加法器 + 分支 mux + ROM 地址 setup"收不紧而 ID 级有余量,就切方案一-B(改动很小:`inst_sram_addr` 由 `pc_next` 换回 `pc_r`;`if_id_inst` 由寄存器改为连线;顺带省掉那个 FF)。
> 但**无论选哪个,都必须先把"第一条指令能不能拿到"处理对**。

取指侧的关键代码(`myriscv/ifu.v`,含两处修正):

```verilog
reg resetn_1;  always @(posedge clk) resetn_1 <= resetn;   // ★ 新增:CPU 侧复位晚一拍
wire pc_hold = !resetn_1;
wire [31:0] pc_next = pc_hold ? pc_r : next_pc;            // ★ 复位期间 + 释放后一拍 next_pc = pc
assign inst_sram_addr = pc_next;
assign pc             = pc_r;

if_id_pc    <= pc_r;             // 与 rdata 同拍配对
if_id_inst  <= inst_sram_rdata;
if_id_valid <= 1'b1;             // 复位后第一拍即为有效取指(resetn_1 复位)
// 分支/冲刷接入时:if_id_valid <= flush_req ? 1'b0 : 1'b1;
```

访存侧落地时必须同时满足的 3 条:

1. **地址路径全程组合** —— `alu_result → data_ram_addr`,中间不插寄存器;
2. **`wr_en` 必须与 EXE 级 valid 相与** —— 被冲刷/气泡的指令绝不能发出写请求(组合派生信号最容易漏的一条);
3. **`addr = alu_result[11:2]`** —— 丢低 2 位;地址只有 10 位,**越界会静默回绕**。

外加一条:`NORMAL_WRITE` 下写周期 `rd_data` 保持不变,所以要用 `mem_rvalid`(load 有效标志)把写周期屏蔽掉,别把上一个地址的旧数据选进寄存器堆。

## 6. 总结

### 6.1 一句话

ROM 与 RAM 是**同一颗 36Kb DRM 原语、同一套"1 拍同步读"时序**,所以两边的处理手法完全同构:

> **把 IP 内部那个不可消除的地址寄存器,当成它本来就该在的那个流水边界来用 —— 既不要让它"多出来一级",也不要让它"晚出来一拍"。**

你把它当 IF 边界 → 取指 0 气泡 5 级;
你把它当 EXE/MEM 边界 → 访存恰好占满 MEM 一级。
一旦你在它前面**额外再插一个寄存器**,它就顺延成"下一级边界",白丢一拍(取指 0 气泡 → 1 气泡;访存 MEM → WB,`load-use` 从不停拍变成必停 1 拍)。

### 6.2 四个方案的落点一览

| 侧 | 方案 | 内部寄存器相当于 | 数据落在 | 级数 / 气泡 |
|---|---|---|---|---|
| **取指 ROM** | 方案一-A `addr=PC`,指令寄存 | pc_r 的下一级(冗余) | ID 级 | ❌ **6 级**,复位 1 气泡 |
| | 方案一-B `addr=PC`,指令直通 | pc_r 的下一级(冗余) | ID 级(组合) | ✅ 5 级,0 气泡 |
| | **方案二 `addr=nextPC`** | **IF 边界**(与 PC 重合) | **IF 级** | ✅ **5 级,0 气泡**(需门控) |
| **访存 RAM** | **方案一 ALU 组合直连** | **EXE/MEM 边界** | **MEM 级** | ✅ 不额外加级,可不停拍 |
| | 方案二 ALU 先寄存 | MEM/WB 边界 | WB 级 | ❌ 多一拍,必停 1 拍 |

两个"推荐项"合起来的统一原则:**让 IP 自己那一级寄存器,替你把流水边界扛下来。**

### 6.3 取指 ROM 方案二的详细逐拍时序

约定:`next_pc` 在复位期间被强制为 `RESET_VECTOR`(=0);`rom_addr` 组合直连 `next_pc`。

| 拍 | `rst` | `pc_q` | `next_pc` = `rom_addr` | ROM 内部寄存器 | `rd_data` | `if_id_pc / inst` |
|---|---|---|---|---|---|---|
| C1 | 有效 | 0 | **0**(强制) | ← 0 | `mem[0]` | 未写入(invalid) |
| C2 | 有效 | 0 | 0 | 0 | `mem[0]` | 未写入 |
| C3 | **释放** | 0 | **4** | ← 4 | `mem[0]` | ← **(0, `mem[0]`)** ✅ 第 1 条有效 |
| C4 | — | 4 | 8 | 4 | `mem[4]` | ← (4, `mem[4]`) ✅ |
| C5 | — | 8 | 0xC | 8 | `mem[8]` | ← (8, `mem[8]`) ✅ |

三个读法上的要点:

1. **`pc_q` 与 ROM 内部寄存器数值永远相同** —— 不是巧合相等,而是同一个沿写入**同一个值**(`next_pc` 同时接 PC 的 D 端和 ROM 的地址端口)。这就是"重合"。
2. **`rom_addr` 永远领先一步** —— C4 里 `pc_q = 4` 而 `rom_addr = 8`,ROM 正在读的是**下一条**指令。这就是"读请求在更新 PC 的阶段发起"的字面含义;领先的这一步正好被 ROM 自己的地址寄存器吃掉,数据不多不少落在 IF 级。
3. **`rd_data` 在同拍就有效** —— C4 一进就是 `mem[4]`,与 `pc_q = 4` 同行。因为 `OUTPUT_REG = 0`,读通路里只有那一个地址寄存器,沿一过数据就出来,**不需要等下一个沿**。

**两个事件**

- **`stall`**:因为 `next_pc = pc_q`,PC / `rom_addr` / ROM 内部寄存器 / `rd_data` / `if_id` **五者同时冻结**,配对纹丝不动。
  ⚠ 只冻 `if_id` 而让地址继续跑,`rd_data` 会跟着 PC 变,配对立刻断裂 —— 这是该方案最容易写错的一处。
- **`flush` + 跳转**:`next_pc = T` 让 `pc_q` 与 ROM 内部寄存器**在同一个沿一起跳到 T** → 冲刷沿输出 1 个气泡,下一拍 `rd_data` 已是 `ROM[T]`,再下一沿锁进 `(T, mem[T])`。**跳转目标零延迟恢复。**

### 6.4 三个必须同时守住的硬约束

| # | 约束 | 违反后果 |
|---|---|---|
| 1 | `rom_addr` **全程组合**直连,中间不夹寄存器 | 等于把内部寄存器往后挤一级,白丢一拍 |
| 2 | `stall` 时 **ROM 地址也必须冻结**(即冻结 `pc_q`) | 只冻 `if_id` → `rd_data` 跟着 PC 跑,配对断裂 |
| 3 | 复位期间 `next_pc = RESET_VECTOR`(常量,不是 `pc_q`) | 内部寄存器初值未定义(当前 `RST_VAL_EN=false`)→ `inst[0]` 被永久跳过 |
| 4 | 访存侧:`wr_en` 必须与 **EXE 级 valid 相与** | 被冲刷/气泡的指令发出写请求 → RAM 被写脏 |

约束 3 用常量而非 `pc_q` 的原因:ROM 内部寄存器的 D 端是 `next_pc`,**一个复位沿就到位**,不必等 `pc_q` 自己先清零的下一个沿。代价为零,鲁棒性更好,而且让整个方案**对 IP 的复位值功能完全免疫**。

**这套时序的固有代价(唯一的长路径)**

`pc_q` 与 ROM 内部寄存器由**同一个组合函数** `next_pc` 驱动,要在同一沿采到同一个值,就必须保证 `next_pc` 在沿前充分稳定 → **分支判定必须在当拍内组合完成**:

```
ID/EX tCO → 分支比较 → nextPC mux → ROM 地址寄存器 setup
```

这是全机最长路径之一。它用 IF/EXE 的一段长组合路径,换了"ROM 那级寄存器不算额外流水级"这一拍。综合后若收不紧,退回**方案一-B**(把 ROM 读延迟挪到 ID 级)。

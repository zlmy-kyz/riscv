## 2. 所有权与调度

每块缓冲独立状态：`FREE=0 → WRITING=1 → READY=2 → CPU=3 → FREE=0`。

- 调度器仅从FREE分配，一次只有一块WRITING。优先选择上次的另一块；若它未释放、另一块已FREE，可使用空闲块，不强制等待严格A/B交替。
- 正常帧结束、精确写拍数及全部在途W排空后，在同一个core边沿发布该缓冲的READY、SEQ、CRC。BYTES/PIXELS为固定几何值，只有READY/CPU时有效。
- READY不可被自动覆盖；CPU须CLAIM才能读取DDR。CLAIM把READY变CPU；CPU读完用RELEASE把CPU变FREE。不能直接RELEASE一个READY，也不能CLAIM正在写的缓冲。
- CLAIM/RELEASE都检查SELECT选中的缓冲状态及EXPECTED_SEQ与其序号一致。错误/重复命令只返回MMIO access fault，无状态副作用。序号为32bit成功发布计数，允许回绕；应结合状态使用，不能把SEQ=0本身当无效帧。
- 两块均非FREE且当前没有采集时，进入WAIT_FREE。此时不发相机AW，不改READY/CPU元数据，不复位它们的DDR内容。传感器继续输出，等待空闲期间的帧不采集；出现FREE后等待下一个完整VSYNC帧起点，不从当前半帧续采。
- 每次STREAM_START首次采集仍丢DROP_FRAMES=10；首帧成功之后stream_warmed置位，同一流后续帧跳过重复预热。每次捕获仍会复位FIFO/计数器/CRC；自动捕获之间保留至少15个core空闲计数周期，随后等待双域复位释放和run握手。单帧ARM模式仍每次丢10帧。
- WAIT_CYCLES统计core域WAIT_FREE周期，32bit饱和；不是传感器丢帧数、不是帧率。全局SEQ只数成功保存帧，不计跳过的传感器帧。

CPU数据互连已把权限从“camera_busy全局禁止”改为“流模式仅允许CPU拥有的那一块读”。因此B正在写时，CPU读A不受camera_busy阻挡。CPU不能读FREE/WRITING/READY，也不能写CPU拥有的缓冲；均使用既有access-fault返回。单帧模式保持busy期间禁止帧区访问、空闲后允许读写的行为，保留窗口扩为4MiB。已有非帧RAM/MMIO/UART/DDR区域不变。

## 3. Camera MMIO ABI 2

窗口仍为0x10002000–0x1000203f，ID改为**0x43414d02**。只接受32bit对齐访问，写命令/SELECT/TOKEN均要求四lane strobe。ABI1旧固件/旧检查器不可直接视作本版验收程序；旧源码及固定BIN保留，Sol按ABI2新建程序。

| 偏移 | 名称 | 访问/含义 |
|---|---|---|
| 0x00 | ID | RO 0x43414d02 |
| 0x04 | CTRL | WO单一命令；读0，命令不可OR组合 |
| 0x08 | STATUS | 见下方bit定义 |
| 0x0c | FRAME_BASE | 双缓冲时由SELECT选择A/B，单帧始终A |
| 0x10 | FRAME_BYTES | 双缓冲所选READY/CPU为1843200，否则0；单帧沿用原值 |
| 0x14 | FRAME_SEQ | 双缓冲所选READY/CPU的冻结序号，否则0；单帧为成功序号 |
| 0x18 | PIXEL_COUNT | 双缓冲所选READY/CPU为921600，否则0 |
| 0x1c | ERROR_CODE | 原错误编码保持；配置错误高字节含表索引 |
| 0x20 | SENSOR_ID | 实际SCCB读回ID |
| 0x24 | WRITTEN_BEATS | 所选READY/CPU为57600；所选WRITING为当前计数；其他为0；单帧沿用原计数 |
| 0x28 | FRAME_CRC32 | 所选READY/CPU的冻结采集CRC，否则0；单帧沿用原值 |
| 0x2c | SELECT | RW，流模式可写0或1；只改变MMIO观察对象，不改变DMA目标 |
| 0x30 | BUFFER_STATE | RO，两个所有权及调度状态原子快照 |
| 0x34 | GLOBAL_SEQ | RO，全局成功发布计数；CLEAR/新流不归零，硬复位归零 |
| 0x38 | EXPECTED_SEQ | RW，流模式下写CLAIM/RELEASE所需序号 |
| 0x3c | WAIT_CYCLES | RO，WAIT_FREE周期饱和计数，新流归零 |

STATUS：bit0 CONFIG_DONE；bit1 BUSY（本次捕获/排空）；bit2流模式为“至少一块READY未领取”，单帧为FRAME_DONE；bit3 OVERFLOW；bit4 ERROR；bit5 DUAL_MODE；bit6 STREAM_ENABLED；bit7 WAIT_FREE。**流模式下CPU读A时BUSY可以因B采集为1，不能套用旧单帧的STATUS=5判据。** 两块均CPU拥有时bit2可为0，仍可读各自持有的帧。

BUFFER_STATE：bits[1:0] A状态，[3:2] B状态，bit4 SELECT，bit5 ACTIVE_BUF（仅busy时表示正在捕获的缓冲），bit6 BUSY，bit7 STREAM_ENABLED，bit8 DUAL_MODE，bit9 WAIT_FREE，其他为0。

| CTRL值 | 命令 | 条件和效果 |
|---|---|---|
| 0x01 | ARM | 仅单帧模式，配置成功且空闲；原逐帧行为 |
| 0x02 | ABORT | 停止流并使当前帧无效；公开AW/已接受W必须排空后释放WRITING；保留其他READY/CPU内容；置ERROR=5 |
| 0x04 | CLEAR | 必须不busy、流已停、两块均FREE；清错误/旧单帧完成并退出双缓冲模式；不复位传感器配置 |
| 0x08 | STREAM_START | 配置成功、无错误、不busy、流已停且两块FREE；进入双缓冲自动采集，首次从A开始，重做预热 |
| 0x10 | STREAM_STOP | 仅流模式；禁止再分配新帧，当前已分配帧继续正常采完/排空发布；READY/CPU保留 |
| 0x20 | CLAIM | SELECT必须READY且EXPECTED_SEQ匹配；转CPU |
| 0x40 | RELEASE | SELECT必须CPU且EXPECTED_SEQ匹配；转FREE |

STOP不是ABORT：STOP等待已分配帧，可能包含尚未完成的初次预热；要取消则ABORT。停止后DUAL_MODE保持1，允许排空队列和释放；全部FREE后才能CLEAR退出或再START。软件收够100帧后可STOP，排空/处理剩余已发布帧，再释放；不能静默把READY当FREE。

CRC与旧版相同：反射IEEE、多项式0xedb88320、初值ffffffff、最终取反，按DDR每像素低字节→高字节计算。每块元数据在READY/CPU状态保持，另一块采集不会改变它。读取时应用SELECT→读取seq→写EXPECTED_SEQ→CLAIM→确认CPU状态→读取整帧/核CRC→核元数据稳定→恢复该SELECT和EXPECTED_SEQ→RELEASE。若一个软件线程轮询另一块时改过SELECT，释放前必须恢复；本接口是单CPU软件串行控制，不是多线程原子队列接口。

## 4. 异常、复位与CDC审查

- 发布只在`run && done_sync && written_beats==BEATS && dma_state==IDLE && !stop_now`发生；最后W尚未消费不得READY。填满长度不是正常帧边界的替代判据。
- ABORT/格式错误/overflow/捕获或排空超时使stream_enabled清零；只在公开事务排空后释放当前WRITING，不递增SEQ、不发布READY。已有READY/CPU保持。DDR永久不响应时busy/WRITING保持并报错，不能抢占owner强行复用；只能全局复位恢复。
- WAIT_FREE不消耗3秒捕获超时预算，不把CPU持有较久当相机错误。软件可设置独立业务超时并保留状态。
- 每次MMIO请求只在req_valid&&req_ready执行一次；背压不重复领取/释放。同沿发布和释放另一缓冲可以并行，目标状态互斥；同沿首次发布的缓冲因旧状态仍WRITING，提前CLAIM返回error，软件应先观察READY。
- 同沿RELEASE与自动分配时，调度仅看边沿前的FREE；刚释放的缓冲最快下周期使用。MMIO RELEASE必须等原数据互连先前的读响应完成，已返回响应不会因释放被重定向。
- FIFO、CRC、DVP输入寄存、复位同步保持单缓冲实现。新增skip_warmup两级同步，core标志在FIFO复位和prepare/run握手前稳定。新增逐缓冲CRC目的寄存器纳入原10ns bundled-data最大延时约束，另对warmup源到同步器增加10ns最大延时；仍无整域false path。
- 全局复位清流模式、所有权、token和所有元数据；不能保留旧CPU持有权到新会话。无需修改DDR PHY或相机引脚。

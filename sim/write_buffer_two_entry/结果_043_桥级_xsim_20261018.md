## 3. 本轮修掉的测试缺陷（都不是 RTL 缺陷）

1. **`pwsel(...)[b*8 +: 8]`——对函数返回值做部分选择**（`tb_wb2_bridge.sv:420/426`）。
   这不是合法 Verilog，ModelSim 宽容接受，xsim 直接语法错。改为先存临时变量 `w_word` 再按字节取。修完两边都能编译。
2. **短序列把同一笔 store 接受了两次**（depth2 暴露）。
   手写激励先"压住" 3 拍再开始看 `dr`，而 depth2 在第一拍就接受了，`dv` 仍挂着 → 同一笔 0x0A0 被接受两次，4 笔 store 变成 5 次 AW、同一地址写两遍。
   改为从第一拍起就监测 `dr`，接受即撤；仅在未被接受时才在第 4 拍释放背压。修后 depth1/depth2 都是 `aw=4 w=4`。
3. **校验器把全量组专属门无条件当必过项**。
   `same_edge_aw_w`、`completion_blocked_same_line`、`third_store_on_w_edge`、`full_backpressure_cycles>=6`、`new_epoch_store` 只存在于 `PLANE=0` 场景，短序列永远 FAIL。改为按 `--short` 分流，短序列只核通用不变量（`unmatched_aw=0`、`unmatched_ar=0`、内存逐字节、无未结清请求、posted 下 accepts==acks）。
   另新增两条通用不变量：`unmatched_aw = AW − W − 复位丢弃`、`unmatched_ar = AR − R`。

## 6. 未覆盖（明确不做结论）

| 项 | 原因 |
|---|---|
| 组 6：SoC 顺序最小集成（FENCE/IRQ/PERF STOP/UART/RAM 在 tail 未排空时不被接受、最小 CPU 程序、Camera/PP 无缓存各一次） | 需要 `soc_ddr3_top` 级 TB 与程序镜像，本轮未做 |
| 非 posted 兼容（`POSTED=0`） | TB 的 DDR 模型假设"AW 时 posted 队列必非空"，而非 posted 模式不走 posted 队列（`write_buffer_busy` 保持 0），模型判据不适用 → `Fatal: RESULT: FAIL AW issued with an empty write queue`。这是**模型缺口**，不是 RTL 结论，需另写非 posted 的记账 |
| x16（`MEM_DQ_WIDTH` 非 32 字节） | 未跑；`BEATB` 会切到 4，TB 的 `word_of` / `pwsel` 需要在 128bit 拍上重新核对，不能沿用 256bit 口径 |
| 原 27 项阻塞分类统计（store 满队等待 / load miss 等排空 / load hit 资格·碰撞·禁转发 / 共享主槽占用） | 本轮只产出部分等价门（`full_backpressure_cycles=7`、`drain_accept_while_busy=0`、`ar_while_busy=0`、`forward_byte_merges=55`、`hit_loads=31`、`miss_loads=15`），原 27 项口径的脚本不在本工作区，未复刻 |
| ModelSim 的 `Errors: 0, Warnings: 0` | 该仿真器在本机无法启动（§1） |

## 7. 结论边界

- 桥级两条顺序 posted 写缓冲的**容量/顺序/同沿更新、AW/W 背压与稳定、逐字节转发、注册资格与碰撞、读 miss/I 查询/冲突、复位与兼容**（除非 posted）在 xsim 上 `RESULT: PASS`，并由**不读 DUT 内部信号**的独立校验器复核 `status=PASS`。
